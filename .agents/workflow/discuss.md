# 讨论登记（discuss）

> **定位**：工作流第一段——想法从「对话」到「被登记」的门槛。回答「这个讨论值不值得沉淀、沉淀成什么」。

## 流程

```
对话/想法 → AI 判断类型 → 登记或丢弃
```

## 沉淀过滤器（AI 主动发现，人确认）

| 类型 | 判断 | 去向 |
|:-----|:-----|:-----|
| **功能想法**（新能力/新场景）| 有真实价值、可能孵化成功能 | `docs/ideas/`（想法归档区）|
| **方案方向**（架构/模型/流程变化）| 影响多个模块、有取舍 | 写 RFC（`design.md` 骨架）|
| **决策**（为什么这么定）| 影响后续开发的取舍结论 | 入 `assets/adr/` |
| **坑/教训**（踩过或预见）| 有复发风险、值得防 | 入 `checklists/` + `assets/pitfalls.md` |
| **一次性对话**（闲聊/澄清/无结论）| 无沉淀价值 | 丢弃（不登记）|

## 触发点（AI 在哪些时刻主动发现）

1. 开发中遇到「为什么这样」的取舍 → 提请 ADR
2. 修复 bug 找到根因 → 提请入 pitfalls
3. 用户提出新想法 → 提请入 ideas/ 或 RFC
4. 审查中发现模式 → 提请入 checklists

## 登记要求

- 每条登记**一句话说明价值**（为什么值得留）——防「什么都记」导致膨胀
- 想法入 `docs/ideas/` 时更新该目录 README 登记
- 本流程是「提请」不是「自动落盘」：AI 提请 → **人确认** → 落盘（尊重审查只报告原则）

---
**追加方式**：新发现值得沉淀的讨论类型 → 补入过滤器表。
