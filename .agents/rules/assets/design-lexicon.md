# 设计与体验术语表

> **为什么有这份**：同一个动作在不同工具/人嘴里有不同叫法（「UI/UX 重构」「体验优化」「界面改版」），来回翻译就漂。本表把**阶段**与**专业词**钉死，任何工具（Codex / Claude / 其他）开口前先对这里。
> **一句话用法**：**说阶段用左列，说专业用中列，写英文用右列**；拿不准时**用更窄的词**（「信息架构」比「UI/UX」准）。

## 一、阶段（流程主链）

通用链条（双钻模型的变体，任何设计团队都能对上）：
**探索 → 定义 → 原型 → 设计 → 实施 → 走查 → 发布**
（Discovery → Definition → Prototype → Design → Implementation → Review → Release）

| 我们干的事 | 专业表达 | 英文 | 产物 |
|:--|:--|:--|:--|
| 问场景 / 痛点 / 第一眼 | 用户研究 · 探索 | User Research · Discovery | 需求输入 |
| 出三个方向让人挑 | 概念探索 · 方向选型 | Concept Exploration | 方向稿 |
| 圈定选哪个方向 | 设计决策 | Design Decision | 决策记录（`decisions.md`） |
| 出可点 HTML | 高保真原型 | Hi-Fi Prototype | `mockups/` |
| 写需求稿 / 设计稿 + 双角色对打 | 需求规格 · 设计规格 | Requirements / Design Spec | 需求 / 设计文档 |
| 出批次清单 → 分批做 | 实施 · 交付 | Implementation · Delivery | 代码 + 提交 |
| 拿真机逐屏比对原型 | **体验走查** | **UX Audit** | 走查报告 |
| 提交 / 推送 / 部署 | 发布 · 上线 | Release | 部署记录 |

> **本项目的流程名**：**规格先行的设计评审流程**（Spec-First Design Review）——文档先行 + 编写者/审核者双角色对打（见 `.agents/rules/process/review-driven.md`）。

## 二、专业词（按「你想说什么」查）

| 你想表达 | 专业词 | 英文 | 别再说 |
|:--|:--|:--|:--|
| 分类、导航、层级、命名、放哪儿 | **信息架构** | Information Architecture（**IA**） | UI/UX、布局 |
| 点击、流程、抽屉、状态、反馈 | **交互设计** | Interaction Design（**IxD**） | UI、动效 |
| 配色、密度、图表、间距、字级 | **界面设计** / 视觉设计 | UI / Visual Design | 美工、样式 |
| 好不好用、顺不顺手 | **可用性** | Usability | 体验好坏 |
| 拿真机逐屏对照（本轮工作） | **体验走查** | UX Audit · Usability Review | 测试、验收 |
| 按专家准则检查（Nielsen 十条等） | 启发式评估 | Heuristic Evaluation | 走查（两者可互换，前者更具体） |
| 学术 / 研究口径 | 人机交互 | HCI | 体验研究 |
| 组件 / 颜色 / 字级固化成规范 | 设计系统 | Design System | 组件库（后者只是其中一部分） |
| 字号、对比度、触达尺寸 | 无障碍 | Accessibility（a11y） | 适配 |

## 三、本项目已定的口径（写文档时照抄）

| 说法 | 含义 | 备注 |
|:--|:--|:--|
| **Web 端体验走查** | 本项目在 web 端做的「原型对照 + 逐屏实拍 + 偏差清单」 | **范围仅 web 端**；app 端以后另开一轮 |
| **体验重构** | 覆盖 IA → 交互 → 视觉的全链改造（本项目 `feat/trading-plugin` 那一批） | 比「UI/UX 重构」准确 |
| **信息架构调整（IA 调整）** | 一级分区、二级存废、命名、编排（横 Tab / 竖导航） | 本项目讨论最密集的一块 |
| **规格先行的设计评审流程** | 需求 → 设计 → 编码，文档先行 + 双角色对打 | 见 `process/review-driven.md` |

## 四、写作约定

1. **文档开头标注阶段**：每份设计/走查文档开头一句「本文档所属阶段：…」——让人（和工具）一眼知道它在链条的哪一环；
2. **标题不用缩写黑话**：写「信息架构与交互设计」而不是「UI/UX」；确需缩写时首次出现给全称；
3. **同一份文档内只用一套**：中文为主，英文只在首次出现时括注，之后一律中文（避免中英混排造成的理解成本）；
4. **窄词优先**：能说「信息架构」就别说「设计」，能说「体验走查」就别说「审查」。

## 五、别名映射（便于检索历史文档）

| 旧说法（历史文档里会出现） | 对应本表口径 |
|:--|:--|
| 「UI/UX 重构」·「UI/UX 重做」 | 体验重构（IA + 交互 + 视觉） |
| 「uiux-discovery」 | 信息架构与交互设计 · 方向稿 |
| 「页面走查」·「视觉走查」 | Web 端体验走查 |
| 「设计稿」「方案」 | 设计规格 / 设计方案（Design Spec / Design Decision） |
