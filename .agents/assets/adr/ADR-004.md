# ADR-004：交易推送开关 + 交易日志归集审核流程

**决策 1（推送开关）**：推送类型 per-user 可关（`data/{userId}/trading/push-settings.json`，8 类型默认开），**写侧（定时任务）+ 读侧（Feed 注入）双侧门控**——用户关闭的类型既不生成落盘也不注入 Feed。

**决策 2（交易日志归集）**：成交截图（VLM 识别）/ 文字（「清仓了XX」宽松解析）→ 当日候选**去重（symbol+方向）存文件（未落库）** → 收盘 15:15 推送「今日操作汇总」→ **用户「确认并入账」** → 走 `recordTrade` 链路落库；**仅 trading 插件用户触发**（门控复用）。不完整候选（缺数量/价格）确认时跳过并引导去交易模块补全。

**背景**：用户 iPhone 实机反馈——推送分不清类型/关不掉；发成交截图希望自动形成当日交易日志。

**备选**：
1. 推送不可关（原状，已改）；归集直接落库（否决——违反「建议引擎不替用户做决定」哲学）
2. 本决策：开关双侧门控 + 归集三步流水线（识别→候选→审核落库）

**结论**：per-user 推送开关（写读双侧门控）+ 交易日志归集审核流程（阿呆只归集不落库，用户确认后才写交易模块）。

**代价**：推送开关需在设置页维护；归集依赖 LLM/正则识别准确率（宽松解析可能误归集闲聊——用「仅插件用户 + 明确买卖动词 + 待确认」三重兜底）。
