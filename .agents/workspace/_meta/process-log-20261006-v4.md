## ③ 改进提案

> 均为**提案**（B7）；括号内为**建议落点**。

1. **领取行必须含时间，且改台账后回写 `lines:`**——或让 meta 守卫对「动态台账」豁免 M2/M3。（落点：`rules/process/review-driven.md §9`（领取行格式）；`mechanism/guards/ai-guard-meta.sh`（豁免 `_meta/inbox.md` 这类台账）。依据：§①.1 两次无时间 + §①.5 的 M2。）
2. **让「派单 → 骨架」可观测**：在收件箱加三列台账（派单 mtime / 骨架 mtime / 终稿 mtime），或要求子代理 `cp` 后把 `stat` 结果写进回执行。（落点：`rules/process/review-driven.md §9` + `workspace/_templates/dispatch.md`。依据：§①.2 的观测缺口。）
3. **重试派发前必须先查领取锁**——同一交付物**禁止两个写入方**；已有领取者改走「看 mtime 变化 / 询问」而非重发。（落点：`review-driven.md §9` 新增「重试前置检查」一条。依据：§①.4 的 04:12 空骨架覆盖完整稿。）
4. **「两官并行」的落地写法收敛为「一次只放一条到待处理区」**：两条以上时，**编号 + 收件人 + 领取行**三者必须齐备，否则不视为可领。（落点：`review-driven.md §9`；本轮 D-06 单条放行已实测可行。依据：§①.1 + ②P-11。）
5. **≥15 分钟无文件 → 立即打断并重派，且重派先执行提案 3**。（落点：`checklists/process-reviewer.md` P-12 判定口径补一句。依据：§①.3。）
6. **「登记 _index.md」与「不要改 _index.md」二选一定死**（当前每次收尾必留 1 项 FAIL，四单同根因）。（落点：`workspace/_directory.md` 或 `review-driven.md §9` 派单纪律。依据：§①.5。）
7. **promote 落点升人一事收口**：作为 ★ 项在编码准入前请人一句话确认（两官意见：现方案更优、建议维持）。（落点：`trading-plugin/decisions.md` 或设计稿 §13.3 —— **由主链/人决定，本单不代改**。依据：§二 P-07。）
