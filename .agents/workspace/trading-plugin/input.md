# 交易插件重做 · 设计输入（讨论产物 · 只剩「怎么做」）

> **归位说明（2026-10-06）**：原本混在里面的**业务规则已并回需求**（一笔怎么算 · 三环的行为 · 止损 / 清仓口径 · 自选"最早出现" · 纠错口径 → 见需求文稿的「**业务规则**」节）。**本件只剩"怎么做"**。
> **它不是需求**——不参与验收、不参与定稿；交给**设计阶段**去**论证 / 改写 / 推翻**。

## D1. 导入：数据现实与处理

**为什么「资金流水」当主源**：一份导出里同时装着**成交 + 资金事件（转账 / 股息 / 税 / 利息 / 申购）+ 余额**；而且**链式自证**：

```
净投入（转存 − 转取） + 成交净现金流 + 股息净 + 利息 = 期末余额
```

**余额还是"完整性哨兵"**——漏导一段，`余额[i] ≠ 余额[i−1] + 发生金额[i]` 会**当场断层**。

**两源不重复入账**：资金流水先建账；历史成交按**编号 / 指纹合并回填**（系统已有的「跨来源合并」能力）——同一笔不新增行。

**顺序**：事件类在前、快照类在后 → `资金流水 / 历史成交 → 持仓股`（快照永远最后：它是"券商此刻的真值"，用来**校真 + 定锚**）。系统内部排序，用户不用管。

**表头识别特征**：`业务名称 + 发生金额 + 剩余金额` = 资金流水 · `成交日期 / 买卖标志` = 历史成交 · `余额 / 可用 / 可取 / 参考市值` = 资金股份 · `证券代码 + 成本价` = 持仓股 · `介入日期 + 清仓日期` = 清仓股；**认不出 → 拒绝并说清**（fail-closed）。

**送股 / 转增**：通达信**没有「股份流水」**导出，它**不是现金事件**，两份成交源都盖不住 → 靠**持仓股**兜底（提示"疑似送股行" + 建议导一次持仓股）。

> ⚠️ **两个数据陷阱**：① **备注列含银行账号** → 入库必须脱敏；② **同一天里的行序不是时间序**（当天先列买入、后列充钱 → 单日余额会显示为负；实测每日收盘余额全部 ≥ 0）→ **只能按天用**，不能拿行序推盘中。

> **顺带**：REVIEW **P2-交易66**（本金不可自证）现在有了数据源（转存 / 转取事件），从「无解」变成「**待实施**」。

## D2. 资金层额外带出的数据维度与画像素材

| 维度 | 说明 |
|:--|:--|
| **股东代码 = 沪深两市** | 每笔能标出**哪个市场** |
| **业务名称 = 事件分类**（10 类） | 可直接当「事件类型」用 |
| **申购配号** | 打新记录（含配号代码） |
| **币种** | 预留多币种（现全为人民币） |
| **只有日期、无时分秒** | **时段不可分**（要分早盘/午盘/尾盘，只能靠历史成交） |

**新增的画像角度**（以前没素材）：**资金纪律**（留多少现金 / 什么时候满仓 · 余额序列）· **出入金节奏**（银行转存 / 转取）· **分红收益**（股息入账）· **费用损耗**（发生金额 vs 价×量）· **市场偏好**（股东代码）· **打新参与**（申购配号）。

## D3. 一笔的识别与切分（机制）

- **归零切** + **同日合并**（口径 C）：顺序扫流水，净额归零即一笔结束；同一天"卖光 → 买回"合回同一笔；
- **建仓完毕** = 首次卖出前的最后一次买入（记在每一笔上，作 R53/R87 观察窗起点）；
- **人工边界**：边界是**一等对象**（`{symbol, 锚定日, 锚定那笔买入, source: auto|manual, 备注}`），**人工 > 自动**；图上可插 / 可合。

## D4. 三环的说话机制

- **卖点尺子的来源与闭环**：**你的清仓股分析**（照出你的卖出模式，如"冲高不卖、回落才走"）→ **候选卖点规则** → **你认** → **下次用它评你**；
- **铁证（四要素）**：本人历史统计（样本门槛 N≥5）· 具体数字证据链 · 规则原文逐字 · 可回溯留痕；
- **确定性优先**：能用引擎判定的（止损 / 仓位 / 买点）**不走 LLM**。

## D6. 纠错机制

**先保存 → 可触发一次简单校验 → 允许就地改 → 确认后直接改 → 不留痕**。

| 数据类型 | 错了怎么修 |
|:--|:--|
| **快照**（持仓股 / 资金股份） | 重导一次即覆盖 |
| **事件**（成交 / 资金流水） | 就地改 / 删（确认后直接改） |
| **派生**（持仓 / 成本 / 盈亏 / 一笔） | 不用修——改源后**自动重算** |
| **切笔边界** | 人工可切 |
| **规则 / 止损价** | 改规则 |

**发现错的机制**：简单校验（余额链断层 / 对账 drift / 丢行提示）→ 指出"哪里不对"。**后路**：原始导入文件留存（`imports/save`），改错了能重导。

## D7. 自选股的落法

- 每导一次 → **存一份带日期的快照**（进 / 出都看得出来）；
- 每只票记 **「最早出现」+「最后出现」**；
- 用户想修正 → **可人工补一句**（同"笔的边界可人工切"）。

## D8. 画像的落法

- **两条腿**：**客观**（从数据推）+ **主观**（它问你 → 你回答）；
- **主观在对话里收**（它问一句、你答一句）——**不专门做问卷**（问卷没人填）；
- **只影响"怎么说话"，不改变事实层**；**必须如实标**「这是我从你数据里看到的，可能不准」；
- **画像里不含金额**（与 AI 红线一致）。

## D9. 记忆归属（机制）

**交易插件是可配置的（能关）→ 交易的一切随插件生灭**：

| 放哪 | 什么 |
|:--|:--|
| **trading 域**（随插件开关） | **账**（成交 / 持仓 / 金额）· **理解**（模式 / 规则 / 偏好 → **画像**） |
| **kernel 记忆** | **不放交易的** |

理由：**你关了交易插件，阿呆就不该再提你的交易**；而 kernel 记忆**关不掉**。唯一例外：**对话里的"动作"**（kernel 的通用待办链）。

（另：记忆侧待修项 **P2-交易88**——一段对话多条动作共用一条记忆，划一条整段消失。）
