# 交易插件 · 推送文案库 v1

> **定位**：用户 2026-10-09「推送文案你先出一版本」→ 本稿是**可直接写进代码的文案基线**（不是需求、不是设计稿）。
> **口径来源**：`decisions.md`（沉默是默认 · 不荐股 · 缺数据不编）· `uiux-discovery §十`（用处表第 1 条＝规则触发的提醒）· 现有实现（`TradingSessionPushService` / `MarketAlertService` / `TradingPushGovernor`）。
> **一句话**：**用我自己定的规则，盯着我手上这几只——到线了就说（正向丢飞 / 反向止损都算），平时别吵。**

## 一、五条原则（先于所有文案）

1. **沉默是默认**：没有「到线 / 异动 / 账务异常 / 该你动手」就不发——**空发一条就是噪音**；
2. **先说结论**：标题一行就是结论，正文才给依据（与 app 判断句同一套「先结论」口径）；
3. **只陈述、不指令**：全文不得出现「建议 / 该买 / 该卖 / 可以加仓」；判断留给用户，系统只做**他自己规则的对照**；
4. **隐私层不出边界**：正文**永不**出现数量与成本金额（成本类告警只说「跌过你的成本」，不给数字）；
5. **缺数据不编**：行情没取到就说「今天给不了数字」，绝不渲染成 0。

## 四、沉默边界（防吵的硬规则）

1. **全局 ≤8 条/日**，超限**折叠成一条汇总**（沿用现状，不新增机制）；
2. **同类同票同日一次**（B 组已说明）；
3. **22:00–08:00 不发**（`plan` 的 20:30 是唯一夜间一条，且在 22:00 前）；
4. **有 B1 就不发 B2**（同一只票只提醒最重的那一条）；
5. **文案红线**（写代码时按字面执行）：不出现「建议 / 买 / 卖 / 加仓 / 减仓 / 目标价」作动词；不出现数量与成本金额。

## 五、拍板（2026-10-09 · 用户「你定就行」→ 主链定，逐条给理由）

| # | 决议 | 理由 |
|:--:|:--|:--|
| 1 | **午间 / 尾盘「无事不发」＝采纳** | 贴「沉默是默认」：全局日上限只有 8 条，而固定两拍常年占掉 2 条——**没有到线/异动就没有信息量**，空发等于训练用户忽略通知。判据：有票到线 ∨ 有异动 ∨ 有昨晚写的计划待执行，三者不成立则当天这两拍不发 |
| 2 | **破线收尾＝「要不要按你昨晚定的处理？」** | 把话递到用户手上，但**不是指令**（不含「建议/该卖/减仓」），且正好呼应「用我自己的规则盯我的持仓」——这是本插件的核心用处（discovery §十 用处表第 1 条） |
| 3 | **放飞线＝要，但排下批** | 数据模型现在只有止损位、没有目标价：本批先让 B3 仅对「写过目标价」的票成立，**不做半成品**；「设放飞线」需后端加字段 + web 可设，属独立小批次 |
| 4 | **通知标题＝带标的名** | 沿用 P1-交易92 已修的前缀口径（锁屏上就能认出是哪只，不用点进去）；徽章归一的坑当时已填平 |

> **落地状态**：文案本体的实现属**后端批次**（文案在 `TradingSessionPushService` / `MarketAlertService` 里）；app 侧这一批只做**落点**——见 `scope-app-20261009.md` 的 `R-07` / `R-11`（已交付）与走查实拍 `app-6-push-landing.png`。

### 七、口径统一（2026-10-09 · 用户拍板「**系统计算是默认，人手动输入是覆盖；按理说只有一个止损价位**」）

`Position.effectiveStopLoss()` 从 `max(人工, 计算)`（取更严格）**改为「人工覆盖、系统兜底」**——
原来那套会出现「我把线主动往下挪了、系统仍按更高的那条判我破了」，而且 app 用人工位 / 推送与 R66 用生效位，
同一只票会给出**相反结论**（前端官 P2-1）。

| 端 | 本批动作 |
|:--|:--|
| 后端 | `Position.effectiveStopLoss()` 改覆盖语义（javadoc 写明口径来源与两条病因）；`PositionSerializationTest` 从「取更严格」改为**「人工覆盖」**并钉住「计算更严时不再压过人工」这条关键回归 |
| 推送文案 | 破线句按**来源**措辞：手填 → 「在你写的止损 X 下方」；系统默认 → 「在**默认风控线** X 下方」（`MarketAlertService#lineLabel`）；临近/大跌两句保留「你的」这个泛称 |
| app | `PositionItem` 新增 `effectiveStopLoss` + `lineStopLoss`/`lineIsManual`；判断句与行内「与你的线」**一律用生效线**；展开态标注来源（「止损 9.00（你写的）」/「（默认）」）；新增用例钉住「没手填时用生效线判破线」 |

### 八、判定基准：日线级别、尾盘确认（2026-10-09 · 用户拍板）

> 用户原话：「**不用那么严格，你也拿不到实时交易信息；还是按照日线级别，尾盘确认**」。

| 项 | 口径（生效） |
|:--|:--|
| **止损类**（破线 `stop-loss` / 临近 `near-stop-loss` / 破成本 `break-cost`） | **只在尾盘窗口（≥14:50）确认一次**（`MarketAlertService#inTailConfirmWindow`，包私有可覆写）；盘中不再每 30 分钟逐拍判——拿到的本就是滞后报价，逐拍判没有信息增益、只会吵 |
| **异动类**（单日 ±3% / ±5%） | 仍是「今天涨跌多少」，**按盘中判**不变 |
| **等值边界** | 不再抠「触线即算」——按日线口径，**收盘/尾盘价低于你的线才算破**（严格 `<`）；app 侧 `readHoldLine` 的 `≤` 待与其统一（登记） |
| 推送节奏 | 破线类与既有 14:50 尾盘 / 15:15 收盘确认同窗口出现（受全局 ≤8/日 与同类同票去重约束） |

**落地**：`MarketAlertService#poll(userId)` 取一次 `tailConfirm` 门控三类止损提醒；`MarketAlertServiceTest` 新增
`stopLossTypes_areGatedToTailConfirmWindow`（盘中：不发破线、但异动照发）。

**验证**：`./gradlew test` 后端全量 **BUILD SUCCESSFUL**（文案相关断言同步更新：`MarketAlertServiceTest` 5 处 + 保留 R66 断言）。
