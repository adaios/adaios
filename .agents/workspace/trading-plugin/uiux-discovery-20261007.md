> **口径**：**前端先定，后端适配**；**不考虑现状实现**（只受 §三「已定约束」约束）。

## 一、为什么现在做 · 走到哪了

- 交易插件是项目核心（adai 用得最多）；前端补做只落了批 1（R-12 一次交文件 + R-05 分析 Tab）。
- **先定形态、再补功能**：批 2-5 按重构后的形态一次做到位——避免「先按旧形态补完、再推翻重做」；批 1 已交付是唯一要迁移的最小存量。
- 三端分工已定（不动）：**admin** 公共数据与治理 · **web** 导入/编辑/分析（坐下来的活）· **app** 记录/持仓/结论/提醒（随身那一半）。
- RFC 20260924（App 形态重做）未收敛——本方向**收编**其 5 个未决项：截图入账路线 / 形态成立与否 / 判断句文案库 / 技术栈 Flutter vs Swift / web 是否跟随（已实质答：**跟随**）。

## 三、已定约束（讨论细节的护栏——不许违反）

> 讨论任何界面细节前先过这张表。来源：`requirement.md` 约束 + 已拍板决策。

- **第一原则（无第三视角）**：用户可见展示都是「我和阿呆」的自然对话，不得出现系统视角标签（「问：/答：/图片记录：/【备注】」）。
- **分端分工**：admin 永不出现于用户端；不把 web 的导入/规则/案例/打分/历史搬上 app；「同一功能两端**不同摆法**」。
- **打码两层**：① 显示层——端上默认 `••••`、点 👁 端上显形（递手机场景）；② 出边界——服务端发给模型/分享的根本不带数量与金额。统一口径：**数量与成本打码，现价与止损保留**。
- **语气**：无一句「该买/该卖/建议」——只有事实 + 用**用户自己规则**做对照；**沉默是默认**（提醒宁少勿吵）。
- **诚实**：缺数据不编（显示「—」，绝不渲染成 0）；判不了就明说判不了。
- **可回溯**：每个数字点得进去（哪几天、哪几笔算的）。
- **颜色**：涨红跌绿（A 股习惯），三端一致（admin 曾出现反色，前车之鉴）。
- **不做**：下单/执行/预测/荐股（`X-01`）；用户端行情/活跃市值导入入口（`X-02`）。
- **不动**：阿呆主页 Feed / Launcher / 底部导航。
- **技术栈**：web/app 均 Flutter；「app 是否换 Swift 原生」是未决项——讨论中不得先行假设。

## 四、三问（v1 · 从素材草拟 · 待增删）

### 问 1 · 日常怎么用它？（真实场景与频率）

| 时刻 | 干什么 | 端 |
|:--|:--|:--|
| **交易日收盘后（每天 · 最高频）** | 一次交导出文件（资金流水 + 历史成交）→ 对账 → 看今天发生了什么 | web |
| 前晚 | 写明天怎么做（一句话） | web/app |
| 早盘 09:15 | 今天该不该动、动哪只 | app（提醒） |
| 盘中 | 随手记一笔；该提醒时被提醒 | app |
| 尾盘 14:50 | 今天该不该卖 | app |
| 收盘后 | 复盘：买卖点回顾、卖飞了没 | web |
| 不定期 | 看画像、调规则、翻案例 | web |

（出处：`requirement.md` §谁会用它 · 在什么时刻 / §分系统）

### 问 2 · 哪个瞬间皱眉 / 哪个「这就对了」？

**皱眉**：

- 导数据要**记顺序、分次导**（→ `R-12` 的动机）
- 新用户开箱**无处下手**——现状是「从『你有一套系统』长出来」（→ 定位扩容的动机）
- **对不上账时不知道信谁**（→ `R-02` / 验收 6）
- 想知道「今天要不要我动」要**翻很多屏**（→ `R-11` 的动机）
- app 记一笔**流程重**（→ 截图入账的历史卡点）
- 提醒要么**吵**、要么静音下**错过**（→「沉默是默认」的由来）

**对味**（现在就想听到的话）：

- 「**一次把文件交给它就行**」——不用记顺序（`R-12`）
- 「**你定的 −5% 到了，要动吗**」——用我的线、只陈述（`R-07` 口径）
- 「**账能自证**」——余额链连续，断了指出哪一天（验收 6）
- 「**每个数字点得进去**」（验收 4）
- 「**缺数据不编**」——显示「—」，绝不渲染成 0（验收 5）
- 递手机给人看某只票，**点 👁 显形**那一刻（`decisions.md` V2）

### 问 3 · 朋友第一次打开，希望他第一眼看到什么？

（草案）按「人人可用」定位——**零术语、零文档**，第一眼只有三件事：

1. **账的状态**：对上了吗、有没有事；
2. **我的钱现在怎么样**：持仓概览，用人话；
3. **要不要我做什么**：今天该知道的 1–N 件。

——而不是 9 个 Tab 的表格全貌。

### 5.1 web 主屏（三方向）

> 三个方向 = 三种「信息组织哲学」的极端，便于对味；**可混搭**。

### 方向 A · 专业终端（数据列表派的极致）

```
┌ 总资产 · 当日 · 总盈亏 · [账实✓] ──────────────────────────┐
│ 导航│ 高密度表格：代码 名称 数量 成本 现价 盈亏 止损 走势     │ 阿呆说 │
│ 今日│ ──────────────────────────────────────────────── │ 卡片  │
│ 持仓│ 行…（行高紧凑 · 数字红绿）                          │       │
└────┴──────────────────────────────────────────────────┴──────┘
```

- 气质：Bloomberg 式专业克制，**一屏最多数据**；
- 强在：效率、全貌、用户熟悉的「列表风」；弱在：新用户门槛。

| 默认态 | 显形态（点 👁 看金额） | 空账号态（新用户） |
|:--|:--|:--|
| ![方向 A 默认态](mockups/png/A-default.png) | ![方向 A 显形态](mockups/png/A-revealed.png) | ![方向 A 空账号态](mockups/png/A-empty.png) |

### 方向 B · 叙事卡片（阿呆的照见）

```
        [ 阿呆说：账对上了。今天没有要动的。 ]
        [ 账户概览 · 大数字 + 涨跌 ]
        [ 持仓卡 · 名称 / 盈亏 / 一句话 ]
        [ 持仓卡 … ]            右上：导入 · 记一笔
```

- 气质：Notion 式呼吸感，**先给结论**，数据收进卡片；
- 强在：对味「照见」、人人可读；弱在：重度数据操作要进二级页。

| 默认态 | 空账号态（新用户） |
|:--|:--|
| ![方向 B 默认态](mockups/png/B-default.png) | ![方向 B 空账号态](mockups/png/B-empty.png) |

### 方向 C · 驾驶舱（图形化仪表盘）

```
┌ 总资产 · 今日 · 持仓市值 ──────────────────────────┐
│ 资金曲线（主视觉大图）              │ 环形图（仓位构成）│
│ ────────────────────────────── │                │
│ 持仓热力矩阵（红绿方块）             │ 事件时间带       │
└────────────────────────────────┴────────────────┘
```

- 气质：高端财富管理 App，**图形优先**；
- 强在：一眼看出状态与趋势；弱在：列表/编辑类操作不顺手。

| 默认态 | 空账号态（新用户） |
|:--|:--|
| ![方向 C 默认态](mockups/png/C-default.png) | ![方向 C 空账号态](mockups/png/C-empty.png) |

**混搭示例**（不限于）：B 的「阿呆说」+ A 的表格（结论在上、数据在下）；或 A 的密度 + C 的热力概览。

### 5.2 app 首屏（三方向 · 2026-10-07 补）

> app 是「随身那一半」；首屏的差别 = **最上面站的是谁**。三张用同一套事实（5 只持仓 / 1 只破止损 / 同日同批成交），只换组织方式。

| 方向 | 首屏主心骨 | 形态 |
|:--|:--|:--|
| **甲 · 清单优先**（**已圈选**） | 我现在持有什么 | 一行一只、最密；点开**就地展开**看数量 · 成本 · 批次 · 你自己写下的规则；自选另起一段；底部常驻「截图入账 / 一句话」 |
| 乙 · 结论先行 | 阿呆怎么说 | 一句结论压顶 → 入账大按钮 → 一行持仓 + 就地展开 → 「今天」时态区 |
| 丙 · 图形优先 | 我的钱现在长什么样 | 资金曲线 + 仓位圆环 + 热度条；持仓压成最小一行；入账收成右下角一个按钮 |

| 甲 · 清单优先（**已圈选**） | 甲 · 显形态（👁） | 乙 · 结论先行 | 乙 · 空账号态 | 丙 · 图形优先 |
|:--|:--|:--|:--|:--|
| ![app 甲](mockups/png/appA.png) | ![app 甲 显形态](mockups/png/appA-revealed.png) | ![app 乙](mockups/png/appB.png) | ![app 乙 空账号态](mockups/png/appB-empty.png) | ![app 丙](mockups/png/appC.png) |

**合流结论（两端一套语言）**：web 与 app 都选了高密度那一族 ⇒ 两端设计要同时满足两条——
① **主体是密清单**（不吃卡片留白）；② **结论仍必须在最上面一行**（不能退回「要自己读完才知道我现在什么情况」）。

⚠️ **甲与现状最接近**（现状就是这个持仓列表）——所以甲成立的关键**不在"列表"本身**，而在**首屏最上面那一行结论** + **点开就地展开**；否则等于没改。

## 十一、web 全量（2026-10-07 · 9 Tab → 8 区 · 无二级 · 横 Tab）

> 依据 adai 2026-10-07 给的分工：「**app = 焦点模式 + 可选的功能出口**；**web = 全量功能列表 + 操作**」。
> **功能一个不删**（2026-10-07 补充：**能力不删 = 后端有服务；前端表现层可删**——见 `decisions.md` 第五轮拍板），只是不再平铺成 9 个 Tab。
> **同夜拍板升级（9→6 ⇒ 9→8）**：行业惯例对照后 adai 拍 **D2 甲方案**——券商里**自选与持仓平级**，原收编法（持仓 ⊃ 自选/清仓）「父子同名 + 父 ⊃ 非持仓」不专业；「账」改称 **资金**；**只保留一级**（D2b：分片改页内分段/chips）· **横 Tab 编排**（D2c）。决策全文见 `decisions.md` 第八轮；批注过程见 `review-annotations-20261007.md`。

| 旧（9 Tab + 页头 4 入口） | 新（8 区 · 横 Tab） | 说明 |
|:--|:--|:--|
| 持仓 | **持仓**（计数 badge） | 只含持仓中——三类拆分后不再混合 |
| 自选 | **自选**（计数 badge） | 独立一级（行业惯例：自选与持仓平级） |

**主屏形态**：上＝状态条（总资产 · 当日 · 总盈亏 · 市值 · **到线 N 只** · 账实）；中＝高密度表（数量与成本打码 · 现价 / 涨跌 / 盈亏在场 · **「最近的那条线」单列**；**窄窗自动降列 + 操作列冻结在右**——D3）；右＝阿呆说（**<1200 收成顶栏「阿呆说」入口 + 抽屉**——D2c / P3-6）。
**导入落点**：**抽屉**（不跳页）——拖入 → 认出多少 → **对账结论** → 确认入账。

**清仓（持续整理）**：筛到「清仓」时**表格换列** —— 了结日 / 拿了多久 / 这笔 / **卖掉之后到现在（↑走早了 · ↓走对了）** / 当时按哪条规则 / 归档。
顶部四个数：清仓 12 只 · 合计 +6.2% · **卖掉之后又跌 7 只（走对了）** · **卖掉之后又涨 5 只（走早了）**。
> 「卖掉之后到现在」这一列是清仓股独有的价值 —— 直接回答「我卖飞了没」。

**案例**：上半＝**从你的记录里长出来的候选**（每条标**支持 / 反对你写的哪条规则**，你认了才算）；下半＝已收下的 27 例。
> **案例是规则的出口** —— 认下的例子会变成下一次提醒的判据（承接 `R-10`）。

**K 线（横切）**：**一张图，四个地方共用** —— 持仓 / 自选 / 清仓 / 案例。图上标 **我的买卖点（B/S/T）· 你定的止损线 · 峰值浮盈线**；**清仓股照画** —— 卖点标在图上、**卖后走势接着画**（＝「卖掉之后到现在」那一列的可视化）。

> ① 生产里**唯一上线的 K 线**是 `apps/adai-web/lib/widgets/case_kline_chart.dart`（**案例专图**：主图蜡烛 + MA10/MA60 + 买点日标记，副图量 + KDJ/MACD，窗口 = 前 60 + 后 30 交易日）——**只有案例有图**；

## 十、插件的用处（v1 · 2026-10-07 从 adai 口述归纳 · 待增删）

> **来源**：adai 2026-10-07 逐条口述（§八 首条「作用小」的正面回答）。
> **背景事实（同日）**：交易日**基本都会看**，并且会**想办法把操作同步进 app**——「**如果失败了，这很打击我**」；习惯已经差不多了。

**一句话**：**用我自己定的规则，盯着我手上这几只——到线了就说（正向 / 反向都算），平时别吵。**

| # | 用处 | 现状 | 归谁 |
|:--|:--|:--|:--|
| **1** | **规则触发的提醒（核心）**：基于**我的持仓** + **我的规则**，**正向（放飞）与反向（止损）都提醒** | 推送**节奏已合适**（早盘 / 尾盘 / 异动 + 一天上限），**内容待精进** | app 收 · web 看依据 |
| 2 | **批次**：同一只票**反复买卖**时替我分清楚——**券商 App 给不了** | 已建（笔 + 批次两个维度） | web 编辑 · app 看 |
| 3 | **持续积累**：清仓股持续整理 · 分析总结 · 完美案例持续添加 → 越用越有东西可回看 | 已建，但**调用 0**（案例库 / 规则参数 / 三维打分全期 0 次） | web |
| 4 | **数据底（我遇到问题最多的场景）**：数据要**一直在**（连续、不丢、对得上） | 账实横幅 + 余额哨兵；**出入金零记录**（P2-交易64/66）是历史债 | 两端 |

**主动打开时我要什么**：看**持仓情况**——资金相关的**不是重点，但不是不展示**（**基础数据**）；**涨幅这些客观数据要显示**。（原话「会影响我的情绪」**adai 2026-10-07 当场撤回**。）
⇒ 所以不是"砍掉成绩"，而是**分层**：**重点**＝你的规则对照（我拿着什么 · 离我定的线多远 · 到没到线）；**基础数据**＝资金 / 涨幅 / 盈亏，**全部在场、不抢主位**（见本节末「分层口径」）。

**同步失败会打击我**：把操作同步进 app（截图 / 一句话）是**每天的固定动作**；它的第一要求不是好看，是**我不需要怀疑「到底记上没有」**。
⇒ 对应 RFC 20260924 卡点③：入账回执只说「记上了哪几笔」、不说「这次改变了什么」；账实横幅只在**进页时**拉一次。

**app 与 web 的分工（2026-10-07 adai 重述）**：**app = 焦点模式 + 可选的功能出口**（少而准）；**web = 全量功能列表 + 操作**（多而全）。

### ✅ 两处冲突已拍（2026-10-07 · adai）

> **「会影响我情绪」这句 adai 当场撤回**——原意是：**资金相关的不是重点，但不是不展示，这都是基础数据**；**涨幅这些客观数据要显示**。

| 冲突 | 结论 |
|:--|:--|
| ① web「专业终端」的资金 strip | **保留**（基础数据，不撤） |
| ② app「清单优先」的涨跌幅比例 | **显示**（客观数据） |

**分层口径（取代早前的"成绩退位"）——全部展示，只分层**：

| 层 | 内容 | 位置 |
|:--|:--|:--|
| **重点层** | **你的规则对照**：到线没（**正向 · 放飞 / 反向 · 止损**）· 离线多远 · 批次 | 首屏第一眼 |
| **基础层** | 资金（总资产 / 可用 / 市值）· 涨幅 · 盈亏 · 现价 · 止损——**全部在场** | 同屏，不抢主位 |
| **隐私层** | 数量与成本（金额类） | 默认 `••••`，点 👁 显形（递手机） |

⚠️ **易混点（记一笔）**：**「打码」是隐私问题（谁会看到），不是「情绪」问题**——早前把「资金影响情绪」误读成「资金该隐藏」，已在上面更正。
