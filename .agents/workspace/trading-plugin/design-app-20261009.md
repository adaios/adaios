# 交易插件 App 端 · 体验重构设计规格（v1）

> **本文档所属阶段**：**设计规格**（Design Spec）——链条位置＝探索 → 定义 → 原型 → **设计** → 实施 → 走查（术语口径见 `.agents/rules/assets/design-lexicon.md`）。
> **范围边界**：**仅 app 端交易插件**（`apps/adai-app/lib/pages/trading_page.dart` + 其二级页）。**web 端本轮不动**（web 轮已闭环：11 批 + 5 轮走查 + 2 份独立审核）；后端契约**零改动**（截图入账走 A 路线，见 §三 I-5）。

## 二、信息架构（首屏四层 · 顺序即此）

```
① 判断句     「持仓 5 只 · 2 只到线了 · 账对上了。」
   小字（仅异常）：「账对不上，差 6,093.97（09-23 那笔现金）」「行情没取到」「2 笔待入账」
② 入账        [ 📷 截图入账 ]            [ 一句话 ]
③ 持仓        一行一只：名称 代码 · 涨跌% · 与你的线的关系      ⌄ 点开就地展开
   自选段      一行一段（只读）：名称 代码 · 涨跌% · 现价/离线距离
④ 今天        有事才出现：待确认的推送 · 账实与现金口径提示 · 今日复盘
   深处入口一行（常驻）：收益日历 · 资金 · 推送设置 · 复盘历史
──── 以下保持折叠（需要时查到即可）────
   资金与配置（快照 · 现金 · 活跃市值）· 今天的操作 · 明天的计划
```

| 层 | 内容 | 与现状的差 |
|:--:|:--|:--|
| ① 判断句 | 由**确定性数据**汇成一句（持仓盈亏 + 破止损/超仓位硬判定 + 待入账数 + 账实与行情状态） | 现状**没有结论**：要读完卡片才知道自己什么情况 |
| ② 入账 | 截图入账 / 一句话，两个大按钮常驻 | 现状入账埋在一串卡片里 |
| ③ 持仓 | **一行一只 + 点开就地展开**（成本与仓位 · 批次 · 这只票阿呆怎么说）；点整行进该票全貌 | 现状每只票一张卡（5 只 ≈ 2~3 屏） |
| ④ 今天 | 时态区：**有事才出现、无事零占位**；深处入口常驻一行 | 现状是把复盘/对账常驻成区块 |

## 三、交互设计

| # | 决定 | 验收看点 |
|:--:|:--|:--|
| **I-1** | **判断句先说结论**，常态一句最短（「持仓 5 只 · 不用动。」）；**有事换句**（破止损 → 「有 1 只破了止损：云南锗业 88.1」）；小字仅在异常时出现 | **不新增 LLM 调用**——复用 `TradingDecisionNarrator` 的「先结论 + 四要素」口径与确定性数据；取不到就说取不到 |
| **I-2** | **持仓一行 + 就地展开**：行内＝名称 代码 · 涨跌% · 与你的线的关系（到了 / 离多少）；展开三条＝成本与仓位 · 批次 · 这只票阿呆怎么说；点整行进该票全貌 | 5 只票**一屏看完**；展开不跳页 |
| **I-3** | **自选段只读**（名称 · 涨跌% · 现价 / 离线距离），不占主位；**管理仍归 web** | 自选不出现写操作入口 |
| **I-4** | **打码两层**：数量与成本默认 `••••`，现价 / 止损 / 涨跌% 明文；点 👁 一处解开、全页显形（递手机场景） | 打码态 + 显形态各一张实拍 |
| **I-5** | **截图入账四步**：传 → 认 → 记 → **失败**（失败与前三步同等待遇）；**分张提交**（3 张＝3 次单图请求，客户端按「方向+代码+价+量+日期」指纹去重）；候选**默认全信 + 可疑项单独醒目**；回执说「**这次改变了什么**」并**落账即跑一次对账** | 首笔候选 ≤30 秒可见；正常批次**一次点击**完成；可疑判据＝缺日期 / 价量异常 / 方向不明 / 与持仓矛盾 / 疑似重复 |
| **I-6** | **今天时态区有事才出现**，无事零占位；深处入口一行常驻 | 无事的日常**零横幅** |
| **I-7** | **提醒落点**：推送点开 → 落到该票 / 该规则的就地展开（app 收 · web 看依据） | 点开即到，不要求再找 |
| **I-8** | **你的线在场**：止损 / 放飞线的关系直接写在持仓行内（到线 / 离线多远） | 颜色＝涨红跌绿 |

**红线（出过事，不得回退）**：

1. **宁可多标可疑，不可放过一笔**——2026-09-13 漏一行＝静默删一只持仓；09-15 同一截图重复提交把 600536 记成 1000 股；
2. **写账必回执、展示必标口径**（RFC 20260918 两条铁律）；
3. **缺数据不编**：取不到显「—」，绝不渲染成 0；账对不上时**先说不信数字、再报数**。

## 四、视觉口径

- **涨红跌绿**（A 股口径，三端一致）；**深色**（沿用 `AppColors`，不新增色阶）；
- **密清单**：行高紧凑、数字等宽、**你的线**（止损 / 放飞）加重；行分隔用 1px 弱线，不用卡片留白；
- **判断句**＝首屏最大字号的一行；小字只承载异常（账 / 行情 / 待入账）；
- **诚实态**：`—` / 「判不了」/「没取到」三种人话，不许用 0 或空白顶替。

## 五、边界（不做 / 不动）

- **不做**：K 线 · 分析明细 · 通达信导入 · 规则参数编辑 · 案例库 · 画像页（**全是 web 的全量面**）；任何下单 / 平仓 / 减仓执行按钮；换技术栈（Flutter → Swift 另立件）；提醒文案库精进（另立件）；
- **不动**：阿呆主页 Feed · Launcher · 底部导航；web（本轮零改动，只做对表检查）；admin；后端契约（A 路线）；`data/` 数据资产。

## 七之二、主链回应（对 `review-app-design-20261009.md` 的 5 条 P2 · 2026-10-09）

> 独立审核结论：**无 P0 / 无 P1 → 收敛**（可进编码）；P2×5 需在批 1/批 2 前统一口径。下面是主链的**统一口径**与落地处（已实现，不再留分叉）。

| 审核条 | 统一口径（生效） | 落地 |
|:--|:--|:--|
| P2-1 **入账位置与稿不一致** | **有意覆盖已圈选稿**：入账（截图 / 一句话）保持第 ② 层（判断句之下、持仓之上），不做底部常驻条。理由：① 现状 `_buildEntrySection` 就在首屏且用户每天固定用它；② 底部常驻条与「今天」区、折叠区抢空间，窄屏更挤；③ 判断句在最上、入账紧随，**3 秒内「看状态 → 记一笔」是同一屏** | `trading_page.dart#_buildEntrySection`（位置不变） |
| P2-2 **持仓行双热区未定** | **整行＝就地展开/收起**（唯一热区，含右缘 ⌄，最小 44pt 高）；「这只票阿呆怎么说」「批次明细」**收进展开态**的两个文字按钮 —— 一行只有一个动作，误触无歧义（再点即收起） | `_buildPositionRow` / `_buildPositionDetail` |
| P2-3 **去重命中无反馈** | **必须可见**：命中去重时写入丢弃明细「N 笔在两/多张截图里重复出现（同一笔只留一条）」，随第一批并入 `_dropped` 明细卡（默认展开） | `_uploadScreenshots` |
| P2-4 **分张提交中途失败语义** | **各图独立、已识别的候选不因后续失败而回滚**（候选先落 `_candidates`，失败图只记 error）；失败图**不自动重传**（避免重复入账），下一轮用户可再传一次，指纹去重兜底；进度写「第 N/M 张」 | `_uploadScreenshots` / `_buildUploadPlaceholder` |
| P2-5 **判断句句式三处不一** | **定版模板**（主句只放结论性事实）：常态＝`持仓 N 只 · 不用动`；破线＝`持仓 N 只 · M 只破了你的线`（**带只数**，点名进小字 `破了你的线：A、B`）；账实＝主句追加 `· 账对不上` + 小字带后端原话；**正向确认「账对上了」不进主句**（贴「无事零占位」）；取不到 → 换句 `这次没取到你的持仓`，**绝不编 0** | `utils/trading_verdict.dart#composeTradingVerdict` + 12 条单测 |

**P3×11 处置**：1/2/3/5/9/10/11 已在实现里取定（见上表与 §二/§三 的实现落点），**4/6/7/8** 属下一批或需延续观察（`I-7` 规则落点在 app 无处展开 → 随提醒落点一起定；展开态第三条的加载/失败态 → 随阿呆说弹层；打码入口单点 → 保持页顶单入口；「已入账不回滚」→ 已由 P2-4 口径覆盖）。**去向登记**见 `LEDGER.md`。

## 八、自评风险

1. **判断句是本轮最容易做假的一处**——若拿不到确定性数据却硬凑成句，等于违背「缺数据不编」；实现必须以「取不到就不说」为默认分支；
2. **`trading_page.dart` 4215 行单文件**：形态重构牵连面大，先把四层抽成独立 widget 再改，避免大重写；
3. **app 回归网薄**（441 条测试里仅 2 个文件碰 `TradingPage`）：每批同步补 widget 测试，走查与测试互为补集；
4. **自选段加回**可能把首屏拉长——自选必须**只读、可折叠、不参与结论**。
