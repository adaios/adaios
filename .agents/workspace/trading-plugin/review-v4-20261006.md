## 三、新引问题（仅 P0 / P1）

### 新引 P1-1 · §1 数量声明「两个 `ContextContributor`」与实体（三个）及代码不符

- **位置**：`design-final:90`（§1「本设计承担」表 · `domain/trading` 行）——「六个子模块（§2）+ 端口（…）+ **两个 `ContextContributor`**」。
- **问题**：`domain/trading` 实际有**三个** `ContextContributor` 实现，且 §8.1 自己把它们**逐行列全**（`TradingContextContributor` · `MarketContextContributor` · `TradingProfileContributor`）。§1 的清点**少了一个正在生效的贡献者**。
- **实测（只读）**：`rg "implements .*ContextContributor"` → `domain/trading/TradingContextContributor.java:25` · `domain/trading/MarketContextContributor.java:24` · `domain/trading/TradingProfileContributor.java:23`（**三个都在 `domain/trading` 包内**）；§8.1 表（`:302-311`）列三行贡献者 + `TradingKnowledgeSource`。
- **为何判 P1（而非 P2）**：① 本稿**自己刚立的规则**是「数量声明必须可机械核对，不符即红」（`:57` 点 3 的整改），且本稿在自评里**宣称**「全文每处『N 个』后紧跟可数清单、逐一对齐」（`:581`）——本句是**该宣称的反例**，属「声明 ↔ 载体不一致」同型病；② 该句是**本稿新加**的（`design-v2` §1 的同一行**并无**贡献者计数，见 `design-v2:78`），故属**本轮新引**；③ 归属清点失真会把「改造范围 = 两个」写进编码基线，`TradingProfileContributor` 会被**漏在改造清单之外**（正是 `P38`「死代码须有调用点证据」的邻接教训）。
- **建议**：§1 该行改为「**三个 `ContextContributor`**（`Trading` / `Market` / `TradingProfile`）」；若本意是「两个**改造项**」，则明写「其中**两个为改造项**（`Trading` / `Market`）、一个**保留**（`Profile`）」——二者择一，**不留可对不上的计数**。

**非 P0 / P1 的观察（不判级，供主链）**

- **对编写者自评风险 1（§10.2 promote 落点由 `os/` 改到 `data/{userId}/`）的裁决**：**不违反人拍板 S1，无需升人**。依据——`decisions.md` 的 S1 拍的是「**保留**（复盘 → 反哺知识库）闭环」，**并未拍定第一跳落点**；§10 把「复盘 → promote → 候选文件 → **人工审核融合** → 重建 `knowledge/context` → 注入」的**步骤保留**，只改候选文件位置与脱敏，闭环**在种类上未变**。附带观察（不判级）：闭环末跳现由「admin / 人工流程」承载，而 §5 admin 组**未列 promote 端点**——建议主链在 §13.2 交接项里把这一步写清（与 `P2-交易66` 残余一并），免落成「无承载面的闭环」。
- 自评风险 2–5（§9 非逐端点穷举 · 六面闸门是设计承诺 · §8.2 默认体量上限 · §4.1「登记补契约」8 项）**均不涉及产品面 P0/P1**，按「不判 P2/P3」不判级。其中 §4.1 的**内容完备性**（漏 3 条实存路径）与 §10.1 的**正则与示例不符**，**已由后端官 `D-20261006-04` 同轮捕获**，本稿不重复计为产品官新引。

## 四、收敛判定

**❌ 不收敛 → 进 v5**（产品面）。

- 上轮 6 项**逐条核过、全部真闭环**（战略 S2 已门禁化且不再谎称闭环 · 产品 P1-1 / P1-2 残留清零 · 三点复核的「双真源」与「数量声明」已治）；
- 不收敛只欠**一条**：**新引 P1-1**（§1 的「两个 `ContextContributor`」→ 改「三个」或写明「两个改造项 + 一个保留」）——**一行可改、不涉方向、不涉取值**；
- **无 P0 · 无 ★ 需人拍板项**（`decisions.md` 已把 U1–U6 / V1–V3 全部拍定，本稿 ★未决**确为空**，核过）；
- 故维 **v5 一轮一行修订**即可收敛；若主链判该条为可当场收口的口径校正，**修正后可径直进编码**（编码准入条件仍是 §13.3 的 S2 两条产物落地）。

> 一句话：**final 稿把两轮积欠的账基本还清**——合并真做了、死代码误判真翻了、数量声明真对齐了；只剩 §1 一处**新加的清点**与自己的规则打架。修掉这一句，产品面即可收敛。
