## 四、偏差清单

### P2-1 分析屏：原型是「这一笔/这只票/这一段」，实现主视图是全局统计

- 原型 web-3 主体是**一只票的买卖点图 + 按批次表 + 右栏三段总结**（描述/对照/事实）。
- 实现（`trading_page.dart` 分析区）顶部 chips 为 `全局 / 单标的 / 单笔 / 看分析`，默认落在**全局指标列表**（做完的笔 230、胜率 35.2%、盈亏比 0.48 倍…）。
- 左导航子项 `这一笔 / 这只票 / 这一段` 与原型 chips 对应，但**默认落地粒度与原型不一致**；且 chips 词汇表本身不同（实现 `全局 / 单标的 / 单笔 / 看分析` vs 原型 `这一笔 / 这只票 / 这一段 / 交易层 / 资金层 / 按批次`）（`13-analysis.png`）。

### P2-2 清仓表：列比原型多，1600px 宽下需横向滚动才能看到「图」入口

- 原型 7 列：代码/名称 · 了结日 · 拿了多久 · 这笔 · 卖掉之后到现在 · 当时按哪条规则 · 归档。
- 实现 11 列：代码/名称 · 介入→清仓 · 天数 · 持仓期涨幅 · 卖掉之后到现在 · 规则对照 · **买点分 · 执行分 · 总分 · 心理标注** · 图。
- 实测 1600×1000 下最右「图」列在视口外（需横滚），与「专业终端一眼看全」的方向 A 意图有摩擦；列名亦与原型不同（`11-cleared.png`）。

### P2-3 账屏：状态条仍用持仓口径，原型要求的「可取」「余额链」无对应格

- 原型 web-2 状态条 6 格：总资产 · 可用 · 可取 · 本金 · 当日 · **余额链**（✓ 连续 · 断点无）。
- 实现：顶部仍是持仓那 6 格（总资产·当日·总盈亏·持仓市值·到线·账实），内容区另起「现金 / 可用 / 本金 / 账实」四格 + 资金曲线 + 流水。
- **「可取」未出现**；「余额链/断点」以「账实 ✓ 对上了」表达，原型要求的「断点当场指出」未在账屏单列（`12-account.png`）。

### P2-9 持仓主屏表列：16 列 vs 原型 8 列，1600px 下最右「买点 / 角色 / 操作」在视口外

- 原型 web-1 表格 8 列：代码/名称 · 数量 · 成本 · 现价 · 涨跌 · 盈亏 · 最近的那条线 · 近 20 日。
- 实现 16 列（源码 16 个 `DataColumn`，`trading_page.dart` L1117-L1137）：多出市值 · 仓位占比 · 当日盈亏 · 今日涨跌幅 · 盈亏% · 止损 · 买点 · 角色 · 操作（图 / 批次 / 编辑）。
- 1600×1000 实测最右 3 列在视口外（需横滚）——与 P2-2（清仓表 11 列）同类且更重，「专业终端一眼看全」的意图受同样摩擦（`10-holding.png`）。
- 注：按 `uiux-discovery-20261007.md` §十末「全部展示，只分层」口径，基础数据「全部在场」成立——问题不在数据是否在场，而在 **16 列的平铺组合**；**收口口径已定（2026-10-07）：adai 补「可删」**（见 `decisions.md` 第五轮）——以「删 / 按设计对齐」为主，「保留」需有明确理由。

### P3-4 案例屏缺顶部 4 格状态条

- 原型 web-5：已收下 27 · 成功/失败 18/9 · 本周新增 2 · 等你认 3。
- 实现以左导航子项计数替代（实测「等你认 8 / 已收下 33」），页内无状态条（`15-cases.png`）。

### P3-5 顶栏动作退化为纯图标

- 原型：`👁 看金额` `记一笔` `复盘` `导入`（文字按钮，一眼可读）。
- 实现：5 个纯图标（复盘历史 / 推送设置 / 复盘 / 刷新 / 看金额）+ `记录交易` + `导入`。功能都在，但前三项无文字标签。

### P3-6 窄窗行为：`maxWidth < 1080` 整栏消失，原型未定义

- `trading_page.dart:903` `final hasRail = cons.maxWidth >= 1080;` —— 右栏（阿呆说/今天/三条口径）在窄窗**整体隐藏**；845px 视口实测确认。
- 笔记本分屏/小屏用户会失去「阿呆说」这一核心出口，需产品拍板。

### P3-7 规则屏未见「导入 / 从你的数据里长出来」入口

- 原型全量地图对规则区的定义：`自建 / 导入 / 从你的数据里长出来；也是提醒的判据来源`。
- 实测规则屏只有 25 项参数表 + 「编辑规则」按钮。

### P3-8 分析屏的金额未纳入打码

- 实测：**打码态**下分析屏仍明文显示金额 —— 「赚的总 66788.45 元 ÷ 亏的总 137826.91 元」「最大单笔亏 −10646.06 元」「赚最多的一笔 5180.95 元」（本报告用图已遮盖这几处）。
- 对照护栏「打码两层：**数量与成本（金额类）默认 `••••`**，点 👁 显形」——分析屏的盈亏汇总同属金额类，但当前不受 👁 控制。
- 注：本报告的脱敏是**审核侧手工**处理；产品侧是否纳入打码需拍板（涉及「递手机时给朋友看分析屏」这一场景）。

### P3-10 web-1 页面信息层：5 条信息带 + 标题层级，原型均未画

- 实拍比原型多 5 条信息带：活跃市值区间切换条（「空头区间」）· 「仓位 97.56% · 现金 2.44%」· 「行情只到 11-10」· 「盈亏还没算全」· 「上次更新 / 账户快照」（`10-holding.png`）。
- 主区标题：原型「持仓」（当前区名）→ 实现「交易」+ 副标题，区名下沉到左导航；另多一行「持仓 N 只 · 自选 M 只 + 导入持仓」（原型无）。
- 「今天」卡：原型为轨迹文字（「09:15 念了你的计划 · 10:32 记了一笔」）→ 实现为「今天没动 / 想动，没动」回填按钮。
- 归属说明：信息带为原型未画、实现已有的信息（诚实口径 / 刷新状态 / 当日口径类），非本次重构新增；但主屏首屏信息密度显著高于原型——**处置口径已定（2026-10-07）：可删 / 按设计收敛**（见 `decisions.md` 第五轮）。

## 五、未覆盖 / 建议人工确认

1. **导入抽屉预检态**（认出来 N 条 / 认不出来 M 行 / 确认入账 N 条）需真实通达信导出文件，本次只看到空态；建议用真实文件走一遍。
2. **空账号/新用户态**（原型有「新用户·空账号」开关）本次未验。
3. **K 线入口覆盖** —— v2 已收口：清仓行实测可用；持仓行「图 / 批次 / 编辑」与自选行「图 / 删」经源码核对确认（`trading_page.dart` L1223-L1252 · L1298-L1317）。
4. **窄屏（<1080）** 是否接受「右栏消失」需产品拍板（见 P3-6）。

## 六、结论

web 端重构**主体达标**：9→6 收编、6 格状态条、筛选式持仓、清仓「卖掉之后到现在」、案例候选、K 线四区图、导入抽屉均已落地；三条硬口径（涨红跌绿、打码两层、缺数据不编）有像素级实测证据。**「达标」不等于「同构」**——主屏（web-1）的列与信息层明显重于原型（P2-9 · P3-10），本报告 v1 原判其「结构一致」，v2 已改判「部分一致」。

需收口的是**四处形态偏差**（P2-1~P2-3 · P2-9）与**六处细节**（P3-4~P3-8 · P3-10）：核心是**分析屏的默认落地粒度**与**两张主表的列预算**（持仓 16 列 · 清仓 11 列，1600px 下均需横滚）——前者偏离原型最主要的交互屏，后者在宽屏下不能「一眼看全」。

> 归口：本报告为分支在制品；合并前如需进 `docs/records/audits/` + `.agents/records/REVIEW.md`，留给合并后的主会话（`.agents/workspace/_directory.md` 约束）。
