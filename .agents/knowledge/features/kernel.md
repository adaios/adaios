# Kernel 意图卡

> 收录规则与卡格式见 [_index.md §三](_index.md)。**只写意图，不写实现**（字段名 / 方法名 / 端点 / 请求响应一律链接出去）。
> 用法：要改某个功能前，先在这里补/更新它的卡。

## `record` · 记录提交与意图分流

- **干什么用**：把你说的、拍的收进系统，并判断这是「记一笔」还是「在问我」——前者只落盘不打扰，后者给回答。
- **不做什么**：不做富文本编辑器；不在记录时追问补全；不把「模棱两可」硬判成记录。
- **选型理由**：判据倾向**宁可多答一句**——带卡片的请求原先 47% 被判 log、一个字不回；代价是部分记录类输入也会走 AI（费用已如实登记）。**媒体入口不套**这套倾向：否则「配文 + 图」多跑一次 VLM，且 >500 字配文会从「可作盘」变成 400。
- **验收**：① 带提问意味的短句（「这个怎么样」）→ 走对话回答、不只回执；② 刚提交那一刻卡片底部出现「记下了 · 想接着说就点提问」，刷新后消失；③ 明确陈述句 → 不调 AI。
- **细节**：[feature-reference §2](../reference/manuals/feature-reference.md) · change-log（2026-09-30 D4 批）。

## `memory` · 记忆

- **干什么用**：按日回看阿呆对你每条记录的理解（摘要 / 标签 / 情绪），并在档案页端出长期观察——「阿呆对你的了解」，你看完点「✓ 对」，这条偏好就从此被记住。
- **不做什么**：不做原始记录的替代展示（原文在 Feed 与时间线）；不做语义相似度自动合并（先用标签重叠 + 时间窗口的启发式）；不把观察当结论硬塞给你，须经你确认才进画像。
- **选型理由**：现有记忆是「全量 + 时间 + 只追加」的档案，与「筛选 + 分类 + 可更新淘汰」的活系统有差距——先补**进化**（同主题新版本取代旧版本、旧版留痕不删）与**出口**（长期观察有地方呈现、可确认），而不是先上语义模型（LLM 参与成本高）。
- **验收**：① 打开记忆页自动落在最近有数据的日期，空日提示「今天没有记忆」；② 标签栏取前 8 个 + 「全部」，点击可过滤；③ 「阿呆对你的了解」（365 天窗口）按置信度降序、行为模式与偏好各最多 3 条，点「✓ 对」后写回身份偏好并在后续问答中生效。
- **细节**：[feature-reference §7](../reference/manuals/feature-reference.md) · [RFC 20260801](../../direction/rfc/20260801-memory-system-evolution.md) · [RFC 20260923](../../direction/rfc/20260923-rhythm-and-memory-temporality.md)。

## `ask` · 问答会话（对话模式）

- **干什么用**：在任意记录卡片上点「提问」进入对话，可多轮续问；聊完点「结束对话」，阿呆把这段收成一句摘要挂回卡片，之后还能接着问。
- **不做什么**：不做「问：/答：」式的系统视角标签（第一原则：用户可见只有我和阿呆）；不在你不点结束时替你做自动收口；不把没收口的对话判成异常。
- **选型理由**：对话的价值全在**前文**，而现状是六成对话不足 5 轮、七成请求把「最近 20 条无关记录」当成了相关历史注入——故方向是把上下文改为**分层装配**（对话前文最高优先不裁剪 → 长期记忆按相关性与时效 → 检索按需 → 插件知识命中才注入）并留 token 预算与回放；该件尚为 draft，未授权改码。
- **验收**：① 卡片上点「提问」进入对话态，可多轮在同一张卡上续接；② 点「结束对话」后卡片显示摘要 + 标签，并保留可再次「提问」的入口；③ 收口摘要不超过 40 字、避免人称代词（既有收口契约）；④ 不点结束时对话保持可续、无任何自动收口（P2-对话1 走查口径：代价是数据卫生，非用户可见缺陷——**该条已归档**，见 `docs/archive/review-fixed-2026-10.md`）。
- **细节**：[feature-reference §3](../reference/manuals/feature-reference.md) · [RFC 20260929](../../direction/rfc/20260929-conversation-context-engineering.md)（draft）。

## `feed` · 主页 Feed 流（双世界）

- **干什么用**：打开 App 就是「今天」——阿呆把你的记录、卡片与简报按时间排成一列；想看别的就在这一屏双指一滑，进 Launcher（记忆 / 标签 / 身份 / 时间线 / 搜索的入口）。
- **不做什么**：历史不走 Feed（只经顶栏日期进时间线）；不做富文本；不在流里重复展示「AI 理解」条目；不为「探索」再造一份数据。
- **选型理由**：一个页面装不下「日常看今天」与「探索过去」两种意图，故拆成两个世界（World A Feed / World B Launcher）用手势切换，而不是往底栏堆 Tab——底栏 4 个 Tab 里空着 2 个，正是当初单页面的症状。
- **验收**：① 首页默认今日 Feed、分页每页 5 条，滚到顶端出现「load more」，达到今日总数即不再显示；② 历史记录不出现在 Feed，只能从顶栏日期进时间线；③ 空状态显示「还没有记录」+ 快捷输入提示；④ 双指滑动可在 Feed 与 Launcher 之间切换。
- **细节**：[feature-reference §1](../reference/manuals/feature-reference.md) · [RFC 20260722](../../direction/rfc/20260722-dual-world.md)。

## `brief` · 简报

- **干什么用**：Feed 顶部那张「今天」卡——一句问候 + 最多三行，回顾今天记了什么、交易上有没有该留意的事、各领域近来活不活跃。
- **不做什么**：不发明提醒（待办为空就一条不提）；不把周期性习惯（「每周四发版」）当待办提；不注入「发现习惯就自然提及」这类鼓励多说习惯的指令；Feed 为空时不出简报。
- **选型理由**：原设计一边让模型「发现习惯就自然提」，一边注入未完成待办与近 7 天记忆，结果一句状态陈述被转成永久待办、概览卡天天提醒——**节律 ≠ 待办**，故改为「命中日只作背景且不提」，习惯另走独立通道。
- **验收**：① 每次至多 3 行内容、每行不超过 30 字、纯文本（不输出 JSON、用真实 emoji 而非转义码）；② 只有待办非空时才提其中 1-2 条，否则一条不提；③ 周期性习惯不再出现在简报的提醒里（「概览卡天天提醒」不再复现）；④ 5 分钟缓存内的重复请求返回同一份简报。
- **细节**：[feature-reference §5](../reference/manuals/feature-reference.md) · [RFC 20260923](../../direction/rfc/20260923-rhythm-and-memory-temporality.md)。
