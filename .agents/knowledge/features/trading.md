# Trading 意图卡

> 收录规则与卡格式见 [_index.md §三](_index.md)。**只写意图，不写实现**（字段名 / 方法名 / 端点 / 请求响应一律链接出去）。
> 用法：要改某个功能前，先在这里补/更新它的卡。

## `trade.ledger` · 账本：导入 / 流水 / 对账

- **干什么用**：把券商的成交与资金快照导进来，落成可回看的逐笔流水；并随时答「账上和我手里对不对得上」——持仓、现金差在哪、差多少，逐笔说得清。
- **不做什么**：不做静默重放（拿不准就拒绝并给逃生路径）；不丢真实成交（卖超也照落流水、逐行标出被拒原因）；不硬拒转出（超额只警告 + 说明要等多少）；不做「可取」的每日自动结转（刻意留的边界）。
- **选型理由**：生产实测一次导入把已含在快照里的成交重放了一遍——现金被算成负数、三笔真实卖出被静默丢弃，三条真源（券商快照 / 逐笔流水 / 派生持仓）互相矛盾。故把「已修」的判据从「代码改过」升级为「存量回填 + 运行时自检 + 失败可见」：派生量恒等于「最近锚点快照 + 锚点之后的事件净变化」，对不上当天就能看见。
- **验收**：① 同一份成交日志重复导入不新增流水行（有成交编号按编号、无编号按指纹，双键都判）；② 锚点未知且存在需回放的行时拒绝导入并给出两条逃生路径（先导快照建锚点 / 只补流水），且不写任何文件；③ 卖超或未持有的成交流水照落 + 逐行给出被拒明细（不再「警告后消失」）；④ 资金与持仓导入先对账、差额不为 0 才要求你确认，差额为 0 不弹窗；⑤ 卖出回款当日只进「可用」、不动「可取」，转出超过可取时给人话警告而不拒绝；⑥ 账实自检有偏差或锚点未知时，部署门禁显式告警。
- **细节**：[trading-features §一](../reference/manuals/trading-features.md) · §十一 · [RFC 20260912](../../direction/rfc/20260912-trading-ledger-integrity.md) · [RFC 20261003](../../direction/rfc/20261003-trading-cash-position-linkage.md) · REVIEW P2-交易66、P2-交易73。

## `trade.holdings` · 持仓与账户卡

- **干什么用**：一眼看清手里有什么、值多少、今天赚亏多少——账户卡给总资产 / 现金 / 市值 / 累计盈亏，持仓列表逐只给现价、当日盈亏与仓位比例。
- **不做什么**：不把取不到的字段渲染成 0（一律「—」）；不用存储价冒充实时现价；不把「可用」与「可取」当同一个数；不让持仓与现金各改各的（两者是同一本账的两侧）。
- **选型理由**：你的口径是「转入有现金才能买、卖出有现金才能转出」——现金与持仓必须**强关联**。历史遗留是两条路各改一侧（九成八的实际成交走导入路径），于是两套现金从不互校、偏离可达数千元；收口成一本账后，任何成交要么同时改两侧、要么两侧都不改。
- **验收**：① 账户卡总盈亏 = 资产 − 本金（券商口径）；② 取不到的字段（区间收益率 / 当日涨跌 / 现价）显示「—」，绝不渲染成 0%；③ 行情失败时现价降级为存储价、再退成本价兜底，且降级不伪造盈亏；④ 现金以券商快照为锚 + 快照后事件净变化可重放，对账差额可解释、可追责（现金侧异常同样进自检，不只管持仓）。
- **细节**：[trading-features §一](../reference/manuals/trading-features.md) · §十一 · [RFC 20261003](../../direction/rfc/20261003-trading-cash-position-linkage.md) · REVIEW P2-交易59。

## `trade.case` · 案例库与三维打分

- **干什么用**：把你认过的「完美买点」一句话标下来，系统自动拉前后 K 线重算形态、还原画面；日后任何标的出现相似形态，就能问「像不像我库里的 N 个买点」——案例是手段，判定当下才是价值。
- **不做什么**：不做全市场每日扫描（自动只覆盖自选股 + 持仓，手动可查任意代码）；不做分时图（日线级别）；不做收藏夹式批量堆料；案例相似度不覆盖止损 / 仓位等规则硬判定。
- **选型理由**：原先自称的「完美图匹配度」其实没有样本库、只是规则阈值加硬编码分数映射，连「三维打分」的选股维度也一直没接（总分实为二维）——故补**真实案例 + 归一化相似度**双轨：规则引擎给确定性基线，案例相似度给经验增强，两者独立判定、独立降级。
- **验收**：① 一句话标注（标的 + 日期，类型 / 描述可选）即自动生成特征画像与后验窗口；K 线拉不到时拒绝且不落半成品；② 同一标的同一日期重复标注被拒；③ 判定当下返回与案例库的归一化相似度 Top 5（空库静默返回空、不报错）；④ 案例相似度不与规则硬判定互相阻塞，缺数据时各自如实降级；⑤ 打分口径如实：选股维度无数据时恒为空、总分按二维呈现，不得自称「完美图匹配度」（S7）。
- **细节**：[trading-features §十](../reference/manuals/trading-features.md) · [RFC 20260830](../../direction/rfc/20260830-trading-perfect-case-library.md) · REVIEW S7。
