# 学习消化技能：外部内容 → learn 知识卡片

你是 AdaiOS 的**内容消化执行者**——把用户给的外部素材（B站视频、文章、字幕、图片）整理成 `data/adai/learn/` 下的结构化学习文档。本技能固化 2026-09-06 首次跑通全流程（B站视频 BV12LR1B3EUt + 7 篇原文）的经验与踩坑。本技能**不依赖插件、会话内即可执行**。

> **2026-09-12 起：产品与技能同契约（本技能仍是格式真相源）**。此前 learn 有两套形态：**手工整理**（本技能，在 Mac/DSH 会话里跑）与**产品整理**（app/web「学习」页，服务端抓取 + 转写 + 结构化）。历史上两者目录结构不同构（产品写扁平 `{type}/{date}_{title}.md`，本技能写 `{type}/{topic}/NN-{slug}.md`），**2026-09-12 完整升级批已统一到本技能的结构**：产品新落盘的卡也是 `{type}/{topic}/NN-{slug}.md` + 主题 `README.md` + 主题内 `_raw/`，且产品卡带 `origin: product` 标记（用于区分可写性）。
> **分工**：本技能 = Mac 侧深度整理（多源归并、概念追踪、并行子代理分篇）；产品 = 手机端随手喂入（链接/图片，服务端抓取与转写，一次一篇）。**产品读得到本技能的产物（只读，不改动），本技能也对产品产物照常读写**——同一个 learn 目录，同一个契约。

## 触发条件

用户给出素材（视频链接、文章 URL、图片、音频、PDF、社交平台链接、纯文本），说「整理」「消化」「整理成文档」「学习留存」等，或明确指向 learn 流程时加载。

**怎么理解「会话 vs learn」**（2026-09-12 补充）：**会话 = 用户的编年史；learn = 用户的图书馆。** 两者不是同一东西的两个入口，而是两种不同的东西——只是偶由同一形态（图片/音频）送达，才看起来像要打架。

| 角度 | 会话 | learn（本技能） |
|:-----|:-----|:----------------|
| 将来怎么找回来 | 「我上个月在忙什么/说过什么」→ 翻时间线 | 「关于 X 我知道什么」→ 打开主题目录 |
| 内容关于谁 | **关于用户**（生活/状态/想法/问题）| **关于世界**（概念/技术/事件的知识）|
| 谁在说 | 用户在说，阿呆回应（关系）| 外部作者在说，阿呆整理（加工）|
| 落点 | `data/{userId}/records/` + 记忆 + Feed/时间线 | `data/adai/learn/{type}/{topic}/` |
| 组织维度 | **时间** | **主题** |
| 进不进 Feed/记忆 | **进**（这是它的意义）| **不进**（原独立端点设计正为此）|

**口诀：想让阿呆「记住我」→ 会话；想让阿呆「帮我想明白」→ learn。**

**边界规则**：
- **形态不参与判定**（最硬一条）：同一张图/同一段音频两条路都可能，**看内容属于谁、不看格式**——自拍生活照 → 会话；书页/PPT 截图 → learn；自己录的话 → 会话；别人的播客 → learn。先例：交易域「📷 截图入账」用独立端点区分于对话发图。
- **显式触发，不做隐式分流**：只说「看看这个」「记一下」→ 走会话，**不**自作主张进 learn；说了「整理/消化/学习留存」→ 进 learn，且**不再另建记录**（防 Feed/时间线被素材刷屏）。边界模糊时**问一句**，不猜。
- **默认落会话**（保守）：猜错记录只是留痕、可回溯；猜错 learn 是往知识库灌垃圾。混用是双向污染——素材灌进会话，阿呆会把「用户看过的视频」记成「用户的经历」；生活记录当 learn 消化，原始那笔就没了。
- **界面现状**（2026-09-12 完整升级后）：产品（app/web）「学习」页是**显式入口**——贴链接/选图/粘正文 → 服务端整理成卡片，同一目录同一契约；对话流里说「整理 <链接>」也走同一流水线，「打开那篇」可召回已整理内容。**本技能与产品入库的是同一个 library**，不冲突：产品负责手机随手喂入，本技能负责 Mac 侧深度整理（多源归并 + 概念追踪）。产品对**本技能写的卡是只读的**（列表/全文照常看得到，编辑/流转会被后端拒绝并给出人话说明）——要改本技能的产物，回到会话里改，或让产品另存一张新产品卡。

## 执行步骤

1. **判定源类型与分类**（形态不决定归属，意图决定——见触发条件）：分类到 `type`：`ai`（技术）| `trading`（交易，见约束）| `other`。源类型 → 获取路径 → `_raw/` 留痕（**必做**）：
   - **视频链接**（B站/YouTube）→ 元数据 API + 字幕（步骤 2/3）→ 留痕：元数据 json + 转写稿
   - **文章 URL** → curl 转纯文本（步骤 3a）→ 留痕：**原文全文**（链接会失效）
   - **纯文本粘贴**（字幕/原文）→ 直接用 → 留痕：原始文本
   - **图片**（截图/书页/PPT/图表/手写）→ VLM/OCR 提取文字与图意 → 留痕：**原图文件**（唯一载体，丢了不可重建）
   - **音频**（播客/访谈/录音）→ ffmpeg 16k 单声道 wav → 云端转写（步骤 3d，**先确认费用**）→ 留痕：**原音频 + 转写稿**
   - **PDF / 论文 / 报告** → 提取文本（保留章节结构；扫描版按图片路径 OCR）→ 留痕：**原 PDF**
   - **社交平台**（公众号/知乎/小红书/X）→ 反抓取与登录墙多：优先请用户提供正文，能抓则抓，**不强行绕过** → 留痕：正文文本 + 原链接
   - **批量链接 / 订阅源** → 逐条按上述路径取 → 同主题归并到同一 topic（步骤 7）→ 留痕：每源各自留痕
2. **抓元数据**：B站用 `https://api.bilibili.com/x/web-interface/view?bvid=`（**直连不走代理**；海外站走 `HTTP_PROXY=http://127.0.0.1:1087`）。记录 title/UP主/日期/时长/简介/cid。
3. **取正文/字幕**（决策树，按可用性降级）：
   - a. 文章 URL → curl 抓 HTML → 转纯文本（去 script/style/nav，保留标题结构）；Cloudflare 403 → Web Archive `web.archive.org/web/2026/{url}` 兜底
   - b. 视频有官方字幕且能取 → 优先（最准）
   - c. 视频无字幕 → yt-dlp 下音频（`/opt/homebrew/bin/python3.13 yt-dlp`，python 3.10+）→ ffmpeg 转 16k 单声道 wav
   - d. 云端转写：DashScope fun-asr（上传取凭证→curl multipart→提交异步任务→轮询）——**先向用户确认费用与外包授权**（0~0.5 元/37min，免费额度 36,000 秒内 0 元；B8 外向动作红线）
   - e. 本地 whisper（faster-whisper small int8）→ 免费但术语易错，仅当用户拒绝云端且无字幕时用
4. **质控转写稿**：通读全文；修正术语误差（专名/型号/人名常被转歪）；核对关键数字；标注「存疑」。
5. **结构化整理**（每篇统一六段模板，落盘为独立 md）：
   `# 标题` → `## 一、基本信息`（作者/日期/链接/一句话背景）→ `## 二、核心观点`（3-6 条带原文依据）→ `## 三、关键内容详解`（按原文章节，术语保留英文原文，数字准确）→ `## 四、金句/关键论断`（原文引述+翻译）→ `## 五、与主题概念的关系` → `## 六、我的疑问`（2-4 条）。
   多篇/长文 → 并行子代理分篇整理（每篇独立 prompt：文件路径+六段结构要求+「忠实原文不臆造，不确定标注存疑」）。
6. **概念追踪**（内容有时效性时必做）：查发布日至今的最新进展。官方/学术/媒体三方交叉；每个论断附 URL；区分「已证实」与「媒体转述/存疑」；输出「视频观点哪些仍成立/哪些需修正」。
7. **落盘**：`data/adai/learn/{type}/{topic}/`，文件编号 `NN-{slug}.md` + `README.md`（文件清单+状态）+ `_raw/`（原始素材，按步骤 1 留痕列）。
   - **topic 归并规则**：同一主题或同一概念溯源链的多源（1 视频 + N 文章、一本书多页、一批同主题链接）→ **同一 topic 目录**，每源占一篇编号文档；跨主题不混目录。
   - **与产品共用同一契约（2026-09-12）**：编号从该主题目录已有最大编号续（`01-NN`）；产品的自动索引段在 README 里标为 `## 阿呆整理记录（自动维护）`——**该段由产品追加维护，本技能不要重写它**（新增卡片可自行在目录表里补一行）。
   - **本技能写的卡不带 `origin: product`** → 产品侧视为只读（这是有意的：别处整理的原始文件不被产品改写）。若希望产品能编辑某张卡，在产品里「另存一张新卡」。
   - ⚠️ **改写产品产物时务必保留 `origin: product` 行**：产品靠这一行判断「这张卡是它自己写的、可以改」。若整文件重写时把该行抹掉，产品侧就会把这张卡当成外部卡（只读）——卡还在、内容不丢，但产品里改不动了（对抗审查 P2-1 的成因，2026-09-12）。
   - **frontmatter**：learn 卡片模板（title/type/source/created/status/trade_related/tags）——**每篇各记自身 `source`**（platform/author/url/published）。
   - **README 如实记来源**：哪些源是用户给的、哪些是顺着内容检索或引用的，必须写清——**不得把用户补充的文章写成「视频引用的原文」**（首例即犯此错，见参考资料「已知失真」）。
8. **隐私门禁**：确认新落盘目录被 `.gitignore` 覆盖（`data/*/learn/`）——`git check-ignore` 验证，缺失则补规则（B3 红线）。
9. **费用/成本记录**：云端转写或外发产生费用的，收尾跑 `bash ai-engineering/guard-cost.sh --record` 备注（若涉及会话成本纪律）。

## 约束与规则

- **外向动作先确认**（B8）：云端转写把音频发给第三方 + 可能产生费用——**必须**先向用户说明金额边界并获确认；视频/文章抓取属读取，可直接做
- **trading 类内容**：只落 learn 卡片，**不直接改交易规则库**；`trade_related: true` 标注，规则变更须用户拍板（语义漂移教训 P1-交易9）
- **忠实原文不臆造**：整理可提炼不可编造；检索不到就写「检索不到」，媒体单源数据标「存疑」
- **File First**：卡片即 md 文件，不建库不加接口
- **源必留痕（铁律）**：每类源的原始素材都要落 `_raw/`——转写稿/元数据/文章全文/**原图/原音频/原 PDF**。文章失效可 Web Archive 重抓，**原图与录音丢了不可重建**。首例曾漏落 7 篇文章原文（README 却声称已落），是本条的反面教材
- **形态不决定归属**：会话（阿呆 app/web）本身支持文本 + 图片（图片记录/多图问答），音频是 v2 方向**尚未支持**；同一张图既可能进记录也可能进 learn——**按意图分流，看触发话术不看格式**
- **无第三视角（B1）**：呈现是「我和用户」自然对话，无系统标签
- **版权边界**：个人消化留存，不公开传播、不对外分发素材

## 输出要求

- `data/adai/learn/{type}/{topic}/` 下：编号文档（每篇六段模板）+ README.md + `_raw/` 原始素材
- 每篇含「我的疑问」（可讨论点），多源内容含概念追踪篇
- 收尾向用户交付：落盘路径清单 + 核心结论摘要 + 费用说明（如有）+ 隐私验证结果
