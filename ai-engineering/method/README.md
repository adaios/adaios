# AI 工程流水线

> **定位**：跨项目可复制的「如何建 AI 工程」方法论（从 adaios 实践提炼）。**核心转变：把 AI 自动化挂在传统开发流程的工具切入点上，让机制替人记得——流程约定 > 内容编写。**

## 核心命题

```
代码工程 = 结果集（意图的投影）
AI 工程  = 驱动层（意图的发生地 + 效果历史的载体）
人的作用 = 审核内容 / 做决策 / 指方向（不参与重复执行）
AI 的作用 = 生产内容 / 执行流程（挂在工具切入点上自动跑）
```

## 三层模型（可复制骨架）

```
AI 工程
├── assets/    静态知识：规范（怎么做）/ 边界（不做什么）/ ADR（为什么）/ 坑（别踩什么）
├── workflow/  过程定义：讨论→方案→开发→审核→验收（六段闭环）
└── state/     动态真相：完成度 / 测试数 / 未修项（指针化，不复制）
```

## 关键设计

| # | 设计 | 说明 |
|:-:|:-----|:-----|
| 1 | **循环而非分层** | AI 工程 ↔ 代码工程互为输入输出（意图驱动代码，现状回喂决策）|
| 2 | **双读者分离** | AGENTS.md 给 AI / README 给人（工具无关命名）|
| 3 | **工具无关** | 纯 Markdown + 可校验脚本；任何 agent 读同一套 |
| 4 | **元治理** | AI 工程资产像代码一样有 CI（图谱/lines/孤儿 + `--fix` 回写）|
| 5 | **流程 > 内容** | 自动化挂在 git hook / CI / 部署切入点上，不靠人读文档记得 |

## 切入点图谱（流水线核心）

```
开发循环（AI 每个动作挂在工具上，机制替人记得）
│
├─ pre-task      开工前：上下文注入（状态/未修项/边界/坑）  ← 进攻侧
├─ pre-commit    提交前：文档对齐 + 结构 + 隐私 + 防复发   ← 最常用
├─ post-commit   提交后：轻量自审（自动派官查本次 diff）     ← 补漏
├─ pre-push      推送前：CI 等效检查（不提交就绕不过）        ← 硬闸门
├─ CI/GitLab     MR 触发：全量测试 + 审查 + 部署预览         ← 协作
├─ 部署前门禁     强制 review + guard 全量，不过关不部署       ← 最硬
├─ 部署后验证     自动 smoke test（新端点/核心链路）          ← 反馈
└─ 定时 cron     每周自动 audit + 检查点沉淀                 ← 防休眠
```

| 切入点 | 触发 | 机器强制 | 拦什么 | adaios 状态 |
|:-------|:-----|:--------:|:-------|:-----------|
| pre-commit | 提交 | ✅ | 文档对齐/结构/隐私/防复发 | ✅ 已做（四层）|
| post-commit | 提交后 | ✅ | 轻量自审（diff 派官）| ❌ 缺 |
| pre-push | 推送 | ✅ | CI 等效检查 | ❌ 缺 |
| 部署前门禁 | 部署 | ✅ | 强制 review + guard | ❌ 缺 |
| 部署后 smoke | 部署后 | ✅ | 新端点/核心链路 | ❌ 缺 |
| 定时 audit | cron | ✅ | 审查 + 沉淀 | ❌ 缺 |

## 新项目范式（搭流水线再写内容）

```
新项目启动 = 跑 init-ai-engineering.sh（脚手架）
  → hooks + guard 脚本 + 流程文件 + CI 模板 一条命令搭好
  → 之后 AI 内容生产顺着管道流（写功能 → 提交自动检查 → 部署自动验证）
  → 无需再研究"怎么搭"，直接开写功能
```

## 内容输出格式（人偏好，2026-08-16 确认）

- **图**：流程 / 逻辑关系（ASCII 流程、关系图）
- **表格**：对比、清单、状态矩阵
- **关联**：方案先给图/表，再给文字
