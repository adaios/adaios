# ADR-005：AI 协作入口标准化（AGENTS.md 统一入口 + 技能包体系）

**决策 1（入口统一）**：全库 CLAUDE.md→AGENTS.md 迁移——根目录 + 6 个子项目（services/adai-core、apps/adai-app、apps/adai-web、os/trading-engine、os/life-os、os/project-os）统一用 AGENTS.md 作为 AI 协作入口；AGENTS.md 只承载 AI 协作最小导航，人类侧完整文档见 docs/README.md。

**决策 2（技能包体系）**：高频工作流程封装为 SKILL.md 技能包——`ai-engineering/roles/`（8 审查官，防守）+ `ai-engineering/skills/`（new-api/new-domain/ship，建设/收尾），形成「建（建设）→ 收（ship）→ 守（审查）」闭环；规范见 `skills-spec.md`（name + frontmatter 9 字段融合、五段正文结构）。

**背景**：用户明确「不用 Claude Code」→ 以工具命名的 CLAUDE.md 不再合适；行业标准（Anthropic Agent Skills SKILL.md、Linux Foundation AAIF AGENTS.md）2025-2026 已成型，项目跟随行业标准。

**备选**：
1. 保留 CLAUDE.md 并让工具侧指向它（否决——工具命名不中立，且与 AGENTS.md 行业标准脱节）
2. 不封装技能包、靠 AGENTS.md 文本描述流程（否决——流程会漂移，无结构化加载/复用）
3. 本决策：AGENTS.md 统一入口 + SKILL.md 技能包体系

**结论**：AGENTS.md 工具无关统一入口；技能包封装高频流程，目录内唯一标准，工具侧配置零迁移。

**代价**：旧工具配置（如 Claude Code settings 指向 CLAUDE.md）需工具侧手动清理；技能包需要持续维护（重复≥2 次才新增，防流水账）。
