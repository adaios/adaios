# ADR-003：Domain=插件模型

**决策**：Kernel（记录/问答/记忆/档案/时间线/搜索/待办）= 人人平等常驻；Domain OS = 受控插件，通过 `Account.plugins` + PluginService + ContextEngine 全量门控，无插件用户不可见/不可写对应 Domain。

**背景**：原实现把 adai 的个人知识（os/trading-engine 87 课/规则）当「产品公共内容」注入**所有用户**上下文，与 VISION §4「Knowledge = 你的知识体系」相悖。

**备选**：
1. 公共内容注入所有用户（原状，已修）
2. 插件门控全通道（本决策）

**结论**：插件模型 + 门控全通道（D5 domain 收敛 + `/me/plugins` + Feed/promote 门控 + 三端显隐）。

**代价**：门控旁路风险（写入口漏 gateDomain）→ 检查点 B36/B40 端点清单枚举兜底。

**关联**：RFC `20260814-domain-plugin-model`；边界 B6（Domain 间不直接依赖）。
