# ADR-006：能力三层定位（core / builtin / optional）

**决策**：所有用户可见能力登记在**同一张表**里，只有 `tier` 与默认值不同——不再有「内核能力 vs 插件」两套机制：

| 层 | 内容 | 默认 | 能否关 | 实现 |
|:---|:-----|:----:|:------:|:-----|
| **core 内核** | 记录 / 问答 / 记忆 / 上下文 / 身份 / 存储 | 开 | **不可关** | Kernel 硬编码 |
| **builtin 内置能力** | **待办** / 搜索 / 时间线 / 简报 | 开 | 可关（用户侧） | Kernel 硬编码的 UI 项 |
| **optional 可选插件** | trading / learn | 关 | 可开（admin） | `Account.plugins` 门控 |

**判据一句话**：没它别的跑不起来 → core；第一次用就需要 → builtin；只有一部分人需要 → optional。

**背景**：2026-09-17 用户在生产里问「任务模块的作用是干嘛的 / 项目插件的作用」，调研钉出三个错位——① 同一个「待办」，前端/文档/用户拍板都算 Kernel 基础能力，后端写端点却 403 锁在 project 插件上（读得到、写不了）；② 待办两套载体并存，`RecordToTaskLinker` 在把活的那套（记忆 `actionable` → Feed 卡 + AI 上下文）搬进死的那套（Task 表 2026-08-01 起零写入）；③ project 插件名为「个人项目管理」，实为 AdaiOS 自举看板（git 提交数 / RFC 状态 / Kernel 组件），对他人是第三视角，对自己已被 `task-log.md` 替代。

**备选**：
1. **「一切都可以当作插件，包括任务 / 基础插件」**（用户在会话中提出）——否决：内核不能插件化（插件要靠它运行），且「基础插件」这个词会误导实现（迟早有人去给「记录」做门控）。
2. **保留 project 插件、只摘掉写端点 403**——否决：project 插件真正装的是自举看板，对他人是第三视角（两轮审查已判违规、建议迁移），且 `os/project-os` 知识已由 `task-log.md` 替代。
3. 本决策：三层定位 + 撤 project 插件 + 待办归 `kernel/todo`。

**结论**：`PluginRegistry` 只登记 optional 层（trading / learn）；builtin 层（待办）在 Kernel 硬编码、**无插件门控**（`/api/v1/todos` 不依赖 `PluginService`）；`os/project-os/` 知识文件按 File First **保留在仓库**，但不再注入任何用户上下文；旧 `data/{userId}/project/` 原样留存、不迁不删。

**代价**：端点破坏性变更（`/api/v1/project/**` 6 个端点删除，已装旧 App 404，用户已拍板「可重装」）；旧 project 数据成为孤儿文件（仅 11 条，保留可追溯）；将来真有第二个用户的通用项目管理需求，需另立插件重写（不复活本项目看板）。
