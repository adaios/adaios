# 陌生人首次使用检查清单

> 用法：**先禁读源码**（见角色装备纪律），只看渲染截图 / 用户可见文案 / 真人反应。逐条判 PASS/FAIL，FAIL 须附「他看到的 / 他以为要做的 / 实际该做的」。
> **三端各走一遍**：iOS 原生 App · Android 原生 App · Web 网站（含 PWA 装主屏）。三端的装机/签名/分发/通知能力不同，**不得用一端的结论代表另一端**。

## 一、入口可达（装不上万事皆休）

| # | 检查项 | 判定 |
|:-:|:-------|:----:|
| E1 | **iOS 原生 App** 能装上、能打开（签名不过期、不闪退）| PASS/FAIL |
| E2 | **Android 原生 App** 能装上、能打开，且**签名可覆盖升级**（非 debug 签名；密钥可保管，换机器构建仍能覆盖安装、不丢数据）| PASS/FAIL |
| E3 | **Web 网站**能打开、手机浏览器可用；PWA 能「添加到主屏幕」并以独立 App 形式运行 | PASS/FAIL |
| E4 | **该端的系统通知真的能到达**：Android（原生与 Web）是否存在任一推送渠道（APNs 仅 iOS；无 FCM / 厂商通道 / Web Push 即等于零通知），且产品不向该端承诺收不到的通知 | PASS/FAIL |
| E5 | **分发方式可复制**：APK 怎么给他、系统拦不拦（未知来源）、以后怎么更新到新版本 | PASS/FAIL |
| E6 | 非开发者能自己拿到账号：建号 → 密码送达 → 首次登录，全程无需作者本人到场 | PASS/FAIL |

## 二、空世界（新账号，不是你的账号）

| # | 检查项 | 判定 |
|:-:|:-------|:----:|
| W1 | 首次登录无报错、无白屏、无内部术语 | PASS/FAIL |
| W2 | 新账号第一屏**有明确下一步**（不是一句「还没有记录」就结束）| PASS/FAIL |
| W3 | 不靠任何人提示，能完成一件真事（他真想做的事，不是功能演示）| PASS/FAIL |
| W4 | 完成一次「原来有用」的体验所需时间可接受（记录实际耗时）| PASS/FAIL |

## 三、五问速判（每一问都要能在界面上找到答案）

| # | 检查项 | 判定 |
|:-:|:-------|:----:|
| Q1 | 这是什么？——第一屏能否自答 | PASS/FAIL |
| Q2 | 我是谁？——（多用户/账号身份）界面是否有交代 | PASS/FAIL |
| Q3 | 我能做什么？——能力范围是否可发现（而非靠人告知）| PASS/FAIL |
| Q4 | 下一步？——每个空态都给出可执行动作 | PASS/FAIL |
| Q5 | 搞错了怎么办？——误操作能改、能撤销，且他知道去哪改 | PASS/FAIL |

## 四、术语与自证（三端各查一遍）

| # | 检查项 | 判定 |
|:-:|:-------|:----:|
| T1 | 首屏与主路径无内部术语（插件 / 端点 / 画像 / 锚定 / 快照基线 / 活跃市值 / 三维打分 / 反哺 / 入库 / 字段…）| PASS/FAIL |
| T2 | 凡需要先懂产品才能读懂的文案，均判 FAIL（不是只有「看不懂」才算——**犹豫即缺陷**）| PASS/FAIL |
| T3 | 全流程未出现第三方视角标签（无「问：/答：/图片记录：/【备注】」）| PASS/FAIL |
| T4 | **三端文案同源**：同一功能在三端用同一套用词；不出现「app 已改人话、web 仍是内部术语」的漂移 | PASS/FAIL |
| T5 | 每个 FAIL 已指定「该在哪一屏补哪句话」（只报告，不直接修）| PASS/FAIL |

## 判定口径

- **P0**：装不上 / 拿不到账号 / 卡死不前（他无法靠自己前进）
- **P1**：能完成，但要猜、要人教
- **P2**：能完成，但过程别扭
