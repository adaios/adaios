# 06_AI_NATIVE_ENGINEERING_STANDARD

版本：v1.0

------------------------------------------------------------------------

# 1. 文档目的

AI Native Engineering Standard 定义 AI 参与软件工程时的质量规范。

目标：

> 保证 AI 提升开发效率，而不是降低工程质量。

------------------------------------------------------------------------

# 2. AI 修改代码标准

任何代码修改必须经过：

    Understand

    ↓

    Analyze

    ↓

    Plan

    ↓

    Implement

    ↓

    Verify

    ↓

    Document

------------------------------------------------------------------------

# 3. Bug Fix 标准

Bug 修复流程：

    发现问题

    ↓

    确认现象

    ↓

    分析根因

    ↓

    定义验收条件

    ↓

    修改

    ↓

    验证

    ↓

    知识沉淀

------------------------------------------------------------------------

# 4. 修改前检查

必须回答：

    1. 当前行为是什么？

    2. 根因在哪里？

    3. 修改影响哪些模块？

    4. 是否影响数据流？

    5. 如何验证？

------------------------------------------------------------------------

# 5. Context Standard

项目必须维护：

    Context

    ├── Architecture

    ├── Domain Model

    ├── Data Flow

    ├── Decisions

    └── Rules

代码变化必须同步对应 Context。

------------------------------------------------------------------------

# 6. Review Standard

AI Review 关注：

## Correctness

功能是否正确。

## Impact

是否影响其他模块。

## Maintainability

是否容易维护。

## Consistency

是否符合项目规范。

------------------------------------------------------------------------

# 7. Agent 使用规范

禁止：

    需求

    ↓

    Agent 直接修改代码

推荐：

    需求

    ↓

    分析

    ↓

    方案

    ↓

    执行

    ↓

    验证

------------------------------------------------------------------------

# 8. Commit 标准

提交应该包含：

-   修改原因
-   修改范围
-   验证结果

避免：

-   无意义提交
-   大范围混合修改

------------------------------------------------------------------------

# 9. AI Native Checklist

提交前：

    [ ] 理解需求

    [ ] 分析影响范围

    [ ] 完成测试

    [ ] 验证真实场景

    [ ] 更新 Context

    [ ] 更新 Knowledge

------------------------------------------------------------------------

# 10. 核心原则

1.  AI 提高速度，但不能降低标准。

2.  快速生成代码不是目标，可靠交付才是。

3.  每次修改都应该增强系统理解。

4.  工程规范决定 AI 协作质量。
