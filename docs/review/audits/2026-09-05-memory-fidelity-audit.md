## 四、结论与对方案的修正（重要）

1. **推翻 memory-fidelity.md 的乐观假设**：原稿写"原话没丢，丢的是证据链"。审计证实：**8 月初大量无卡对话的原话在入口就被 `ai_summary` 转述覆盖，从未落盘**——records/ 的 conversation 正文即终态。→ memory-fidelity.md §二 诊断需修订（见下）。
2. **E-A（读取侧吃原话）前置条件不满足**：8 月样本大部分无 cardId/无卡片，读取侧无料可保。**必须先解决"写侧保原话"**：无卡对话也把用户原问原句落盘（records 正文保留原话 + `aiSummary` 摘要字段并存，或至少不覆盖），否则 E-A/E-B 都是空转。
3. **kind 失衡 + 同质化**：decision 74%、同因记忆 20+ 条、fact 错标——记忆聚合/去重策略本身需要治理（升级链收敛、decision 限流、kind 分类校准），与"保真"是两条平行线。
4. **套话模板**：大量正文共用"延续了…/反映出…依赖外部确认/焦虑感"句式（如 mem_20260802_212149167 记"焦虑感"，原话只是问安排）——转述 prompt 需防心理归因滥用。

## 五、对 memory-fidelity.md 的修订建议

- §二 2.3 失真链：补"原话缺失层"——无卡对话原话从未落盘（8 月初主体）。
- §四 E-A：标注前置依赖 = 写侧保原话；E-C 由"远期"提前为"近期必要项"（至少无卡路径）。
- §四 E-B：evidence 无原话可引时降级为空——需先有写侧保真。
- §六 拍板点：新增 P4（写侧保原话的字段方案：records conversation 正文存原话 + summary 并存 vs 仅新入口开始）。
- §七 路径：审计 → **写侧保真（新 E-A'）** → 读取侧 → evidence。
