## 结论

**P0-1（对抗）+ P1（backend）——交叉命中同一算术缺陷（独立证据 ⭐⭐）**：
`computeDailyPnl` 已实现段把当日卖出量一律先冲抵「当日买入」，超出才用持仓 `avgCost`（当日末、已含当日买入摊薄）→ A 股 T+1 下当日卖出必为盘前旧仓：卖光后买回 / 卖旧+加仓场景出现**已实现与持仓日浮动重叠/漏算**，示例 q0=1000@10、SELL 1000@12 后 BUY 1000@12.5、收盘 12.6：旧口径约 −400 vs 真实约 +2100（符号翻转），且无任何附注。测试 6 场景全为单边，无同日同标的混合用例。

## 修复（本轮已落地，commit 见 change-log 2026-09-09 三官修复批）

1. **computeDailyPnl v2（T+1 语义）**：卖出成本 = 盘前成本——今日无买入 → 持仓 avgCost 即盘前（精确）；有买入/已清仓 → 回退「当日之前」流水历史买入含费加权；仍无基线 → 持仓成本兜底并诚实附注。仅当存在「卖出晚于当日最早买入」（T+0 边界，A 股不会出现）才对卖出冲抵当日买入价并附注。持仓日浮动「今日买入仍持」= max(0, 当日买入 − T+0 已冲抵部分)，不再重复计已被卖出冲抵的当日买。
2. **主流程随流水重算（P1-1）**：当日成交在 15:05 后落库（单笔 POST /trades、/trades/batch、/trade-log/confirm、历史成交导入）→ `refreshTodayPnl` 重算写入 todayPnl（只改该字段；仅当 account 存在；best-effort）——晚间补流水后不再「浮动冒充全日盈亏且无法自愈」。
3. **导入空明细保留（P1-2）**：资金股份导入明细为空（当日清仓后导出无行）→ 不用 sum=0 覆盖（保留系统精确值）；带「当日盈亏」列且有明细才以券商真源覆盖。
4. **frontend P2/P3**：清仓「流水」徽标改中性灰淡底（不再与买点高分蓝撞色 V9-8）+ 字号 11 + 来源说明拆独立短行；补 widget 测试（flow 行显 / import 行不显 + 图例行可见）。
5. 测试：DailyPnlComputeTest +4（T+1 卖光后买回 2100 / T+0 混合 2600 含附注 / 导入空明细保留 428 / refreshTodayPnl 只写 todayPnl）；web +1 徽标 widget 用例。后端 1339→**1343** · web 179→**180** 全绿。
