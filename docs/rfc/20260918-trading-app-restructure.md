# 交易 App 端重排——「记录 → 对账 → 照见」三层与两条铁律

> **触发**：2026-09-18 用户「**目前交易 app UI 和交互不咋地，怎么说派出 UX/UI 审查下？**」
> → 按项目体系派出 `ui-reviewer` + `ux-reviewer` **隔离并行**（各自按 `roles/*.md` + `checklists/*.md` 走查，只报告不改代码），
> 两人共出 **24 条**（去重后 14 条，P0 无）；用户随后亲口补三条：
> ①「**资金和空头/多头区间，需要占据这么大空间吗？一般用不上的功能**」
> ②「**截图入账没有特别顺利过，整个流程**」③「**总资产堆积太多东西了**」。
>
> **本 RFC 的立场**：那些条目都是**症状**。24 条里绝大多数会在结构定下来之后自然消解，
> 因此本件**不排细节修复顺序**，只定三件事：**功能分三层、核心唯一、口径划边界**，再据此排四批实施。
>
> **实施边界**：本 RFC 是文档先行件；**获批后才开工**，且**不部署、不 push**（等验收）。

## 一、现状事实（钉到行号与实测）

**F1 · 页面是「按数据来源」堆的，不是「按使用频次」排的。**
`trade_page.dart` 的 `ListView` 顺序（`:966-1010`）：账实横幅 → **快照卡**（券商资金）→ **资金卡**（转账）→ **活跃市值卡**（择时开关）→ 当日总结 → 复盘横幅 → 快记 → 确认卡 → 精确表单 → 候选卡 → 未记行 → 持仓区。
15 个区块平铺一列，其中「券商真源 / 行情 / 系统推导」三类数据混排。

**F2 · 核心动作（记录与入账）既是最小目标、又在最深位置。**
用户日常路径是「截图入账 → 候选确认 → 看持仓」，但「截图入账」入口是 `11px` 绿字下划线（≈19pt 高，`:1079-1093`），排在第 7 位，前面压着快照/资金/市值三张卡（合计 ≈400pt，iPhone 上已出首屏）。

**F3 · 三套口径在界面上没有任何标注。**
同一屏出现四个「当日/今日」（账户级 / 今日区间 / 本票当日盈亏 / 本票今日涨跌幅）；app 金额用「46.4万」（`_fmtMoney :2666`）而 web 用「¥464,235.18」；收益日历「本月」是前端遍历求和（`profit_calendar_page.dart:66-79`）而账户卡「本月」来自 `GET /trading/pnl-periods`——**两个数**。

**F4 · 唯一有数据丢失风险的入口，恰好保护最弱。**
候选行「×」≈20×14pt、点击**直接 `DELETE`、无确认无撤销**（`:1283-1289`、`:602-619`）；而破坏性更弱的「全部忽略」反而有确认弹窗（`:625-635`）。

**F5 · 「截图入账全程不顺」有生产实证。**
最坏 90 秒（3 张 × VLM 单图 28s）全程只有 11px 转圈、重复点击静默 return；
**实测后果**：2026-09-18 用户 10:34、10:35 **连传两次**同一批成交（生产日志两次各 6 笔）。

**F6 · 同一条结构结论只在 web 落地。**
web 端 2026-08-16 已 Tab 化（`_buildTabWorkspace` 7 Tab，代码注释即「Tab 工作区替代纵向堆叠（UI/UX 审查方案）」）；
app 端至今 15 区块平铺，实测 **14 档字号 / 6 档圆角 / 9 种容器规格**硬编码。

**F7 · 本批（2026-09-18 修复批）新引入一处回归。**
候选卡加「收起」后，`_uploadScreenshots` 只重置 `_dropped`，**漏了 `_candidatesCollapsed`**（`:523-529`）——收起过之后再发截图，新候选藏在收起态里。

## 二、问题定性：不是细节，是结构

四条判断（本 RFC 的全部依据）：

1. **页面按「数据来源」分层，而不是按「使用频次 × 对账目真假的影响」分层** —— F1/F6；
2. **核心（记录与入账）不在心脏位置** —— F2/F5。而它是**所有下游数字的上游**：持仓、今日盈亏、批次、收益日历、阿呆建议全部建立在「账对不对」之上；
3. **两条铁律缺失**：
   - **写账必回执**：凡改账的操作，必须给出「这笔进了哪里」（流水/持仓/现金？被挡住？为什么）—— 用户今天的「提交不成功」、90 秒黑箱、候选不可改，都是这条缺失；
   - **展示必标口径**：凡展示给用户的数字，必须能看出它是券商口径 / 系统推导 / 行情 —— F3；
4. **口径边界（锚定日）在实现里用错了日期语义** —— 2026-09-18 事故：凌晨 00:24 导入的持仓快照以**导出日**（09-18）为锚定日，于是当天真实成交被划进「券商已含」一侧、全部被拒（REVIEW P0-交易59）。这不是字段 bug，是边界规则实现走样。

## 三、目标形态

### 3.1 功能三层（与模块定位对齐）

> 模块定位（RFC 20260902，用户拍板）：trading 是「**阿呆 memory 内核在交易域的投影**」——历史成交沉淀为对自己交易的理解；
> 五层记忆：①事件（流水）②模式（行为标注）③案例（买点库）④规则（纪律）⑤认知（待建）。
> 它**不是交易终端**（无下单/平仓执行，建议只输出不执行）。

| 层 | 是什么 | 页面归属 |
|---|---|---|
| **记录** | 把当天真实成交准确地变成账 | 截图入账 · 快记 · 候选确认/编辑 · 精确表单（web：历史成交导入） |
| **对账** | 券商真源 ↔ 系统推导是否一致 | 账面自检（drift/gaps）· 快照导入（低频）· 口径标注 |
| **照见** | 从账里长出阿呆的理解 | 持仓 → 建议 · 复盘 · 批次 · 收益日历 · 案例库 |

**明确移出交易页主区**（它们是配置，不是日常）：活跃市值区间、资金转入/转出/本金、快照导入。

### 3.2 布局：隐私优先 + 焦点分配（依用户 2026-09-18 补充约束修订）

> **用户原话**：「注意私密性，核心数据不要在首页显示，**金额私密，比例无所谓**，不用那么常规 UI，
> 焦点和次要分配好，目前主要的可能就是**每日入账和持仓批次查看**，其他可能是一些快捷操作，
> 毕竟 app 比 web 更方便，**web 端导入数据更方便**。」

**焦点只有两个（其余都不得与它们争视觉重量）**：
① **每日入账**（截图入账 / 快记 → 候选 → 确认）② **持仓与批次查看**。

```
┌─ 首屏：只有「今天的操作」和「持仓」，且【不含任何金额】─────────┐
│  今日 · 09-18                          [👁 揭开金额]           │
│                                                                │
│     [ 📷 截图入账 ]      [ ✍️ 说一句… ]      ← 两个一级动作     │
│                                                                │
│  持仓 4 只 · 仓位 62%        当日 +1.2%      ← 比例可显示       │
│  ──────────────────────────────────────────                    │
│  云南锗业 002428   +123.5%   300股                             │
│  有研新材 600206    +11.6%   600股                             │
│  中国稀土 000831     +1.0%   400股                             │
│  亨通光电 600487     +0.7%   300股                             │
│  ──────────────────────────────────────────                    │
│  ▸ 资金与配置   ▸ 数据源   ▸ 账面自检        ← 默认折叠         │
└────────────────────────────────────────────────────────────────┘
       ↓ 点持仓行（主动进入）
   批次详情弹窗：这里才显示金额（成本/市值/盈亏/现金）
```

**隐私规则（写进实现约束）**：
- **首页面（交易页默认态）不得出现金额**——总资产、总盈亏、市值、现金、成本价一律不渲染，或渲染为 `••••`；
- **比例无所谓的**：涨跌 %、盈亏 %、仓位 %、比例条照常显示——它们不泄露资产规模；
- **金额只在「主动进入」的容器里出现**：批次详情弹窗、账户详情、设置本金等——用户点进去才看得到；
- **可选揭开**：`[👁]` 一次性揭开当前会话的金额（离开页面即复原），避免"看明细要一页页点"的摩擦。

**去常规化（不做卡片堆叠）**：
- 主区用**数据列表 + 细分隔线 + 等宽数字**（对齐、密、可扫），不再用"9 种容器规格的圆角卡片"；
- 卡片只留给**真正独立的事件**（候选卡、异常横幅），其余信息用文字层级表达；
- 主次靠**字号 / 颜色 / 留白**三样拉开，不靠"再加一层背景块"。

**取舍说明（遵守 app 设计约定）**：`apps/adai-app/AGENTS.md` 定「**单页 — 无 BottomNavigation，无 tabs，无多级页面**」，
因此**不照搬 web 的 Tab 化**，改用**首屏聚焦 + 默认折叠**：交易页的价值是"一屏看清今天"，Tab 会把状态藏起来。

**双端分工（本 RFC 明确写死）**：

| | App（手机） | Web（电脑） |
|---|---|---|
| 定位 | **随手记 + 看**（轻、快、单手、任何地方） | **导入 + 编辑 + 管理**（重、全、键鼠、大屏） |
| 主力 | 截图入账 · 持仓/批次查看 | 通达信导入 · 批量编辑 · 规则 · 案例库 · 历史成交 |
| 原则 | 重操作不在 App 硬做——**引导到 web**（既有先例：「导入资金」按用户拍板不做，管理归 web） | 看盘/随手记不重复造（已有 app） |

### 3.3 两条铁律（可检验的约束）

- **铁律 1（写账必回执）**：`POST/PUT/DELETE` 类交易写操作，返回后界面必须给出**逐笔结果**：进了流水 / 改了持仓现金 / 只记账不改账 / 被挡住（原因 + 下一步）。**不允许**"转圈后无变化"或"只报第一条原因"。
- **铁律 2（展示必标口径）**：每个金额/盈亏数字，用户必须能回答"**这是谁算的、什么时候的**"。实现形态：紧邻标注（`券商口径 · 09-18` / `系统推导` / `行情 15:02`）+ 同一数字在全产品口径一致（app/web 不得一个「万」一个「千分位」）。

### 3.4 三套口径与边界（写进实现约束）

| 口径 | 内容 | 来源 | 更新时机 | 谁有权改账 |
|---|---|---|---|---|
| 券商真源 | 持仓、资金、成交明细 | 通达信文件导入（手动） | 低频（收盘后/隔天） | 只有券商文件 |
| 行情 | 现价、昨收、涨跌 | 腾讯 / 东财 | 30 分钟自动 + 手动刷新 | 只影响显示 |
| 系统推导 | 流水、批次、盈亏、日历、建议 | 本地文件推导 + LLM | 写入即算 | 记录与入账 |

**边界 = 锚定日**：`≤ 锚定日` → 券商说了算（系统**只补流水、不动持仓现金**）；`> 锚定日` → 系统推导说了算。
**锚定日不得取「文件导出日」**——通达信文件名日期是导出日、内容是上一交易日收盘状态（2026-09-18 事故根因，已修于 `normalizeAnchorDate`，本 RFC 把它升格为**明文约束**）。

## 四、方案（四批，顺序即依赖）

### A1 · 记录与入账链路（改动集中在一个区块，可独立验收）

| # | 问题 | 改法 | 契约影响 |
|---|---|---|---|
| A1-1 | **本批回归**：收起后新截图不展开 | 上传成功回调重置 `_candidatesCollapsed = false` | 无（纯前端） |
| A1-2 | 90 秒黑箱、重复点击静默 | 上传即插入**占位卡**（「在认这 N 张截图，最慢约一分半」）；重复点击回到同一张卡的状态提示，不再静默 return | 无 |
| A1-3 | 结果落在屏幕外 | 出结果后**自动滚到候选卡**（补 `ScrollController`）；「全部确认入账」提到卡头与「收起」同行 | 无 |
| A1-4 | 候选不可改，错一笔只能重录 | 候选行可点开轻量编辑：**价格 / 数量 / 方向 / 成交日期** | 复用既有 `PUT /trading/trade-log/meta`、`PUT /trade-log/date`；App DTO 补 `orderId`/`fee` 字段（后端已返回） |
| A1-5 | 行级「×」20×14pt 且直接真删 | 命中区撑到 **44×44**；单条丢弃给**确认或可撤销 SnackBar** | 无 |
| A1-6 | 「全部确认入账」是写操作却无确认，且紧邻「全部忽略」 | 确认前回显「要记这 N 笔？其中 M 笔缺日期会跳过」；「全部忽略」降级为卡头文字入口，与主按钮拉开 | 无 |
| A1-7 | 缺日期时确认按钮仍可点，点了才被拒 | 有缺日期 → 按钮置灰 + 下方写原因（可点直达那一行） | 无 |
| A1-8 | 确认结果只报第一条原因 | 失败/降级/跳过**逐笔回执**（铁律 1 的落地） | 响应已含 `failures/duplicates/ledgerOnly`，前端完整呈现 |

**验收锚点**：用 2026-09-18 那张 6 笔截图 → **6 条候选 → 可就地改一笔 → 确认后逐笔回执**。

### A2 · 结构重排（首屏聚焦 + 隐私 + 去卡片化）

- **首屏只留两块**：「每日入账」与「持仓（含批次入口）」——其余一律折叠；
- **隐私模式（新，硬约束）**：首页默认态**不渲染任何金额**（总资产/总盈亏/市值/现金/成本价 → 省略或 `••••`），只显示比例（涨跌 % / 盈亏 % / 仓位 %）；金额只在**主动进入**的容器（批次详情 / 账户详情 / 设置本金）出现；提供一次性 `[👁]` 揭开（离页即复原）；
- **截图入账做成一级动作**（≥44pt、有图标与底色），与「说一句」并排；快记条复用首页输入栏尺寸档（15px / 40pt / 圆角 14，hint 不得用 `darkGrey6`）；
- **去卡片化**：持仓区改**数据列表**（等宽数字 + 细分隔线 + 对齐），不再一种信息一个卡片；
- **资金 / 活跃市值 / 数据源 / 账面自检收进默认折叠**（折叠头显示关键摘要，如「资金 · 仓位 62%」而不带金额）；
- 圆角与卡片内距收敛为 **2~3 档常量**（消除 6 档圆角 / 9 种容器规格）；
- **次要功能一律"快捷操作"待遇**：单行、无卡片、可折叠（复盘 / 规则 / 案例 / 日历入口按此处理）。

### B · 数字可信度

| # | 问题 | 改法 |
|---|---|---|
| B1 | `pnl ?? 0` → 算不出的盈亏显示「+0 红色」 | null → 「—」中性色；`== 0` 单独判平（不带号、不上红绿） |
| B2 | 资金卡 `a?.cash ?? 0` → 「现金 ¥0.00 · 总资产 ¥0.00」与同屏快照卡「—」打架 | 账户未就绪一律「—」；相关按钮禁用并说明 |
| B3 | app「万」vs web 千分位；无 FittedBox | 账户级金额统一**千分位 + ¥**，大字套 `FittedBox`；「万」只留给日历格等极窄场景 |
| B4 | 收益日历「本月」与账户卡「本月」两个真相源 | 月合计消费同一份数据（`pnl-periods`）；若必须前端求和则标注口径与截止时间 |
| B5 | 同屏四个「当日/今日」口径各异 | 标签显式区分：账户当日 / 今日区间 / 本票当日 / 本票今日涨幅 |
| B6 | `darkGrey5` 承载 11px 数据标签（实测 2.58:1，AA 需 4.5:1） | 承载数字的元信息提到 `darkGrey4` 以上；`darkGrey5` 只用于非关键说明 |
| B7 | **隐私兜底（工程约束）**：任何新增的金额展示都可能再次泄露 | 金额一律走统一"金额呈现"入口（受隐私开关控制），**禁止裸写 `Text('¥…')`**；补一条回归测试断言**首页默认态不出现金额字符串** |

### C · 打磨（触达 / 一致性 / 漂移）

- 小目标统一 ≥44pt：复盘横幅关闭键（16pt）、活跃市值双选（34pt）、补日期 chip；
- 资金卡三个 `OutlinedButton` 未指定 style（吃 M3 默认近白 primary）→ 显式走 AppColors 体系，把最高视觉权重留给记录/入账；
- 持仓卡主操作（点卡看建议）补可点提示；附属批次行弱化 chevron；
- 交易页补 `RefreshIndicator`（日历页已有）；顶栏三个 18px 图标收敛或补文案；
- 日历：金额 `clip` 硬裁改 `ellipsis`/`FittedBox`（宁可省略不可显示错的数）；禁未来月份 + 加「回到本月」；明细补当天成交；
- 双端漂移：web `discardTradeLogCandidate` 同步 id 口径；Feed 卡确认失败给直达候选卡的入口。

## 五、契约与数据影响
