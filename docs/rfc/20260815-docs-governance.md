# 文档治理：瘦身 + 单一事实源

> 背景：用户决策「先不着急功能开发，先治理好工作流程」。本 RFC 为第一阶段——**文档减法**（病灶 A/B/C），功能代码零改动。第二阶段（自伤自查、使用形态审核）见 §六，不在本批执行。

---

## 一、问题（全部有实测证据）

| # | 病灶 | 证据 |
|:-:|:-----|:-----|
| A | **测试数/端点数散在 ≥5 处，注定漂移** | 已漂移 3 处：P2-7（根+adai-core CLAUDE.md 写 15/50，实测 16/51）；adai-app 写 86，实际 92；adai-web 写 44，实际 46 |
| B | **「当前焦点」= 无限增长的历史日志，历史冒充状态** | 根 CLAUDE.md 412 行，当前焦点占 99 行、56 条已完成条目（每条 100-300 字）；08-15 批自己都漏写了 step-1（P3 docs×7 已记录） |

根因：**数字会过期，指针不会；状态与历史混放，文档越写越重、越写越没人读。**

---

## 二、治理原则

1. **单一事实源**：一个事实只在一处定义，其他文档引用（指针），不复制
2. **状态与历史分离**：常驻文档只留「当前状态」；历史进归档，按需可查（git log 是最终真相）
3. **瘦而准优于全而陈**：宁可少写，不可写错/写旧——过期数字比没有数字更误导 AI

## 三、方案详表（每项改动）

### 改动 1：新建 `docs/reference/status.md` —— 状态快照（唯一事实源）

- 内容：后端测试数/端点数/Controller 数、三端测试数、生产环境、当前发布状态（v1.0.0 待 tag）
- 更新规则：**每批 /ship 时更新**（/ship 已要求同步文档，把这一条并进去）
- 替代：根 CLAUDE.md「测试状态」、adai-core/adai-app/adai-web CLAUDE.md 的测试数段落

### 改动 2：新建 `docs/reference/change-log.md` —— 批次变更日志

- 内容：根 CLAUDE.md「当前焦点」56 条已完成条目 → 压缩为每条一行（`日期 | 批名 | 一句话摘要 | 测试数变化`）
- 作用：历史有处可查，但不再占用每次会话必读的 CLAUDE.md
- 替代：CLAUDE.md 历史批次、REVIEW 已修复区的超长条目（git log 仍为最终真相）

### 改动 3：根 CLAUDE.md 瘦身

| 段落 | 现状 | 改为 |
|:-----|:-----|:-----|
| 当前焦点·已完成 | 56 条历史条目 | **只保留最近 1-2 批**（当前正在推进的），其余移 change-log；「已完成」改为「当前焦点批」 |
| 当前焦点·方向进展 | 保留（是状态） | 保留，压缩为 3 列 |
| 当前焦点·测试状态 | 5 处计数之一 | 指针：`测试状态见 docs/reference/status.md` |
| 当前焦点·运行环境/关键文档 | 保留 | 保留 |

预期：412 → ~280 行；当前焦点 99 → ~15 行。

### 改动 4：REVIEW.md 减负

| 区块 | 现状 | 改为 |
|:-----|:-----|:-----|
| 摘要区 | 7 条滚动审核历史 | 只留最近 2 次；更早靠 git 历史 |

预期：172 → ~100 行。REVIEW 只留「战略 + P0-P2 未修复 + 最近摘要 + 成本表」。

## 五、风险与对策

| 风险 | 对策 |
|:-----|:-----|
| CLAUDE.md 变短 → AI 会话缺历史上下文 | 历史在 change-log/REVIEW/git log，按需可查；「正在做什么」被保留 |
| status.md 变成新的漂移点 | 更新规则写入 /ship（唯一写入点），CLAUDE.md 不复制数字 |
| REVIEW 减负后已修复记录变少 | git log 是最终真相，REVIEW 只是视图；change-log 提供批次摘要 |

4. 测试数不变（后端 422 / adai-app 92 / adai-web 46 / adai-admin 32）
