# 交易插件目标形态——决策时点的对话式提醒与四要素铁证

> **触发**：2026-09-21 深夜，用户在看到 09-20 刚部署的「记录 → 对账 → 照见」重排（v3.73 / iOS 构建 9）之后，
> 仍说「**目前 app 交易插件的功能，我不满意**」，并在随后四轮问答里把用法讲清楚了。
>
> **本 RFC 的立场**：不满意的**不是功能缺失，也不是 UI 细节，而是形态错位**——
> 项目已经把必要的**数据**都攒起来了（清仓回合、批次、流水、规则、画像、资金曲线），
> 却把它们做成了**给用户看的报表**（三维打分列、行为模式统计面板、案例库 Tab）。
> 用户要的是**阿呆在决策时点对他说一句话，并且当场掏得出证据**。
> 「报表」是系统视角，与项目第一原则（不出现第三视角）本就相抵。
>
> **实施边界**：本件是文档先行件；**获批后才开工**，且**不部署、不 push**（等验收）。

## 一、用户画像（亲述 + 数据佐证）

### 1.1 亲述（2026-09-21，原话）

> 「对我的作用是，持仓，批次情况，**目前日线级别**，一般习惯**早盘买，尾盘卖**，
> **不太会在中间时间放飞和止损**，所以需要阿呆**提醒我，给我意见，尤其给我铁证**，
> **通过我之前的操作**，懂我意思么？**数据同步可以放到收盘后**，包括每日复盘可以根据数据更新」

四轮问答的收敛结果：

| 维度 | 用户选择 |
|:--|:--|
| 真正会用 | **看某只票的仓**（批次 / 成本 / 止损）——多选里只勾了这一项 |
| 可以砍掉 | **案例库 · 三维打分 · 行为模式统计** |
| 铁证含义 | **四要素全选**（本人历史操作统计 / 具体数字证据链 / 规则依据原文 / 可回溯可追责） |
| 出现时点 | **早盘（买点）· 尾盘（卖点）· 收盘后小结与复盘**，且**买点提醒并入早盘**（不实时盯盘） |
| 数据同步 | **账放收盘后**；每日复盘**随数据同步更新** |

### 1.2 数据佐证（生产 `api-access.log` 全期写操作，GET 多为开页自动加载故不计）

| 他真正在做的 | 次数 |
|:--|:--|
| 截图入账链路（解析 13 · 提交 12 · 改日期 16 · 确认 10 · 丢弃 5） | **56** |
| 要建议 `POST /advice` | 17 |
| 导入（历史成交 13 · 归集保存 7 · 持仓 3） | 23 |
| 忽略推送 | 12 |
| AI 复盘 | 2 |

| 他说可以砍的 | 写操作次数 |
|:--|:--|
| 案例库（标注 / 匹配 / AI 理解） | **0** |
| 16 项规则参数 | **0** |
| 三维打分 | **0** |

**读法**：他的日常是一条窄路——**把真实成交变成账 → 对账 → 看某只票的仓**；
而插件表面积有一半（案例库 / 规则参数 / 打分 / 行为模式 / 复盘叙事）他从未主动使用。
且案例库仍在**自动回填**（`cases/` 33 个文件，目录 mtime = 当日 15:35 自动任务）——不用它，它还在后台跑。

## 二、问题定性：不是"少功能"，是"形态错位"

用户的每一句抱怨，翻译过来都是同一个结构性问题：

| 用户的说法 | 现状 | 他要的 |
|:--|:--|:--|
| 「不太会在中间时间放飞和止损」 | 早/午/尾/收盘**四节点等频推送** | 只在**他会动手的两个时点**出现 |
| 「需要阿呆提醒我，给我意见」 | 打分列 / 统计面板 / 案例 Tab（要他自己去读） | **主动对他说一句话** |
| 「尤其给我铁证，通过我之前的操作」 | 统计是**总体**口径（胜率 / 纪律遵守率） | 证据要**贴着他自己的历史**、能核对 |
| 「数据同步可以放到收盘后」 | 盘中也在等实时数据（取数失败即空值，P1-交易60） | 账盘后同步；盘中零操作 |

**结论**：把「照见」能力**从报表改造成对话**，并把它**装到正确的时点上**——
这是本 RFC 的全部内容。能力底座（数据、规则、AI、推送渠道）**已经齐了**。

## 三、目标形态

### 3.1 早盘（买点）——「今天该不该动、动哪只」

**时点**：开盘前（建议 09:15，与现有早盘节点对齐；用户拍板可调）。
**并入**：现有「买点提醒」不再实时推，**合并进这一条**（用户明确选择）。

形态（人话 + 四要素，示例）：

```
阿呆：今天有 2 只进了你的条件——

· 600487 亨通光电  现价 18.42
  ① 你的历史：你过去 6 次在「B2 放量突破」买入，4 次在 3 日内卖出、平均 +2.8%
  ② 证据：量比 2.3（你要求 ≥ 2.0）· KDJ.J = 72（你要求 < 90）· 距 20 日低点 +11%
  ③ 规则：《买点规则》B2 条原文「量比放大 2 倍以上 + KDJ 勾头向上」
  ④ 位置：距你上次卖出的 19.10 还有 3.7%，你的止损习惯位 −7% = 17.13

· 000831 中国稀土  现价 53.30（同上格式）

（无信号则这一条不发——不制造噪音）
```

### 3.2 尾盘（卖点）——「今天该不该卖、卖哪只」

**时点**：收盘前（建议 14:50，与现有尾盘节点对齐）。

形态：

```
阿呆：你手上 3 只，两只要看一眼——

· 000831 中国稀土  +6.2%（成本 50.18）
  ① 你的历史：过去 8 次盈利 ≥ 6% 卖出，7 次次日回落（平均回吐 2.1%）
  ② 证据：今日量比昨日 1.4 倍 · 距你上次卖出位 54.10 还差 0.8%
  ③ 规则：你的规则第 7 条「尾盘涨幅 > 5% 且放量 → 考虑兑现」
  ④ 位置：这笔若卖出，本回合 +6.2%（已扣双边费用约 0.11%）

· 600206 有研新材  45.88，跌破你设的止损 46.20（本批剩余 300 股）
```

### 3.3 收盘复盘（数据同步之后）——「今天到底发生了什么」

**时点**：收盘后，且**必须等到当天的账同步完成**（用户原话「每日复盘可以根据数据更新」）。
**若当天没同步**：不硬生成，改为一句「今天的持仓/成交快照我还没看到，导一下我再给你复盘」。

形态：

```
阿呆：今天你做了 2 笔，我按你的账核过一遍——

记账：买 600487 100 股 @18.42 · 卖 000831 200 股 @53.30
账实：一致（3 只标的派生持仓与落地持仓相符）
只记流水的：无
复盘：000831 这笔持了 4 天，+6.2%，卖在放量当天——
      与你过去 8 次同类卖出相比，这次位置偏好（分位 前 25%）
明天：600487 若跌破 17.13 触发你的止损习惯位
```

### 3.4 「四要素铁证」的定义（本 RFC 的核心约束）

用户四要素全选。**没有这四条，宁可不说**——这是本条目的验收红线：

| # | 要素 | 数据来源 | 现状 |
|:-:|:--|:--|:--|
| ① | **本人历史操作统计** | `sold.json` 清仓回合 + `lots` 批次（按形态/时段/涨幅区间分组） | ⚠️ **缺**：现有统计是总体口径（胜率/纪律遵守率），**没有按形态分组的 N 次/胜率/平均盈亏** |
| ② | **具体数字证据链** | `positions`/`lots`（成本/数量/止损）+ 行情（现价/量比/KDJ）+ 规则参数 | ✅ 基本齐（`closeAdvice` 已在产出这类文本） |
| ③ | **规则依据原文** | `os/trading-engine/` 知识库 + `TradingRuleSettings`（16 参数） | ⚠️ **缺**：现在是整段注入，**没有按规则 ID 精确引用原文**的能力 |
| ④ | **可回溯可追责** | `AdviceHistoryRepository`（已有 `data/{user}/trading/advice-history/`） | ⚠️ **缺结果回填**：建议落盘了，但**没有"这条建议后来对不对"的回看** |

**③ 的补充口径**：引用原文必须**逐字来自用户自己的规则库**（`os/trading-engine/`），
不得由 AI 复述改写成"大概是这个意思"——用户要的是能核对的原文。

**④ 的补充口径**：每条建议落盘时记下**依据快照**（当时的价、量、形态判定、规则命中），
N 个交易日后回填「实际走势 / 用户是否操作 / 结果」——这是"可追责"的实体，
也是①的统计能越用越准的来源。

### 3.5 午间（用户拍板**保留**）——只报状态，不催操作

**拍板（2026-09-22）**：用户明确「**D1 不砍**」，午间 12:00 那条保留。
但按他的节奏（盘中不放飞、不止损），这条**不能被写成"提醒"**——否则每天中午都在对他说
「现在该动手」，与他的用法直接相悖。**定位 = 知会，不是提醒。**

四条推送的分工就此写死：

| 时点 | 回答的问题 | 性质 |
|:--|:--|:--|
| 早盘 09:15 | **买点什么** | 提醒（决策） |
| 午间 12:00 | **现在是什么状态** | 知会（**不给操作建议**） |
| 尾盘 14:50 | **要不要卖** | 提醒（决策） |
| 收盘后 | **今天做完了什么** | 复盘 |

**午间这条的形态约束**：
- 只陈述**事实**：持仓的当日大致位置（按**昨收盘同步的账** + 当前价）、**是否已触及你设的止损**——
  即使触及也只说事实与位置，**不出现「快卖 / 建议减仓」这类催促**（该不该卖归尾盘那条）。
- **不给决策建议**（四要素里的"判断"留给早/尾盘）；但可以给**数字与位置**（要素②的弱化版）。
- 无异常（没有触及止损、也没有持仓）时**不发**——保留≠天天发。

## 五、数据同步与建议的时序（架构约束）

用户拍板「**账放收盘后同步**」，因此时序被钉死如下：

```
盘前/开盘   ← 行情（系统自取）  +  昨收盘同步的账（持仓/批次/成本/止损）
              └→ 早盘买点推送（3.1）
盘中        ← 用户在忙，阿呆不打扰（不推"盘中异动"，不催操作）
尾盘 14:50  ← 行情（当日实时）  +  同上那份账
              └→ 尾盘卖点推送（3.2）
收盘后      ← 用户导入「持仓股 / 资金股份」快照 + 历史成交（**账在此刻才变**）
              └→ 账实自检 → ① 同步完成即可出「收盘小结」
                          → ② 复盘随数据更新（3.3），未同步则如实说"还没看到"
```

**关键推论（写进实现的约束）**：

1. **盘中不读"今天的账"**——它根本不存在（用户还没导）；拿旧账当新账是最危险的谎（P2-交易50/51 同族）。
   所有盘中/尾盘文案必须标注**账的日期**（"按你 09-19 收盘的账"）。
2. **行情失败必须显式**（P1-交易60）：双源都失败时，**不发**带空洞数字的推送，改为
   「今天行情没取到，这条我暂时给不了」——**不知道 ≠ 没问题**。
3. **复盘不是定时到点就发**：它是"数据同步完成后"的产物。同步事件（导入成功）应触发复盘刷新，
   而不是 15:30 硬发一份基于旧账的复盘。

## 七、契约与数据影响

- **`AdviceEntry` 扩展**（A3）：新增依据快照与回填字段 → `data/{user}/trading/advice-history/` 文件
  **MINOR 变更**（加字段，旧文件读作缺失），登记 `data-format-freeze.md`。
- **推送 payload**：`PushMessage` 复用现有字段，不新增渠道；四要素作为正文组织方式，不改渠道契约。
- **端点**：预计**不新增端点**（复用 `advice` / `push-settings` / `integrity`）；
  若 A1 的统计需要独立查询，再加 `GET /trading/evidence/...`（届时同步 api-spec）。
- **`ui-state`/口径**：所有涉及"今日/当日"的文案必须带**账日期**（呼应 RFC 20260918 的"展示必标口径"铁律）。

## 八、验证（怎么算做完了）

1. **四要素不缺项**：任一条推送，逐条能指到①的 N 次统计、②的数字、③的原文、④的落盘记录；
   缺任一条 → 该条**不发**（回归测试钉住"缺证据不发"）。
2. **时点正确**：盘中不出现任何"提醒操作"的推送；账日期在每条文案里可读。
3. **复盘与同步联动**：未同步 → 不出复盘（给人话）；同步完成 → 复盘刷新且口径与 `integrity` 一致。
4. **可追责闭环**：任意一条历史建议能查回当日的依据快照与后续结果。
5. **不制造噪音**：无信号 → 该节点不发；统计样本不足 → 明确说"样本还不够"。

## 九、非目标（明确不做）

- **不做自动交易/下单**：模块定位仍是"投影与照见"（`20260902-trading-memory-positioning`）。
- **不做盘中实时陪伴**：用户明确"盘中不放飞不止损"——盘中打扰是负价值。
