# 交易逐笔批次跟踪与行为纠偏

> **方向 RFC**：trading 插件当前持仓是「摊薄成本 + 整只一个止损」，看不见每一笔买入——「分批建仓 + 短线博一下」混在一起、以及「赚了舍不得卖、破止损还补仓」的行为，全部被摊薄口径掩盖。本 RFC 定**批次（lot）模型**：持仓细化到每一笔买入独立跟踪/止损/标注，配合当日成交同步、每日操作总结、推送定时消失，破「越套越深」的行为闭环。

---

## 〇、背景与痛点（用户场景，2026-08-25 用户提出）

| # | 场景 | 现状问题 |
|:-:|:-----|:-----|
| A | 有低成本底仓，回调后又买入（不是好机会），短期想卖最近买的、底仓不动 | 持仓只有摊薄成本，分不清「哪笔是底仓、哪笔是短线」；卖出按摊薄算，「卖一半」说不清卖的是哪批 |
| B | 短线博一下：浮赢过舍不得卖；破止损不卖反而补仓，越套越深 | 摊薄成本把成本线越摊越低、浮亏比例变小 → 「没那么糟」的数学幻觉，给侥幸补仓递刀；止损只对整只，说不清「哪批」该走 |

**根因**：持仓粒度 = 股票，不是每笔买入；止损粒度 = 股票，不是每批。摊薄口径在数据层面纵容补仓。

## 一、时间模型约束（先决条件，用户确认）

阿呆看不到实时成交：用户 **T 日收盘后**把当天成交喂给阿呆（通达信导出 / 截图 / 一句话），阿呆记录、分析，**T+1 日起**推送。

→ **买入当下无拦截/实时提示**，行为提醒全部走「**记录即标注 + 次日推送**」：

- T 日导入/归集 → 当场标注行为 → 当晚复盘可生成
- T+1 早盘计划带行为提示；盘中批次级止损轮询；浮盈回吐 / 短线超期持续盯

## 二、核心定义：三层模型

| 层 | 定义 | 作用 |
|:--|:--|:--|
| 成交单 | 通达信导出的原始成交（orderId 唯一） | 客观事实、幂等去重基础 |
| **批次 lot** | 用户心智的「一笔买入」= 同标的 + 同方向 + **同日** | 跟踪单位：成本/盈亏/止损/角色挂批次 |
| 回合 round | 批次从建立到全部卖出的完整生命周期 | 复盘总账：这批到底赚了多少 |

**关键规则**（用户拍板）：

1. **批次切分：按日合并**——同标的同方向同日 = 一个批次（一天最多一个买批/卖批）；跨日自动新开；批次成本 = 当日多张成交单**加权平均**（含费）
2. **卖出：LIFO**——不建批次，先扣最近买入批次，数量不够往前扣；一笔卖出跨多批 → 各批按自己成本分算已实现盈亏
3. **批次关闭**：剩余数量 = 0 → 自动生成回合总账（买入→卖出完整盈亏），进复盘/清仓统计
4. **初始批次**：导入的底仓（无对应流水）→ 标「初始批次」，成本/止损/角色取持仓字段，不丢历史
5. **批次止损**：每批一个止损位（未填默认 −7% 可后改；买入即带止损是用户既有纪律）；批次破止损单独推送，不跟底仓混
6. **处理顺序**：导入的成交按成交时间排序后逐笔处理（A 股 T+1，顺序确定，LIFO 才准）

## 三、批次推导（纯推导，不落盘）

批次视图 = 从逐笔流水**重放推导**（`trades/{yyyy-MM}.json` 已有日期/数量/价格/费用/止损/买点/原因），**不新增落盘文件、不改持仓主模型、不动券商账户口径**：

```
按 symbol 分组流水 → 按时间排序重放：
  BUY  → 同日并入当日买批（加权成本）｜跨日新开买批
  SELL → LIFO 扣最近批次剩余，扣完即关（生成回合）
重放后 持仓数量 与 positions.md 差额 → 初始批次（成本=avgCost，止损/角色取持仓）
```

- 批次 id 稳定：`{symbol}_{buyDate}_{序号}`（推导幂等）
- 对账：重放持仓 vs positions.md 差异 → 导入/展示时警告（防漏导静默错）

## 四、行为标注（记录即标注，推导不落盘，进当日总结 + 复盘）

| 行为 | 判定 | 说明 |
|:--|:--|:--|
| 亏损加仓 | 买价 < 同标的上一买批成本价 | 越跌越买/摊薄信号 |
| 追高 | 买价 > 同标的上一卖批均价 | 低卖高买 |
| 短线新开 | 新批次且角色 = 短线 | 博一下标记 |
| 破止损未走 | 现价 < 批次止损位 且仍持有 | 该走没走 |
| 浮盈回吐 | 批次峰值浮盈回吐 ≥ 50%（K 线回溯，尽力而为） | 说好的浮盈没走 |
| 短线超期 | 短线批次持有 > N 交易日（默认 5） | 博一下博成中长线 |

阈值先保守默认，`os/trading-engine` 规则文档登记，后续配置化（P2）。

## 五、当日成交同步（导入自动识别双模式）

现状（缺陷）：历史成交导入**只补流水不重算持仓/现金**（对账只报告不改数据）——给「补历史」设计的，不适合「每日喂当天成交」工作流。

改造：导入时自动识别——

- **同步模式**（成交在最近窗口内且流水基线完整）：逐笔走正常交易链路 → **同步更新持仓/现金/流水**；orderId 幂等（重复导入不重复加减）；处理完回放对账
- **补录模式**（明显历史）：维持只补流水 + 提示（现状）
- 导入响应含：`syncMode` + 对账结果 + **当日操作总结**

## 六、每日操作总结（导入/归集后秒出）

客观聚合（买卖笔数/金额/时段，复用 `?date=` 聚合）+ 行为标注（新增/扣减批次、亏损加仓 n、追高 n、破止损未走 n）——**不耗 AI 秒出**；AI 复盘保持晚上/手动触发。

## 七、推送定时消失（按类型 TTL）

| 类型 | 保留期 |
|:--|:--|
| 行情类（stop-loss / near-stop-loss / loss / gain / break-cost / market / session / buy-point） | **次日 09:30 消失**（当天收盘后晚上仍可看，次日开盘前自动清——实施时按对抗审查 P1-5 修正，原定「当天收盘消失」会让用户收盘后看 App 误以为推送坏了） |
| 汇总类（当日操作总结 / 复盘） | **次日 23:59** |

- pushes 记录加 `expiresAt`（落盘时算好）；前端展示过滤过期 + 后端读取/写入顺手清理过期
- 用户不再需要手动左滑删时效推送

## 八、端点设计

| 方法 | 路径 | 功能 |
|:--|:--|:--|
| GET | `/trading/lots?symbol=&state=open\|closed\|all` | 批次视图：批次明细（日期/数量/剩余/成本/现价/盈亏/距止损/角色/买点）+ 已关回合（roundPnl） |
| POST | `/trading/trades/import` | **响应扩展**：`syncMode` + 对账 + 当日操作总结（含行为标注） |
| 推送 | `pushes/{date}.json`、Feed 展示 | 推送记录带 `expiresAt`，过期不展示 |

（其余复用：批次止损判定挂现有 30 分钟行情轮询；早盘计划/复盘注入批次与行为标注；行为阈值走规则文档）

## 九、双端 UI

- **web**：持仓 Tab 批次展开行（批次明细/止损/盈亏/角色 + 已关回合）；导入结果含当日操作总结卡片
- **app**：持仓卡批次简版（最近批次成本/距止损）；Feed 推送过期自动消失；导入/归集后当日操作总结展示
- 遵循 B1 第一原则：全部以「我和阿呆」对话呈现，无系统标签

## 十二、验收标准

1. `GET /trading/lots`：同日多单合并一批（加权含费）；跨日新开；初始批次兜底；已关回合含整批盈亏
2. LIFO：卖出先扣最近批次；跨批分算已实现盈亏
3. 批次止损独立：某批现价 < 该批止损 → 单独推送（不跟底仓混）
4. 当日成交导入 → 持仓/现金/流水同步，orderId 幂等；历史导入 → 只补流水（双模式自动识别）
5. 导入响应含 syncMode + 对账 + 当日操作总结（客观 + 行为标注）
6. 行为标注六类判定正确（测试覆盖）
7. 推送带 expiresAt：行情类当天收盘、汇总类次日消失；过期不展示/被清理
8. 回合总账：批次清仓自动汇总
9. guard-meta/align PASS + 全部测试通过

## 十三、不做（本版范围外）

- 买入实时拦截/提示（时间模型不允许，看不到实时成交）
- 批次手动拆/合（按日合并后不需要，P2）
- 行为阈值配置化（先常量 + 文档登记，跑起来再调，P2）
- 除权除息调整 / 多市场（P2）
- 回合与 sold 清仓股数据打通（P2，数据源不同，先各自独立）
