# 交易计划与复盘闭环

> **一句话**：让系统从「提醒你」变成「**你承诺、系统守**」——前晚写清楚明天买什么、卖什么、什么条件；当天条件到了就用**你自己的原话**喊你；收盘对账「计划做了几条、有没有做计划外的」；一笔走完之后，再拿**你自己的规则库**检查这一轮做对了什么、违反了哪条。

> **触发来源**：2026-10-03 用户原话——「**我可以整理第二天操作规则，买和卖，到时候结合起来提醒我；就是说我必须认真对待这件事情，就像开公司我要认真对待我的每一笔投资，就像打仗我要规划好我的子弹，必须抬高自身态度**」。

---

## 一、定位：为什么要反转「谁写计划」

系统**已有**四个推送时点（09:15 / 12:00 / 14:50 / 15:30），09:15 那条在产品里就叫「早盘计划」——**但它是系统生成的**（读持仓 + 自选买点 + 止损位算出来的）。本文要把它反过来：

| | 现状 | 本文 |
|:--|:--|:--|
| 计划由谁写 | **系统**（读数据算出来） | **用户**（前晚自己定） |
| 提醒语气 | 「今日关注：600206 逼近止损位」 | 「**你昨晚定的**：600206 跌破 45.50 就走」 |
| 性质 | 近似建议（系统替你判断） | **守你自己的约** |

**这个反转同时解决了两件事**：① 产品的边界问题——系统不产生判断，自然不是「投资建议」；② 用户的纪律问题——承诺是自己下的，提醒才有分量。

**目标不是「系统更聪明」，而是「用户更认真」。** 因此本文的度量不是模型准确率，而是 **计划执行率**（计划 N 条里做到了几条）——一个纯事实、可长期累积的自我账本。

## 二、事前：第二天的操作规则

### 2.1 数据形态（File First）

`data/{userId}/trading/plans/YYYY-MM-DD.json`——**文件日期 = 该计划管的那一天**（前晚写、次日执行）。

> **为什么是 `.json` 而不是起草时的 `.md`**（独立审查 2026-10-03 指出契约与实现不一致，已按实现收敛）：
> 与 `transfers.json` / `sold.json` 同惯例，且结构化读取不必再写一个 Markdown 解析器（少一处会出错的地方）；
> 「人可读」由 `GET /trading/plans/{date}` 的返回与前端页面保证。

```markdown
# 2026-10-08 操作计划

## 卖出
- 600206 有研新材｜跌破 45.50｜清仓
- 002428 云南锗业｜到 95.00｜减半

## 买入
- 000776 广发证券｜回到 19.50 以下｜买 500 股

## 约束
- 只做计划内的票，不追高
```

每条计划三个要素：**标的 · 条件 · 动作**。缺条件的（如「清仓 600206」= 开盘即做）也允许，条件为空即「无条件」。

### 2.2 一句话写（**用户已选**）

复用既有 `POST /trading/trades/parse` 的一句话解析能力（自然语言 → 结构化，LLM 优先 + 正则兜底），新增计划语义的槽位：

| 用户说 | 解析为 |
|:--|:--|
| 「明天 600206 跌破 45.5 清仓」 | symbol=600206 · cond=`price < 45.50` · action=清仓 |
| 「002428 到 95 减一半」 | symbol=002428 · cond=`price ≥ 95.00` · action=减半 |
| 「广发回到 19.5 以下买 500 股」 | symbol=000776 · cond=`price < 19.50` · action=买 500 |

**解析失败不猜**：落到「我没听懂，你是说——」并给出可编辑的结构化草稿（与既有交易解析同一约定：`matched=false` 转精确表单）。

### 2.3 提醒我写（**用户已选**）

前一日 **20:30**（可配）若次日计划文件不存在 → 提醒一次，**只提醒一次、不追命**。文案必须是阿呆的口吻（B1 无第三视角），例如：

> 明天的作战计划还没写。要不要现在花两分钟定一下？哪怕只写「明天不动」也算数。

**「明天不动」是合法的计划**——空仓也是一种决定，且它让「计划外操作」的判定成立。

## 三、事中：按你的条件守

### 3.1 四个时点（沿用既有 cron，只换内容来源）

| 时点 | 现状内容 | 本方案内容 |
|:--|:--|:--|
| 09:15 | 系统算的持仓概览 + 买点 | **先念你的计划**：「今天你定了 3 件事…」（然后才是持仓事实） |
| 盘中轮询 | 行情/止损/盈亏类推送 | **条件触发**：「**你定的 45.50 到了**，现价 45.32」 |
| 14:50 | 尾盘卖点 | **计划进度**：「计划 3 条，触发了 2 条，都做了吗」 |
| 15:30 | 收盘复盘 | **对账**（见 §四） |

### 3.2 触发的三条纪律

1. **引用原话**：提醒里必须带上用户当时写的那句（「你昨晚写的是『跌破 45.50 清仓』」），而不是系统改写过的判断句。
2. **只报事实，不加判断**：说「现价 45.32，低于你定的 45.50」；**不说**「建议止损」「该走了」。
3. **触发一次即止**：同一条计划当日不重复轰炸（与既有推送防重同一约定）；用户可标记「已知悉 / 已执行 / 不执行」。

## 四、事后：收盘对账

每日收盘（或次日早盘）给出**纯事实**的三栏对账：

| 计划 | 条件是否触发 | 实际做了什么 |
|:--|:--|:--|
| 600206 跌破 45.50 清仓 | ✅ 触发（09:41 现价 45.32） | ✅ 10:03 清仓 800 股 |
| 002428 到 95 减半 | ❌ 未触发（最高 92.7） | — |
| —— | —— | ⚠️ **计划外：买入 000831 200 股** |

**「计划外操作」是这张表最有价值的一栏**——它正面对上规则库里的 **R96 四不原则（不追 → 不动 → 不慌 → 不乱摸）**。判定完全依赖流水（已有），无需用户输入。

**累积指标**：`计划执行率 = 已执行 / 已触发`、`计划外操作次数`。按周/月可看趋势——这是「态度」的可量化账本。

## 五、事后（深）：一轮完整交易的规则检查

> 本节原为账本 RFC 的 §十一，2026-10-03 拆出独立成文（那份回归「账本强关联」单一主题）。它与本文同源：**都卡在「账本口径不完整」**——轮次识别依赖流水配对，而券商导出的清仓股表不提供轮次。

### 5.1 口径：「一轮完整交易」怎么算（**用户拍板 C**）

| 口径 | 规则 | 实测轮次 | 取舍 |
|:--|:--|--:|:--|
| A 严格 | 持仓归零即一轮结束 | 238 | 客观无参数；但把「82 秒后回补」算成两笔 |
| **C 同日合并** ✅ **已选** | A + **同一交易日内「卖光→买回」合并为同一轮** | **232** | 更贴近「一段连续的持有意图」 |
| B 宽松 | 归零后 N 个交易日内买回算同轮 | 取决于 N | 需定 N，易主观；**不做** |

**建仓完毕的定义（用户给出）**：**卖出之前的最后一次买入 = 建仓完毕**，其后 N 个交易日为观察窗（暂定 3 个交易日）——用于 R53/R87 类「该涨不涨」判定。

### 5.2 为什么必须自己识别轮次（生产实测）

通达信「清仓股」表是**标的级总账**（首次介入 → 最后一次清仓，累计全部买卖），**没有轮次概念**：

- **铁证**：160/172 只标的的「买卖次数」**完全等于该标的全部流水的买卖笔数**（000776 = 33+16、002279 = 54+18、000547 = 11+9…），而流水显示 000776 实际做了 **7 轮**；
- **后果**：文件给 172 条，流水还原 **232 轮** → **60 轮（26%）原本不可见**；
- **同日「卖光→买回」实测 6 处**，4 处有精确时刻：601618 中国中冶 **82 秒**、600036 招商银行 58 分钟、603551 奥普科技 4.5 小时、601336 新华保险 5 小时；
- **口径缺口**：`parseSold` 丢弃了清仓股表的「清仓天数」「清仓后涨幅%」两列——后者正是「卖飞了没」的现成答案。

### 5.3 规则检查矩阵（规则 ← 过程指标）

| 规则（`os/trading-engine/knowledge/context/rules.md`） | 判定输入 | 现状 |
|:--|:--|:--|
| **R55 盈转亏立刻走** | 峰值浮盈 ≥ 阈值 且 最终亏损；峰值日 → 清仓日的交易日数 | ❌ 未做 |
| **R66 只输一根K线** | 首次收盘跌破止损位日 → 实际清仓日 | ❌ 未做（缺止损位，§5.5） |
| R67/R72 止损三级别 / 幅度 3-5% | 止损位相对成本比例 | ❌ 未做 |
| R68 入场即设止损 | 该轮是否有止损位 | ❌ 未做 |
| **R69 被套不补仓 / R90 短线不加仓** | 每次加仓当日是否处于浮亏 | ❌ 未做 |
| **R53 没涨=错** | 建仓完毕后第 N 个交易日相对成本的表现 | ⚠️ 部分（现按「持仓天数」粗判） |
| R88 超配是涨出来的 / R51 两根中阳减半 | 峰值浮盈 ≥ 阈值后是否减仓 | ❌ 未做 |
| R81 单票仓位上限 25% | 该轮建仓成本 ÷ 总资产 | ❌ 未做 |
| — 胜负 | 每轮最终盈亏 | ✅ 已有（sold 表） |

**现状**：`SoldTradeVerdict` 只吃**两个输入**（持仓期涨幅% + 持仓天数），只能覆盖 R53/R66，且都是粗判。

### 5.4 实测结果（用户 230 个已平仓轮次）

参数：峰值「曾赚过」**≥3%**（用户拍板）· 止损基准 **−4%**（R72 的 3-5% 取中值，用户拍板）· 「被套」**>1%**。

| 规则 | 命中 | 占比 | 过程数据 |
|:--|--:|--:|:--|
| **R55 盈转亏没走** | **65 轮** | **28.3%** | 平均峰值 **+6.9%** → 最终 **−4.3%**，从峰值平均**扛 5.4 个交易日** |
| **R66 跌破 −4% 未当日走** | **38 轮** | — | 平均**多扛 13.2 个交易日** |
| **R69/R90 被套加仓** | **172 轮** | **74.8%** | 共 **819 次**加仓发生在浮亏 >1% 时 |
| R53 建仓完毕 3 日仍未脱离成本区 | 32 轮 | 41.6%（77 轮有效） | — |
| 胜负 | 亏损 149 轮 | **胜率 35.2%** | — |

**最典型一轮**：**600584 长电科技** 2026-07-22 → 08-03，峰值 **+9.4%**（就在买入当天）→ 最终 **−25.9%**，扛 **9 个交易日**，期间买入 5 次。

> ⚠️ **口径声明**：止损基准是**规则默认值**而非真实止损位（1721 笔流水带 `stopLossPrice` 的 0 笔）；
> R53 仅 77 轮有效（本地日线截至 2026-08-31 + 部分轮次过短）。以上为**实测近似**，非精确复盘值。
>
> ⚠️ **口径已升级（2026-10-03 实施批）**：上表数字出自**调研期脚本**，当时峰值浮盈用「**全轮摊薄成本**」
> 对比每日 high——而独立审查（P1-5）指出这会让**加仓前的价格被算成浮盈**，从而**系统性多报 R55**。
> 实施版本已改为「**当日成本**」（截至该日全部买入的加权均价）逐日推进，并补了回归用例
> （`TradingRoundServiceTest.peakPct_usesCostAtThatDay_notWholeRoundAverage`）。
> 因此**上面 65 轮 / 28.3% 是旧口径的偏大值**；用新口径重跑会**变少**（具体数值以实际运行的
> `GET /trading/rounds` 为准——本文不编造一个未实测的替换数）。

### 5.5 两个硬约束

1. **止损位从来没进过系统**：1721 笔流水带 `stopLossPrice` 的 **0 笔**，`lot-stoploss.json` 不存在——通达信「历史成交查询」与「持仓股」**都没有止损位列**。→ R66/R67/R68 目前只能做**「应然（规则默认）vs 实然（实际亏损）」**对照；要按真实止损位复盘，须新增数据来源。
2. **复盘阈值必须进 `rules.yaml`**：峰值「曾赚过」与「被套」阈值直接决定命中数（实测：阈值 2% → R55 = 94 轮；3% → 65 轮，**差 29 轮**）。现状只有实时提示用的 `givebackPeakPct: 20`，没有复盘阈值。

### 5.6 边界：**只陈述事实，不作建议**（用户明确要求）

- ✅ 「这一轮峰值 **+9.4%**、最终 **−25.9%**，从 07-22 扛到 08-03（9 个交易日），命中 **R55**」
- ❌ 「你应该在 +9.4% 时卖」「下次记得止盈」「这票还能涨」
- 不预测、不给目标价、不评「该不该」——与既有边界一致（建议只输出不执行；阿呆是镜子不是操盘手）。

## 六、闭环总图

```
前晚：一句话写次日计划（或「明天不动」）
   ↓
当日：09:15 念计划 · 盘中条件触发（引用你的原话）· 14:50 进度
   ↓
收盘：对账 —— 执行率 + ⚠️ 计划外操作（R96）
   ↓
一笔走完：轮次识别（口径 C）→ 规则检查（R53/R55/R66/R69…）
   ↓
长期：计划执行率 · 规则命中率 · 胜率（全是事实，不掺判断）
```

事前没有承诺，事后的复盘就只能对规则、对不了**你自己**。本文的价值就在把这条链接上。

---

## 七、不做边界

- **不生成计划**：系统绝不写「建议明天买 XX」；可给线索（「自选里 3 只有买点信号」= 事实），是否写进计划由用户决定。
- **不下判断、不预测、不给目标价**。
- **不自动执行**：没有任何下单/平仓按钮。
- **不改动既有推送时点**：只换内容来源，不新增打扰时段（除 §2.3 那一条「提醒写计划」）。
