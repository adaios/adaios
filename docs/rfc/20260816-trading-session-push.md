# 交易时段节奏推送（早盘计划 → 午间跟踪 → 尾盘建议）

> **方向 RFC**：交易模块的主动服务从「等异动才推」升级为**按交易时段节奏主动服务**——开盘前给计划、中午跟踪进度、尾盘给当日建议；推送渠道从「仅 App 内 Feed」扩展出**微信**（不打开 App 也能收到）。这是框架+插件形态（`framework-plus-plugin-model`）在推送层的落地：渠道 = 插件，Feed 默认、微信第一个外部实现。

---

## 一、背景（现状限制，诚实评估）

| # | 现状 | 限制 |
|:-:|:-----|:-----|
| A | 推送只在 App 内 Feed（`MarketAlertService` 落盘 → Feed 读取）| **不打开 App 就看不到**——"你不问，App 也告诉你"的前提是打开了 App |
| B | 检测是 30 分钟轮询（免费行情源 qt.gtimg.cn 无推送接口）| 不是实时；且**频率与用户实际节奏不匹配** |
| C | 推送内容是被动异动（跌 3%/涨 5%/破成本线/真止损）| **没有主动服务**——用户要的是按交易时段被服务：开盘有计划、中午有跟踪、收盘有建议 |

用户明确的时间原则：**交易操作时间是早盘和快收盘，最多中午一个查询**——不需要高频轮询，需要的是"该用的时候给到"。

## 二、目标

1. **三个交易节点主动推送**：早盘计划（9:15）→ 午间跟踪（12:00）→ 尾盘建议（14:50），工作日。
2. **真止损异动兜底**：现价跌破止损位立即推（R66，保留 2026-08-16 A 最小闭环）。
3. **推送渠道插件化**：`PushChannel` 抽象——Feed（默认）+ 微信（Server酱，不打开也收到）。

## 三、方案

### 3.1 时段服务（三节点 + 兜底）

| 节点 | 时间 | 内容 | 对应交易系统 |
|:-----|:-----|:-----|:------------|
| **早盘计划** | 9:15 | 今日计划：持仓总览 + 每票止损位/买点 + 今日关注（择时状态，读 `knowledge/context/current.md`）| 择时 → 计划 |
| **午间跟踪** | 12:00 | 上午表现：涨跌汇总 / 是否触发止损 / 计划是否需要更新 | 应对 → 跟踪 |
| **尾盘建议** | 14:50 | 当日建议：逐票建议（R66 止损硬判定 / R81 仓位）+ 明日关注 + 复盘提醒 | 应对 → 收队 |
| **真止损异动**（兜底）| 随时（可配间隔）| 现价跌破止损位 → 立即推「已跌破你的止损位 X，按纪律该清仓」（R66）| 只输一根K线 |

### 3.2 内容生成（两阶段）

- **阶段一（先做）**：模板 + 数据注入——确定、快、便宜。数据全来自已有组件：`PositionRepository`（持仓/止损/买点）+ `MarketDataSource`（行情）+ `TradingRuleEngine`（R66/R81 判定）。
- **阶段二（后续）**：LLM 自然语言生成（阿呆口吻，无第三视角）。

### 3.3 推送渠道插件化

```
PushChannel（接口，新）
   ├─ FeedChannel    默认：落盘 → App 内 Feed（现状延续）
   └─ WeChatChannel  新：Server酱 HTTP POST → 微信服务号推送（不打开也收到）
```

- **Server酱（难度低）**：扫码绑定微信拿 SendKey → 一次 HTTP POST → 微信收到。个人自用免费额度够。比 FCM/APNs（要改 App + 注册推送服务）简单一个量级。
- 微信渠道是**第一个外部渠道插件**——后续可加邮件/企业微信 webhook/钉钉，不动主流程。
- 配置：`adai.push.wechat.sendkey`（env `ADAI_WECHAT_SENDKEY`），未配置时该渠道跳过（Feed 不受影响）。

### 3.4 轮询频率调整

- 三节点 = 三条 cron（`@Scheduled(cron=...)`，机制已有）：`0 15 9 * * MON-FRI` / `0 0 12 * * MON-FRI` / `0 50 14 * * MON-FRI`。
- 真止损异动保留独立轮询（可配间隔，默认 15 分钟交易时段；原 30 分钟 poll-cron 语义不变或调整）。
- 不再需要高频轮询——用户节奏是"早盘 + 快收盘 + 最多中午一个"。

## 四、技术落点（全部在现有地基上）

| 组件 | 现状 | 本次动作 |
|:-----|:-----|:---------|
| `@Scheduled` cron | 已有（MarketAlertService.poll）| 新增三条时段 cron |
| `MarketDataSource` | 接口已抽象（G-1）| 直接复用 |
| `TradingRuleEngine` | G-3 引擎（R66/R81）| 时段服务调用判定 |
| `Position.stopLossPrice` | 字段已有（RFC 20260816）| 计划/跟踪/建议注入 |
| `MarketAlertService` | 真止损已接入（A 闭环）| 保留为兜底，改渠道走 PushChannel |
| `PushChannel` | 无 | 新建接口 + Feed/WeChat 两实现 |

## 五、边界

- **建议是输出不是执行**：时段推送给计划/建议，交易动作永远人决策。
- **无第三视角**：推送文案是「阿呆跟你说」，无系统标签（boundaries B1）。
- **隐私**：微信渠道推送持仓/止损信息到用户自己的微信——内容含持仓数字，推给自己可控；如担心第三方可见（Server酱中转），可先推脱敏摘要（只标名+触发点，不推市值/数量）。
- **LLM 生成是阶段二**：阶段一模板先跑通，避免推送链路依赖 LLM 稳定性。
- **未配置微信渠道**：静默降级为仅 Feed，不报错。
