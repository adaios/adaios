# 完美买点案例库——从案例积累到判定当下

> **方向 RFC**：用户长期积累了大量「完美买点」真实案例（通达信画面：K 线 + 默认/自定义指标）。现状买点判定是规则阈值（B1/B2 参数），**没有画面、没有案例参照**——REVIEW S7 的病根（D3 自称「完美图匹配度」实际是硬编码分数映射，无样本库）。本 RFC 定义：把用户的完美案例沉淀为**结构化案例库**（手段），最终产出**判定当下**——任何标的新出现买点形态时，与案例库做归一化相似度匹配，输出「与库中 N 个历史完美买点相似 X%」的参考信号（目的）。
>
> **核心命题**：AI 理解「什么是完美买点」不能靠干巴巴的阈值，要靠**真实案例的画面 + 数据上下文**。案例是认知沉淀，判定是价值产出。

---

## 一、背景与问题

| # | 现状 | 问题 |
|:-:|:-----|:-----|
| A | 买点判定 = 参数阈值（回调 0.5/缩量 0.7/KDJ<13/放量 1.5/前高 20 日，第三阶段已可配）| 阈值是**无画面的概念**——「回调一半」到底长什么样，AI 没有画面参照 |
| B | REVIEW S7：打分自称「完美图匹配度」，实际是规则阈值 + 硬编码分数映射 | **无完美图样本库、无归一化相似度**——「完美」没有数据支撑 |
| C | 用户手里有大量完美买点案例（通达信画面 + 日期 + 直觉）| 这些资产**没有消化通道**——说了就丢，AI 无法学习 |
| D | 已有 K 线能力：日 K 拉取（腾讯主源，上限 320 根）、KDJ 计算、买点扫描框架（15:10）| 技术底座足够支撑案例库，缺的是**案例模型 + 特征提取 + 相似度引擎 + 画图** |

**用户洞察（2026-08-30 原话）**：没有数据范围、没有画面，很多概念无法更好地理解。→ 结论：AI 理解概念靠**数据精度 + 画面还原**，两者系统都要给。

## 二、目标与核心价值

```
完美买点案例库 = 认知沉淀（手段）
      ↓ 长期积累
判定当下 = 相似度匹配输出（目的，核心价值）
```

1. **案例积累**：用户一句话标注（日期 + 标的 + 买点类型 + 可选描述）→ 系统自动拉前 60 + 后 30 日 K → 计算特征画像 → 存结构化案例 + 生成 K 线图还原画面
2. **案例理解**：LLM 消化每个案例 → 结构化「为什么完美」→ 积累 20-50 个后自动归纳共同特征 → 对照/修正 B1-B2 参数
3. **★ 判定当下（核心价值）**：每日对自选股/持仓扫描 → 计算当前形态特征向量 → 与案例库归一化相似度匹配 → 输出「此形态与库中 N 个完美买点相似 X%，参照案例后验 +5 日均涨 Y%」
4. **双轨判定**：规则引擎（B1/B2 参数，确定性基线）与案例相似度（教科书形态识别，经验增强）叠加输出，各自独立降级——不互相阻塞

## 四、完整链路（四环）

```
环 1  案例标注（你，一句话）
      「2026-08-03 000725 B1 完美入场」+ 可选「为什么完美」
      （截图可作辅助素材，非必需）
        ↓
环 2  案例数据化（系统自动）
      拉 前60+后30 日 K → 重算指标（KDJ/MACD/MA/量比/回撤位置/黄白线态）→
      特征画像 → 存 data/{userId}/trading/cases/ + 生成 K 线图
        ↓
环 3  案例理解（LLM）
      读案例画像 + 数据 → 输出「为什么这是完美买点」结构化理解 →
      沉淀到 20-50 个后自动归纳共同特征 → 对照/修正 B1-B2 参数
        ↓
环 4  ★ 判定当下（核心价值）
      每日对自选股/持仓扫描 → 算当前形态特征向量 → 与案例库归一化相似度匹配 →
      输出「此形态与库中 N 个完美买点相似 X%，参照案例后验 +5 日均涨 Y%」
```

**信任起点**：先做环 1-2 最小闭环——用户标注一个案例，系统还原出 K 线图 + 特征画像，验证「画面还原」的真实度，再进入环 3-4。

## 五、案例数据模型

### 5.1 存储

```
data/{userId}/trading/cases/
├── 2026-08-03_000725.yaml     # 案例真相源（结构化，File First B2）
├── 2026-08-03_000725.png      # K 线图还原（主图 MA + 副图 KDJ/量能 + 买点标记）
└── _index.yaml                # 案例清单（可检索）
```

### 5.2 案例文件格式（草案）

```yaml
# data/{userId}/trading/cases/2026-08-03_000725.yaml
formatVersion: 1
case:
  id: "2026-08-03_000725"
  symbol: "000725"
  name: "京东方A"
  buyDate: "2026-08-03"
  buyType: "B1"            # B1/B2/B3/SB1/自定义——由用户标注，未标注时系统按特征推测
  description: "回踩 60 日线 + 地量，次日大阳启动"   # 用户可选
  labeledBy: "adai"
  window:
    beforeDays: 60
    afterDays: 30
  data:                     # 快照引用（K 线数据本体不入库，只存引用 + 特征）
    klineRef: "kline/000725_daily.json"   # 或按需拉取（腾讯主源可重放）
features:                   # 买点日特征画像（全部标准化相对值，跨标的可比）
  drawdownFromHighPct: 52.3       # 距前高回撤 %
  volumeShrinkRatio: 0.62         # 量比（3 日均/5 日均）
  kdjJ: 8.4                       # KDJ.J 值
  kdjGoldenCross: true
  maRelation: "close_above_ma20_below_ma60"
  macdHist: -0.31                 # MACD 柱
  macdCrossUp: true
  yellowLineState: "price_near_yellow"   # 黄白线态（自定义指标近似）
  whiteAboveYellow: false
  distanceToMa60Pct: 1.8           # 距 60 日线 %（黄线近似）
  sidewaysDays: 5                 # 盘整天数
  breakoutFromHigh: false
verify:                     # 后验窗口（完美买点必须事后可验证）
  +5dReturnPct: 18.2
  +10dReturnPct: 24.5
  maxDrawdownAfterBuyPct: -2.1
  stopLossHit: false
aiInsight:                  # 环 3 LLM 理解产物
  summary: "缩量回踩 60 日线（黄线）获得支撑，KDJ 低位金叉，次日放量启动——教科书式 B1"
  keyFeatures: [缩量, 黄线支撑, KDJ低位金叉, 次日放量]
  confidence: 0.9
```

### 5.3 特征字典（标准事实，全部归一化到相对值）

> 设计要点：特征**只引用标准事实字典**（价格/量/指标数值，不引用用户私有数据）——与规则包同一原则，保证跨标的、未来跨用户可比。

| 类别 | 特征 | 说明 |
|:-----|:-----|:-----|
| 形态 | 距前高回撤 % / 距 60 日线 % / 盘整天数 / 是否破前高 | 位置类，B1/B2 参照系 |
| 量能 | 量比（3 日/5 日均量）、缩量/放量标记 | 缩量洗盘 vs 放量突破 |
| 指标 | KDJ.J / KDJ 金叉 / MACD 柱 / MACD 金叉 / MA 关系 | 后端全部可从 OHLCV 重算 |
| 自定义 | 黄线位置（≈长均线）/ 白线-黄线关系（开门/关门态）| 第一版语义近似，公式后补 |
| 后验 | +5/+10 日收益、买入后最大回撤、是否破止损 | 完美与否的客观证据 |

## 六、判定引擎设计（环 4）

### 6.1 判定流程

```
每日 15:10（复用现有买点扫描框架）或按需查询：
  候选标的 → 拉 60 日 K → 算当前特征向量（同案例画像，缺 buyDate 用最近一日）
         → 与案例库归一化相似度匹配（特征 min-max 归一化 + 欧氏/余弦距离）
         → 输出：
           - 相似案例 Top N（案例 ID + 相似度 % + 后验结果）
           - 综合建议：相似度 ≥ 阈值 → 「形态与库中完美买点相似，参照后验 +5 日均涨 Y%」
           - 无案例库 / 无命中 → 静默降级（不影响现有规则判定）
```

### 6.2 双轨叠加

| 轨道 | 输入 | 输出 | 降级 |
|:-----|:-----|:-----|:-----|
| 规则引擎（现有）| B1/B2 参数 + K 线 | 命中/未命中 + 分数 | 已有，独立 |
| 案例相似度（新增）| 特征向量 + 案例库 | 相似度 % + 参照案例 | 案例库空 → 不输出 |

> 两轨独立判定、独立降级；输出端合并展示。**案例相似度是「经验增强」，不覆盖规则硬判定**（止损/仓位等确定性判定仍以规则为准）。

### 6.3 特征归一化

- 每个特征定义 min-max 边界（如回撤 0-100%、量比 0-3、KDJ.J 0-100）——归一化到 0-1，保证不同标的可比
- 距离度量：欧氏距离为主，余弦相似度为辅（形态方向敏感时用）
- 相似度阈值：第一版先输出 Top N + 分数，阈值由用户观察后拍板（避免过早拍死）

## 七、自定义指标还原策略（三态）

| 状态 | 做法 | 触发 |
|:-----|:-----|:-----|
| **语义近似（第一版）** | 黄线 ≈ 可调长均线（默认接近 60 日，参数可配）；白线 ≈ 短均线；洗盘短线 ≈ 缩量 + 长下影；转型图（砖形图）≈ 趋势分段 | 现在就能做，让案例画面先立起来 |
| **公式精确** | 用户提供通达信公式源码 → 转写为 Java 指标计算（公式语言可翻译）| 用户提供后，替换近似实现 |
| **校验** | 精确实现后，对历史案例重算对比（画面一致才算数）| 公式落地批 |

> 课程语义依据（2026-08-30 核实 `os/trading-engine/01-raw/2025-10-04_国庆课程.md`）：黄线 = 主力成本线/盈亏线（「接近于 60 日线但非 60 日线」）；白线在黄线之上 = 「开门」买入区间，之下 = 「关门」。这些语义已入库，是近似实现的依据。
