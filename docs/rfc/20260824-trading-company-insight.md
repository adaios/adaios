# 公司透视——上市公司客观画像 + 红黄绿排除判定（查公司）

> **方向（用户 2026-08-24 确认）**：trading 插件新增「查公司」能力——输入代码/名称，产出基于**可查证公开事实**的客观画像 + 结构化判定（风险清单/资金信号/关注点），帮用户排除大部分不值得研究的公司。
> **流程**：先写本文档（draft），审查确认后开工（代码 + 数据文件新增登记）。

---

## 一、问题与现状

1. **选股维度恒缺失**：清仓复盘「三维打分」实为二维（REVIEW S7），选股维度恒 null——查公司画像正是选股维度的素材底座。
2. **`/trading/lookup` 只能查名**：现有端点仅「代码 ↔ 名称」，查不到任何公司基本面/风险信息。
3. **建议引擎无公司级上下文**：`/trading/advice` 注入持仓+行情+规则，但不知道持仓公司「是什么公司、有没有雷、控股方是谁」——建议是纯量价视角。
4. **用户现状**：查公司要靠外部 App（东财/同花顺），信息分散、带营销噪音、无法沉淀进个人知识库。

---

## 二、目标

1. **单点查公司**：`GET /trading/company/{symbol}` 产出九维度客观画像 + 结构化判定，一次看清「能不能碰」
2. **喂建议引擎**：`/trading/advice` 注入持仓公司画像摘要（riskLevel + 硬排除原因 + 财务一句话 + 解禁/质押风险），建议带上基本面/风险维度
3. **财报季感知**：财务维度随当前报告期自动切换（当前 8 月 = 中报季，优先最新中报），未披露显示交易所预约披露日
4. **排除法价值**：红黄绿三档判定——硬排除（红）/警示（黄）/可研究（绿），批量筛查（v1.5）让持仓/自选/候选池一次性瘦身

## 三、方案

### 3.1 端点与画像结构

`GET /trading/company/{symbol}`（trading 插件门控，与其余端点一致；symbol 支持代码或名称，名称走 `/trading/lookup` 反查）

画像结构（九维度，每维度带**数据日期 + 来源**，判定优先）：

| # | 维度 | 内容 | 来源 | 刷新 |
|:--|:--|:--|:--|:--|
| 1 | 背景 | 主营/成立/上市日/注册资本/员工 | 东财 F10 概况 | 7 天 |
| 2 | 行业定位 | 行业 + 市值排名 + PE/PB 及行业分位 | 东财行业板块 + 行情 | 7 天 |
| 3 | 产业链 | 上游/下游/竞争对手（**标注「基于公开资料的归纳，可能不准」**）| LLM 归纳 + 人工修正 | 月度 |
| 4 | 概念归属 | 所属概念（**客观事实**，不做热度炒作）| 东财概念板块 | 1 天 |
| 5 | **财务质量（核心）** | ROE/净利率/负债率/经营现金流/商誉占比 + 业绩预告/快报 + 报告期标签 | 东财财报 API | **报告期感知** |
| 6 | 股权结构 | 实控人/控股方/股东性质（国资/民营/外资）/十大股东+流通股东/大资金持仓（公募/社保/保险/QFII/北向）/股权质押/股东户数变化 | 东财 F10 股东 | 季度（北向日更）|
| 7 | 黑历史 | 处罚/问询函/立案/减持/商誉减值/ST 风险（**只列可查证公告事实，带状态+来源级别**）| 巨潮/交易所公告 | 1 天（事件驱动）|
| 8 | 解禁日历 | 未来 3-6 个月限售解禁 + 在途减持计划（**前瞻**，标注「计划可变化」）| 官方公告 | 1 天 |
| 9 | 持仓联动 | 「你持有 N 股 @ 成本 X，当前盈亏 Y」（本地数据，无则省略）| 本地持仓 | 实时 |

**明确不做**（客观原则红线）：传闻、舆情、新闻催化、题材热度炒作、龙虎榜交易席位——一切不可证伪或基于交易的来源不碰。

### 3.2 数据源（免费公开接口，复用行情熔断/兜底模式）

| 数据 | 接口 | 说明 |
|:--|:--|:--|
| F10 概况/股东/质押 | 东财 f10.eastmoney.com | 结构化，可靠性高 |
| 财务指标/业绩预告/快报 | 东财 datacenter-web 财报接口 | 带报告期 |
| 概念归属 | 东财概念板块 | 只取归属事实 |
| 公告/问询/立案/减持/解禁 | 巨潮资讯 cninfo 公告检索（官方源）| 黑历史/解禁的真相源 |
| 预约披露日 | 沪深交易所 | 财报季感知的前瞻输入 |
| PE/PB/市值 | 行情接口（已有腾讯主源/东财兜底）| 复用 |

**技术要点**：数据源层完全复用 `KlineService` 的主源/兜底/熔断/缓存模式，不新造轮子；任一源失败 → 该维度降级（标注「数据暂缺」），不整报告失败。

### 3.3 财报季感知（中报季优先）

1. **报告期标签铁律**：每个财务数字必须带 `(报告期, 披露日)`——如 `2026H1 中报（8/20 披露）`；同比对上年同期、环比对上一报告期，**严禁跨口径比较**
2. **自动感知**：当前日期 ∈ 中报季（7-8 月）→ 财报区置顶最新中报；年报季（1-4 月）→ 年报+一季报；三季报季（10 月）→ 三季报
3. **未披露前瞻**：报告期未出 → 显示交易所预约披露日 + 倒计时——「预约 8/31 披露、暂未出」本身是判定输入
4. **当前时刻（2026-08）**：中报披露高峰，财务维度信息量最大——首版上线即服务此场景

### 3.4 判定（结构化规则，LLM 零事实生产权）

**红黄绿三档（排除法）**：

| 档 | 条件（任一即触发） | 含义 |
|:--|:--|:--|
| 🔴 硬排除 | 立案调查中 / ST·退市风险 / 商誉占比>30% / 质押>50% 且股价接近平仓线 / 问询进行中 | 不碰 |
| 🟡 警示 | 单一问询（已结）/ 减持计划在途 / 未来 3-6 月解禁高峰 / 中报预亏·业绩预警 / 质押 30-50% / 商誉 10-30% | 研究成本高，需理由 |
| 🟢 可研究 | 以上均无 | 值得花时间 |

**财务质量分**（0-100，五指标规则打分，商誉占比>30% 直接不及格）——只做客观事实映射，不是选股推荐。

**资金信号**（全部为可查证披露事实）：大资金新进十大股东（社保/知名基金/QFII）、股东户数减少=筹码集中、控股方变更、质押比例下降。

**关注点**：映射现有 **R21-R32 选股规则**（每条关注点引用规则号，衔接知识底座，不另起一套）。

**买入前必须回答的 3 个问题**（决策清单，不是买卖指令，与模块「建议只输出不执行」定位一致）：由画像自动生成，如「中报预亏的这家，题材兑现前业绩雷风险能否承受？」「解禁高峰在 3 个月后，持有周期是否覆盖？」「质押 48%，股价再跌 15% 触平仓线，你的止损位是否在其上方？」

**边界**：红黄绿只回答「哪些不能碰」，不回答「哪些该买」——排除法不是选股法。

### 3.5 缓存与知识沉淀（File First）

- 画像缓存：`data/{userId}/trading/companies/{symbol}.json`（公开市场数据，无隐私问题，但属用户数据目录）
- 知识沉淀：画像 markdown 写入 `os/trading-engine/knowledge/companies/{symbol}.md`（公开数据可进 git；不含持仓联动等个人数据——持仓联动只在 JSON 缓存层，不沉淀）
- 成本纪律：结构化数据本地模板渲染为主，LLM 只做产业链归纳 + 关注点提炼，按 symbol 缓存复用

### 3.6 建议引擎注入

`/trading/advice` 的 LLM 上下文注入持仓公司画像摘要（riskLevel + 硬排除原因 + 财务一句话 + 解禁/质押风险，每公司 1-2 行）——**不改变现有「硬判定覆盖 LLM」机制**，画像摘要是事实输入不是建议来源。

### 3.7 批量筛查（v1.5，承载排除价值）

`POST /trading/company/screen`：输入 symbol 列表 → 每只输出红黄绿 + 排除原因表。用于持仓/自选/候选池批量跑，一张表看完全池「哪些不能碰」。**v1 不做**（先验证单点画像质量与数据源可靠性），列为紧接 v1 的下一步。

### 3.8 前端入口

- **v1**：web 查公司入口（输入代码 → 画像卡片：九区块 + 红黄绿判定区）
- **v2**：app 端查公司入口 + 批量筛查视图（web 先行，与现有「详细管理去电脑端」分工一致）

## 四、边界与风险

| # | 项 | 说明 |
|:--|:--|:--|
| 1 | 客观原则红线 | 不做消息面/传闻/舆情/题材热度炒作；黑历史只列可查证公告事实（带状态：立案调查中 > 问询进行中 > 已结案 > 已解决），LLM 不演绎 |
| 2 | 股东数据滞后 | 季度披露（季报后 1-3 个月公布），**永远滞后**——显著标注「数据截至 X 季度报告期」，定位是判断长线持有/控股结构，不追短线 |
| 3 | 解禁/减持是计划 | 官方披露但可中途终止/变更，标注「计划可变化」 |
| 4 | 数据源稳定性 | 公开接口易变/限流 → 复用 KlineService 熔断/兜底/缓存；失败降级不整报失败 |
| 5 | 判定边界 | 排除法不是选股法；判定是提示不是指令 |
| 6 | 阈值先定死 | 商誉 30%/质押 50% 等阈值 v1 硬编码，后续加配置入口（吸取买点参数无配置的教训，P2-交易17） |
| 7 | 成本 | LLM 只排版+归纳；结构化模板为主；缓存复用；批量筛查按需触发避免高频外呼 |
| 8 | 数据隐私 | 画像 JSON 在 `data/`（gitignore）；沉淀 markdown 脱敏（不含持仓/盈亏个人数据）|

## 六、验收要点

1. 查任意代码 → 九维度齐全（数据源失败维度明确标注「数据暂缺」，不整报失败）
2. 中报季（当前）财务维度置顶最新中报，带 `(报告期, 披露日)` 标签；未披露显示预约日倒计时
3. 红黄绿判定可复现：立案/ST/高商誉/高质押 → 🔴；单一警示 → 🟡；干净 → 🟢
4. `/trading/advice` 建议含公司画像摘要，硬判定机制不被破坏（回归测试）
5. 黑历史条目全部带来源 + 日期 + 状态，无 LLM 演绎内容
