# learn 表征适配与链路打通

> **触发来源**：2026-09-16/17 五轮产品讨论（沉淀见 `../ideas/20260916-plugin-and-cold-start-discussion.md`）。
> 用户的原始判断：「**一键分享给阿呆，每次分享，阿呆就会用一个更好的方式、结合用户习惯的方式，展示给用户**」
> 「一个内容，老师讲解……**不是每个学生都会有好接收、消化**，但阿呆可以基于对你的了解，以你喜欢的方式展示」
> 「**主要是把链路打通**」。
>
> **三条拍板（2026-09-17）**：① 门控选 **B**（接收基础能力 / 整理插件能力）；② **不做收藏夹导入**，只允许单个导入（配额控风险）；③ 落 RFC + 开工。
>
> **实施边界**：本 RFC 获批后开工（用户授权自主推进，**不部署、不 push**）。

**三句核心判断**（决定方案形态）：

1. **精美决定他会不会点开第二次，表征决定他会不会留下来，只有「这是我的」决定他会不会离开。**
2. **精美必须是"一次性的"**：生成时把页序列存下来，之后打开/导出/分享全是**渲染，不再烧钱**。（`LearnQuota` 的存在说明这个矛盾已经现实存在。）
3. **重生成可以多次，但要"次数有感"且由反馈驱动**——无限免费重抽 = 从协作退化成老虎机。

## 三、门控拆分 B（本批前置）

### 3.1 语义

> **「接收」是基础能力（人人可用，永不失败）；「整理」是插件能力（受控开放，会花钱）。**

符合已确立的尺子：**通用需求 → 基础能力；垂直需求 → 插件**。同时**不违背** `RFC 20260916` 的「新用户插件都不开」。

### 3.2 行为

| 场景 | 现在 | 改后 |
|:-----|:-----|:-----|
| 有 learn 插件 | 正常消化 | **不变** |
| **无 learn 插件** | 403 拒绝 | **落一条记录**（不调 AI、不烧钱）+ 返回人话提示「已经帮你记下了；开启「学习」后，我可以把它整理成卡片」 |
| 参数非法（url/content 皆空） | 400 | **仍 400**（校验提到门控之前） |

### 3.3 实现要点

- 改动点：`LearnController.doDigest`（`:105`）——**先校验、后判插件**；无插件走新增的降级分支；
- 降级落盘：`RecordRepository.save(userId, ContentRecord)`，`type=note`、`source=external_import`、`title` 取 URL 或正文首段（截断）、`content` 存原文，**不调 `RecordFlowAppService`**（那会触发 AI 理解，等于绕过门控花钱）；
- 返回：新增 status 值 `recorded`（沿用 `Map.of("status", …, "message", …)` 的既有人话风格）；
- **真正的花钱动作**（抓取 / 转写 / LLM 卡片化）**仍全部门控**。

### 3.4 前端适配（必要）

现前端把 403 当错误展示；改后要能识别 `status=recorded` 并展示"已记下 + 可开启学习"的提示。**双端分享投递与学习页均需适配**（标注：真机未验证）。

## 四、2a 偏好回流（最小改动、最大杠杆）

**做法**：`digest` 组装 prompt 时，把现有记忆资产拼进 user prompt。

```
LearnDigestAppService.digest(userId, …)
  ├─ 现有：existingTopics(userId)
  └─ 新增：preferencesText(userId) + patternsText(userId)
             ↑ memoryService.findAllPreferences / findAllPatterns
       ↓
     buildDigestPrompt(..., existingTopics, userPrefs, userPatterns)
```

**约束**：

- **prompt 长度预算**：偏好/模式各取 **Top N（建议 ≤5，按 confidence 降序）**，只取 `content` 文本，避免 token 膨胀（`estimateTokens` 已存在）；
- **空偏好时零影响**（新用户 → 行为与今天完全一致）；
- **不得泄露隐私到日志**（只记条数，不记内容）；
- 措辞要求「**据此组织表达方式**」，而非"复述用户偏好"——避免卡片里出现"你是个喜欢 X 的人"这类冒犯性表达。

**验收**：同一素材，两个偏好不同的账号 → 生成产物**可辨识地不同**（表述结构/侧重）。

## 五、2b 反馈入口（后端部分）

**做法**：新增写反馈的通道，把用户对产物的评价沉淀为 `MemoryPreference`。

- 载体：`preference` 落在 memory 上（`MemoryPreference(content, confidence)` 已有）。**当前 `findAllPreferences` 是只读聚合**（从既有 memory 聚合），所以需要一个"写一条含 preference 的 memory"的路径；
- 输入：自然语言短句（「太啰嗦」「这样好」）或预设按钮；
- **闭环要快**：反馈后应能触发一次重排（复用既有 `repages`），让用户**当场看到变化**——慢或没变化会产生习得性无助（"说了也没用"）；
- 幂等/去重：同一用户的同类反馈不无限累积（避免 preference 被单句刷爆）。

**边界**：**不做"让用户写 prompt"**——那等于把最费力的一步推回用户（learn B 形态的死因）。

| V7 | 全量测试零失败；`guard-meta` PASS | `./gradlew test` + guard |

## 七、边界与非目标

- ❌ **不做收藏夹批量导入**（2026-09-17 拍板）——风险不在代码，在登录态/风控（`REVIEW P2-learn28` 已踩过 412/429）；保持**单条导入**，配额沿用 `LearnQuota`；
- ❌ **不做"让用户写 prompt"**（见 §五）；
- ⏳ **演示模式（横向翻页）暂缓**——它的价值取决于分享场景是否成立，先打通链路；
- ⏳ **收藏夹/知识库的"意外感"出口（4a/4b）**排在链路打通之后——**没有它，前几阶段就是在养仓鼠**（把收藏夹的病搬到阿呆）；
- ⚠️ **门控不旁路**：降级只放行"接收"，不得顺带放行抓取/转写/LLM 任何一环。
