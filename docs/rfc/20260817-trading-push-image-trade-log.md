# 交易推送体验 + 图片对话流 + 交易日志自动归集

> 本批三项，均来自用户 iPhone 实机反馈（2026-08-17）：
> 1. **交易推送**分不清类型、样式不清晰、无法关闭
> 2. **图片对话卡**刷新后格式丢失（图片不再跟随对话流）
> 3. **交易日志**希望截图/文字自动归集为当日交易日志（审核后落库）

---

## 一、问题与现状（实测证据）

### P1 交易推送
- 后端 push 类型已有 title 映射（早盘计划/午间跟踪/尾盘建议/买点提醒/止损预警/单日大跌/放飞提示），但 **app 端 `FeedCardType.push` 无专属渲染分支**——落到普通记录卡样式，所有推送长得一样，分不清类型
- 推送内容是 LLM 自由生成的一大段文字，非「总结 + 持仓 + 建议」结构化
- **无推送开关**：后台定时任务自动注入 Feed，用户无法关闭任何类型（含大盘行情条）

### P2 图片对话卡格式丢失
- 聊天时：图片作为首轮上下文渲染在对话流顶部，问/答气泡成对跟随滚动（格式存在）
- 刷新/重开：Feed 重新组装为「图片记录卡」——turns 渲染在卡内、图片缩略图固定，图片不再跟随文字滚动，看起来「居中悬着」
- 根因：图片卡刷新后走 `toFeedEntry`（图片记录形态），丢掉了「图片在对话流首轮」的结构身份

### P3 交易日志无自动归集
- 用户发「今日成交截图」或说「我清仓了XX」，目前只是普通记录，**不进入交易模块**
- 无去重、无汇总、无收盘确认、无审核落库流程

---

## 二、方案

### 2.1 交易推送（P1）

| 子项 | 方案 |
|:-----|:-----|
| 专属样式 | `push` 卡独立渲染：顶部类型徽章（早盘计划/午间跟踪/尾盘建议/买点提醒/止损预警/单日大跌/放飞提示，各配色）+ 内容结构化排版 |
| 内容模板化 | 推送内容改为结构化输出：**总结一行 + 每只持仓一行（名称/现价/涨跌/建议）+ 建议高亮**；LLM 降级模板同样结构化 |
| 推送开关 | per-user 推送类型开关（存账号数据或独立配置文件）：早盘/午间/尾盘/买点/止损/大跌/行情条，逐项可关；关闭后定时任务跳过该用户该类型 |
| 交互 | app：**左滑 = 删除单条推送**；**右滑 = 弹出该类推送开关**（或进设置）；web：设置入口在交易页 |

### 2.2 图片对话卡（P2）

| 子项 | 方案 |
|:-----|:-----|
| 结构保留 | 图片对话卡（image_qa）持久化时保留「图片 = 对话流首轮上下文」结构；刷新后仍渲染为对话流形态 |
| 渲染统一 | app/web 图片对话卡统一：图片缩略图在对话流开头，问/答气泡成对跟随滚动；点图片可看原图 |

### 2.3 交易日志自动归集（P3）

三步流水线，**仅交易插件用户触发**（插件门控复用）：

```
用户发截图 / 说「清仓了XX」
   ↓ ① 判定（仅 trading 插件用户）
识别为「疑似当日成交」（截图表格特征 / 文字含 股票+方向）
   ↓ ② 归集汇总（当日，去重）
按 (股票, 方向, 数量近似, 当日) 去重 → 当日交易记录预览
   ↓ ③ 收盘确认（15:05 定时任务）
推送「今日操作汇总：XXX 是否完整？不完整说一声」→ 用户确认/补充
   ↓ ④ 审核落库（用户确认后）
走 recordTrade 同一链路（持仓增减+现金+手续费自动算），不越权写入
```

关键决策：
- **判定**：截图（表格特征明显）或文字（股票代码/名称 + 买/卖 + 数量）都算；纯闲聊不触发
- **去重**：同 (股票+方向+当日+数量近似) 只算一笔
- **审核**：阿呆只归集不落库，用户确认/补充后才写交易模块（建议引擎哲学一致）
- **不完整引导**：只有标的无数量 → 标记不完整 → 收盘确认时引导去交易模块补全

## 三、涉及面

| 层 | 改动 |
|:---|:-----|
| 后端 | 推送模板结构化 + per-user 推送开关（MarketPushRepository/账号配置）+ 交易日志归集服务（识别/去重/汇总/收盘确认）+ 图片对话卡结构保留 |
| app | push 卡样式 + 左滑删/右滑开关 + 图片对话流渲染 + 交易日志确认 UI |
| web | push 卡样式 + 推送设置入口 |
| 文档 | api-spec（新端点）+ REVIEW + checklists 检查点 + change-log + status |

## 四、测试与验收

- 后端：推送开关跳过逻辑、去重逻辑、归集判定（截图/文字/纯闲聊不触发）、确认落库链路、图片 turns 结构保留——各配测试
- 前端：push 卡渲染分支、左滑/右滑交互、图片对话流渲染、交易日志确认 UI——各配测试
- 验收：iPhone 上推送可分类型、可关闭；图片对话刷新后仍为对话流形态；发截图/说清仓 → 收盘确认 → 确认落库
