# 记忆底座质量——原文保真与证据链

> 一句话：**原话在卡片层还在，但 8 月初大量无卡对话的原话从未落盘**（入口即被 `ai_summary` 转述覆盖），记忆又吃不到原话——**诊断经 2026-09-05 失真审计修正**（`docs/review/audits/2026-09-05-memory-fidelity-audit.md`）。本文给诊断、方案与失真审计基线。

## 一、背景

- 2026-09-05 用户选定建设方向「E：记忆底座质量（原话 + 摘要并存，让记忆少失真）」。
- task-log #153（观察）：08 月 `data/adai/records/2026/08/` 158 条记录中 **conversation 140 条、note 仅 9 条**（<6%）——直接原话 note 极少，绝大多数经对话产生。
- 关联：P2-用户3「交易帮不到忙」同源问题——阿呆对用户的理解若建立在转述之上，建议与复盘自然"隔一层"。

## 二、现状实测（2026-09-05 只读核查）

### 2.1 三层存储与真相源

| 层 | 位置 | 内容 | 是谁的原话？ |
|:--|:--|:--|:--|
| **卡片层** | `records/cards/{yyyy}/{MM}/{dd}/card_{id}.md` | 对话流 turns（`用户：{原话}` + AI 回复）| ✅ **原话** |
| **记录层** | `records/{yyyy}/{MM}/{id}.md` | 扁平记录：note 正文 = 原话；**conversation 正文 = `source: ai_summary` 的一句话转述**（如"询问《三体》可读性评价"）；summary 字段 = AI 单行化 | ⚠️ note 是原话；conversation 是**转述** |
| **记忆层** | `memory/{yyyy}/{MM}.md` | 条目正文 = AI 提炼洞察；frontmatter 有 `recordId` + `cardId`（08-14 已补 cardId 锚点）但**无原文摘句** | ❌ AI 提炼（二次/三次转述）|

### 2.2 关键代码路径（提炼/回读的取料）

- 问答沉淀：`QuestionAppService` → `Memory.fromUnderstanding(record.id(), cardId, understanding)`——memory 正文来自 AI 对**本次对话**的理解（有原话参与），但落盘不带原文摘句。
- 记录沉淀：`RecordFlowAppService` / `RecordRetryService`（跨日重补）→ 基于 `record.content()`——**重补路径吃的是记录层转述**。
- 图片沉淀：`MediaRecordAppService` → `Memory.fromImageRecord`（摘要提炼）。
- 回读方：`BriefAppService`（简报注入 `memoryService.recent(7)`）、ContextEngine 记忆注入、复盘/建议知识注入——吃的都是记忆层提炼文本，**无人翻卡片原话复核**。

### 2.3 失真链（2026-09-05 审计修正）

```
你的原话 ──(有卡对话)──▶ 卡片 turns ✅ 原话
    │
    └──(无卡对话：8 月初主体)──▶ ❌ 原话从未落盘，records 正文 = ai_summary 转述（终态）
                                      └─ AI 提炼 ──▶ 记忆层（正文无原文证据，cardId 缺失） ← 阿呆"回忆你"吃这里
```

失真风险点：① **无卡对话原话在入口即被转述覆盖**（8/2-8/3 主体场景，审计证实）；② 转述本身丢细节/改语气/加料（抽样加料过半——"今天星期几呢"被记成"依赖外部确认时间感知的习惯"，奶茶分享被套进"频繁核查时间"归因）；③ 记忆正文模板化套话（"延续了…/反映出…/焦虑感"句式滥用）；④ kind 失衡（decision 74%、fact 错标）与同因记忆 20+ 条轰炸；⑤ 卡片被归档后记忆无从核验原话。

## 三、目标与非目标

- **目标**：阿呆的记忆可溯源到原话；提炼与回读优先用原话而非转述；失真可量化、可改进。
- **非目标**：不推翻展示层形态（Feed/时间线仍以摘要/卡片呈现——B1 第一原则与阅读体感优先）；不做全量历史重写（动存量风险大，留 v1.0.1）。

## 四、方案（三档，可叠加）

### E-A 写侧保真（审计后新增，**最高优先**——其余方案的前置）

无卡对话（或任何对话）的**用户原句必须落盘**：records conversation 正文保留原话，AI 转述降为独立字段/摘要，或正文 = 原话 + `aiSummary` 并存。

- 现状：8 月初大量无卡对话正文 = `source: ai_summary` 转述（终态），原话从未存在 → E-A 读侧/E-B 全空转（审计 §四 结论 2）。
- 做法：`QuestionAppService` 等入口侧——records 落盘改存原问原文（content = 原话），转述进 summary；存量无卡转述记录**不可恢复**（原话已丢），仅新数据受益（或卡片续接对话已天然保真）。
- 影响面：records 格式字段语义（freeze §2.1 判定 MINOR/MAJOR）+ Feed/时间线展示口径（展示用 summary 还是 content？）+ 旧数据回填无源。
- 拍板点见 §六 P4。

### E-A2 读取侧保真（原 E-A，依赖写侧保真后才有料）

回读/提炼场景**有原话先吃原话**：

| 接入点 | 做法 |
|:--|:--|
| 记忆提炼（question 沉淀、跨日重补 `RecordRetryService`）| 提炼 prompt 注入 `cardId` 对应的原话 turns（或原文摘句）作为主料，记录转述降级为旁证 |
| 简报 / 记忆注入（Brief、ContextEngine）| 记忆条目命中时若有 cardId，附原话摘句上下文（注：不改变展示文案，只丰富 AI 内部理解）|
| 复盘/建议（交易）| 行为标注与"当时阿呆说过什么"的对照，翻卡片/记忆原话而非转述 |

- 影响面：只改取料/注入侧 + prompt，不动 `data/` 任何格式；**仅对存有原话的场景生效**（卡片对话 + 写侧保真后的新数据）——存量无卡转述记录读侧无料可保（审计 §四 结论 2）。
- 测试：提炼/重补/简报三类取料优先级单测 + prompt 契约回归。

### E-B 记忆 evidence 字段（随批，freeze MINOR 变更）

memory 条目 frontmatter 增加**可选** `evidence:`（原文摘句，1-3 句；降级/无原文可为空）——记忆随取随验，AI 回读时可直接引用"你当时说过：{原话}"。

- 变更登记：`data-format-freeze.md` §2.4 记忆格式 **MINOR**（可选字段，旧条目解析兜底 null，不迁移存量）。
- 写入口径：提炼时从卡片 turns 截取用户原话关键句（≤ 阈值字数），随 `Memory` 对象落盘。
- 展示注意：`evidence` 仅供 AI 内部引用与核验，**不新增用户可见系统标签**（B1）。

### E-C 存量原文化（v1.0.1，依赖 E-A 定字段后只做存量）

存量 conversation 记录迁移为"原话 + `aiSummary`"双字段形态。**关键约束（审计证实）：存量无卡记录的转述正文是唯一存在物，原话已不可恢复**——E-C 只能对"有卡片可回填"的存量生效（卡片仍在的对话反填原话），无卡历史接受原话永久缺失。

- **动冻结格式 + Feed/时间线/标签索引连锁**，需 freeze §2.1 MINOR/MAJOR 判定 + 回填幂等 + 渲染侧回归；不列入本阶段。

## 五、失真审计（✅ 基线已产出 2026-09-05）

基线报告：`docs/review/audits/2026-09-05-memory-fidelity-audit.md`。

- 抽样：8 月 172 条全量结构统计 + 6 条可核验样本对照（fact 无 ≥2 样本——全月仅 1 条且错标；无卡样本只能核转述）。
- 基线结果：**加料 3 / 丢细节 1 / 正确 1 / 无法溯源 1**——可对照样本加料过半；kind 失衡（decision 74%）、同因记忆 20+ 条、cardId 全缺失。
- **复测计划**：写侧保真落地后隔周同法抽 10 条对比，偏差率下降即验证有效；新数据复测以新写入记录为池。

## 六、拍板点

| # | 问题 | 选项 | 备注 |
|:--|:--|:--|:--|
| P1 | evidence 摘句长度上限 | ① 1 句（≤80 字）② 3 句（≤240 字）| 越长越真、占 memory 越大（单月单文件膨胀）|
| P2 | E-C（存量原文化）是否立项 v1.0.1 | ① 立项排期 ② 继续搁置 | 影响 data-format-freeze 主格式；无卡历史原话已丢不可回填 |
| P3 | 审计样本量 | ① 10 条基线（已按可行样本执行 n≈6）② 扩到 20 条 | 成本 vs 置信度 |
| P4 | **写侧保真字段方案（新，最高优先）**| ① conversation 正文 = 原话，`summary` 存转述（展示改 summary）② 正文 = 原话 + `aiSummary` 并存 ③ 仅新入口保留原话不动存量 | 决定 E-A/E-C 字段形态与 freeze 变更级别；②最稳但格式改动最大 |

## 七、推荐路径

1. ✅ **失真审计基线**（2026-09-05 已出，audits/）→ 2. **拍板 P4**（写侧保真字段方案）→ 3. **E-A 写侧保真**（新数据原话落盘，入口侧改动 + freeze 变更登记）→ 4. **E-A2 读取侧保真**（有原话的吃原话）→ 5. **E-B**（evidence 字段，freeze MINOR 登记）→ 6. 复测审计对比 → 7. P2 拍板后决定 E-C（存量）。

## 八、影响面与风险

- 代码：adai-core 入口侧（`QuestionAppService` 等 records 落盘）+ 取料/注入侧 + prompt 模板（B5 知识归 `kernel/context/prompts`）；Feed/时间线展示口径可能受影响（若 P4 选①）；无前端 UI 改动。
- 数据：E-A 起**新写入记录**格式变化（freeze 变更登记）；E-B 仅新条目带可选字段（不迁移存量）；存量不动。
- 风险：旧数据原话永久缺失（接受并如实标注，不伪造回填）；转述仍是 Feed 展示主料（B1 阅读体感）；evidence 过长撑大 memory 单月文件 → P1 拍板上限 + 行数治理阈值预警。

## 九、开放问题

- 记录层 conversation 转述是否继续作为 Feed 展示（是——阅读体感），还是加"展开看原话"交互（产品方向，另行讨论）。
- 交易复盘对照"阿呆当时说过什么"是否与本方向同批（可能属方向 B 反馈闭环，可复用 E-A 的取料改造）。
