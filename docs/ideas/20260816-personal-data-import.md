# 个人数据导入总纲（想法记录，不着急实现）

> **用户原话（2026-08-16）**："数据导入是很重要的入口……包括每月消费账单、体重变化、睡眠时间记录、电动车充电记录、相册（有地点时间）、高德地图记录……一下子丰富起来了。导入的方式也得重新考虑，可能照片是个很好的方式。这些可以先记录，目前不着急扩展。" 以及 "我和 ChatGPT 的聊天记录，我为什么舍不得 ChatGPT——聊了太多了，对我了解太多了。"

## 一、核心洞察：数据导入 = 阿呆的认知入口

- **数据资产优先**（工程原则）：代码会变，数据是长期资产——导入进来的每类数据都是阿呆对"我"的一层认知。
- **数据主权是阿呆与 ChatGPT 的分水岭**：用户舍不得 ChatGPT 是因为大量个人数据（聊天/行为/偏好）沉淀在对方手里。阿呆的价值 = 这些数据**归自己所有**，可分析、可反哺、不流失。
- 从交易数据（已落地：持仓/自选/清仓/资金）推广到**全方位个人数据**——导入是同一个机制，扩展数据源即可。

## 二、数据源清单（用户列举 + 扩展）

| 数据 | 来源 | 导入方式 | 阿呆能分析出什么 |
|:-----|:-----|:---------|:-----------------|
| 证券转出转入 | 券商流水 | 文件/文本 | 资金流向、仓位变化 |
| 详细交易日志 | 券商/通达信 | 文件（已做：清仓/持仓）| 交易行为模式（已做雏形）|

| 睡眠时间 | 手环/手机 | 导出/API | 作息规律、与状态关联 |

## 三、统一导入入口设计（重新考虑）

**原则：一次导入入口，多种数据源**——不按数据源建入口，按「导入方式」建：

```
导入方式（当前已有 + 扩展）：
① 文本/文件粘贴或上传   → 结构化解析（表头定位，交易已做）
② 照片识别（★通用方式） → GLM-VLM 看图 → 结构化（地点/时间/数字 OCR）
   —— 相册、账单拍照、充电记录截图、体重秤照片……一张照片就是一条记录
③ API 接入（后续）      → 高德/手环/DeepSeek 用量
④ 手动记录（最后手段）   → 简单表单
```

**照片作为通用方式的原因**：门槛最低（拍一张就有）、信息密度高（时间地点+内容）、覆盖广（账单/体重/充电/相册都能拍）。GLM-VLM 多模态**已有现成能力**（图片记录已落地），扩展为"识别任意结构化信息"即可。

## 四、与现有机制的衔接

- **交易导入**（2026-08-16 已做）：positions/watchlist/sold/cash 四类 + `imports/save` 通用上传留存 + GBK 转码——是"文件导入"的样板
- **图片理解**（已做）：GLM-VLM 图片→文本，是"照片导入"的地基
- **统一导入框架**（未来）：`ImportChannel`（文件/照片/API/手动）+ 数据源适配器 + 留存（原始文件归档可追溯）

## 五、优先级与节奏

- **当前**：不扩展（用户明确"先记录，不着急"）；交易导入继续完善（Tab 化/账户卡）
- **近期候选**：ChatGPT 聊天记录导入（数据主权回收，情感价值最高）
- **中期**：账单/照片通用导入（照片 OCR 打通后一鱼多吃）
- **远期**：API 类（高德/手环/DeepSeek 用量）

## 六、边界

- 数据主权：所有导入数据存 `data/`（隐私保护），阿呆只读不外包
- 导入需**确认步**（照片识别结果可编辑，防 OCR 错）
- 每类数据独立存储（File First），不强行统一 schema
