# 相机拍照/视频 → AI 运动动作分析（想法，2026-08-12 登记）

> 来源：阿呆 2026-08-12 补充想法——最近在学调整投篮姿势，「阿呆可以获取相机权限，拍照或者拍视频，拍完视频就可以得出分析结论给出意见」。视频分析较高级，拍照分析更可行。
> 状态：想法登记（未立项）。成熟后升级 `docs/rfc/`。

## 想法原话（转述）

阿呆最近在学调整**投篮姿势**，希望「阿呆」能**获取相机权限**，让用户**拍照或拍视频**（运动过程），拍完视频/照片后 **AI 得出分析结论、给出改进意见**。阿呆自评：视频分析（动作拆解）比较高级，但**拍照分析**目前看是可行的。

## 触发场景

- 学投篮 / 学运球 / 练挥杆等**动作类技能学习**——用户自己很难客观看到自己动作哪里不对
- 拍一张（或连续几张）动作照片 → AI 看骨架/姿态 → 指出问题（如「投篮手肘外翻」「发力点偏低」）+ 改进建议
- 进阶形态：拍视频 → AI 逐帧拆解动作节奏 → 对比标准动作

## 与现有能力的衔接（代码事实）

- **L4 多模态已就绪**：`POST /api/v1/records/media` 图片 → `VisualAiClient`（GLM-4.1V-Thinking-Flash）理解 → 文本化进 Timeline/Memory/Search 闭环；`POST /records/media/{id}/ask` 图片追问（#209 后追问历史持久化到图片卡）
- **拍照 = 现有图片通道的语义升级**：不需要新数据管线，需要的是「动作分析」专用 prompt + 结果沉淀（建议记录 `image_qa`/专门 type）
- **视频 = 新能力**：目前无视频上传/理解通道；视频需抽帧（首帧/关键帧）→ 再走图片理解，或等更强的视频理解模型
- **相机权限 = 纯前端**：Flutter `image_picker`（拍照）可引；`camera` 插件（拍视频）成本更高

## 候选方向

| 方向 | 说明 | 成本 | 备注 |
|:-----|:-----|:----:|:-----|
| **A. 拍照动作分析** | 现有图片通道 + 动作分析专用 prompt（GLM 看图输出「问题点 + 改进建议」结构），沉淀为专门记录 | 低 | 最贴合「拍照可行」，复用 L4 全部基建 |
| **B. 多图对比** | 用户拍 2-3 张（不同角度/阶段）→ AI 对比分析动作一致性 | 低-中 | 现有单图通道扩展为多图上下文 |
| **C. 视频抽帧分析** | 视频上传 → 服务端抽帧（首帧/中段帧）→ 逐帧图片理解 → 动作节奏分析 | 高 | 需视频上传 + ffmpeg 抽帧，v2 方向 |
| **D. 相机权限 + 拍摄内嵌** | 前端 `image_picker`/`camera` 插件，App 内直接拍照/拍视频而非相册选 | 中 | 前端插件 + 权限处理（iOS/Android），独立于后端 |

## 归属与约束

- **复用 L4**：走 `VisualAiClient`（GLM-4.1V），不新开模型通道
- **沉淀**：分析结果与「图片追问」一致——沉淀为记录（时间线/搜索可见），可再追问（如「那出手点应该多高？」）
- **File First**：照片/视频落 `data/{userId}/records/.../media/`，受 `.gitignore` 隐私保护
- **视频成本**：视频理解/抽帧是重投入，阿呆自己也判断「有点高级」——先做拍照，视频留 v2 观察
