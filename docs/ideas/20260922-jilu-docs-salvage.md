## 一、Mx 的词源（文档独有，代码里查不到）

姊妹篇提到代号 Mx / 页脚 `Make Anythings(X)`，但代码查不到含义。文档给了答案（`README.md:402-437`，2019-06-14）：

```
道生一    一 o        一生二   m，w/n,v/u
二生三    x/v        三生万物 o
mxwo ／ mark x-anythings write o-one
mx 标记于万物 按照某种方法（标记）积累
wo 编制成万物 按照某种规则（编制）录入
```

**Mx = mark × anythings（标记万物）**，是这个项目最早的自我命名；`MX.txt` 就是那时的服务器搭建笔记（CentOS + Tomcat + MySQL）。这条补上了 postmortem 里「Mx 从哪来」的空白，也再次证明：**从 Mx 到「阿呆」是产品决断，不是工程演进**。

## 三、五年前就写下的产品立场（文档最浓的部分）

1. **单用户觉醒**：「我好像又走偏了，**我的用户只有我一个**，我似乎不应该去考虑博客的数据统计啊。我应该去关注，对于我个人来说如何更好地实现核心目标。」（`README.md:460`，2019-06-10）——AdaiOS 今天的单用户定位，五年前就有人写下并自我修正过。
2. **找回的痛点**（memory / learn 的动机原型）：从 B 站看到一个电动牙刷广告、想买却忘了品牌，「我查看了浏览历史，但是被覆盖了…**我们能记住的只有一些影响深刻的片段**…最终结果是，我跟没看差不多」（`log/2019-04-13.md`）。
3. **强迫消化机制**（从饿了么「待评价」借来）：看完一篇文章就该评价/评论/贴标签，「**如果没有以上操作，那则不会记录那些，因为你其实不会记得什么，不算读过**」；并设想「鼓励金」式的切实利益（同篇）。→ 可对照 learn 的复习流转。
4. **评论即身份**：「你的评论会作为你的主页首展示内容」；评论会被当博客处理、**甚至高于博客**（`评论.md`）。反恶意评论的机制设计：主页按最新评论或举报次数排序。
5. **标签不可删**：「你可以查看你贴过什么标签…但是不能删除，…那是食言」；标签是「你那时候的共鸣点，会作为以后的**触发器（trigger）**」（`标签/标签.md`）。
6. **反恶意评论的世界观**：「理论上没有『无价值』的博客存在，只存在一种供求关系」（`评论.md`）。
7. **知识付费立场**（`知识收费.md`）：讨厌「会员制」→ 改「订阅制」（按时间计费）；礼物分成类比、**按阅读分配、作者为大、平台小或无**；「价值对等（付出≥回报）」可以不走钱；「**不存在唯一收费制度**」，按个人/团队、获取/推广划分。
8. **付费的反面教材**：解冻卡 15 元一张，让不在乎钱的人破坏其余九人的体验——「如果不在乎，那就 100、200？适当增加其权重，**15×9，为其他人买单？**」（`log/2019-04-19.md`）。
9. **用户标识观**（`用户.md`）：底层 ID 随便是什么，上层昵称/头像/LOGO **随意可改**；讨厌身份证/手机号/卡号这类数字标识；备注只是辅助。篇末自省：「我追求的东西不是一点，而是**整个互联网世界**」。
10. **交互学习库**（`good_things.md`）：饿了么的订单评价与快捷留言、B 站「友好快捷的反馈方式」、腾讯视频多端清晰度 + 双击两端快进——「总之这似乎就是应该这么做的」。

## 四、可直接抄的工程规范（低成本高收益）

| 规范 | 内容 | 出处 |

## 七、结论：抄什么 / 印证什么 / 随它去

- **建议抄进 AdaiOS**（需用户点头）：命名介词表、VO 命名、注释分区、API 自查矩阵、实体最小属性原则、校验三层 → `ai-engineering/conventions.md` 或 `checklists/`；分页真值表 → 前端实现时备查。
- **若要认真继承，落点都已存在**（2026-09-22 现状盘点）：标签 → `kernel/record/ContentRecord.tags` + `infrastructure/storage/TagIndexService`（现有 hot/cold 冷热，**缺同义词与共现**）；话题 → `domain/learn`(`LearnCard.topic`) + `kernel/memory`(`Memory.topic`)（**无独立话题实体**）；片段 → `domain/learn/LearnCardPages`（**无原子复用、无版本/分支**）。这三项属**空白新增**，不是改造。
- **印证已实现**（姊妹篇已处理）：自动分段 → learn「一页一单元」；共现关联 → 待补「标签→标签」；「未生成」口径 → 建议进 `checklists/`。
- **可孵化成 ideas 的一条**：**强迫消化机制**（看完必须评价/贴标签，否则「不算读过」）——与 learn 的复习流转/复述直接对照，是当年唯一没被实现却最有产品味的设计。
- **不必回搬**：社交/订阅/评论/投票/付费/文件服务器/图书商城——AdaiOS 是「单用户个人 OS + 多账号架构预留」（`product-roadmap.md:107`「v1.0.0 单用户先行策略不变」），这些属**定位差异而非遗漏**；`adai-dota` 与主仓库无关，随文档库原样归档即可。
- **文档库本体**：建议**保留**（除零节的凭据脱敏）——它是「积录」除代码之外仅存的另一半，也是姊妹篇判断的证据来源。
