## 一、起点与结论速览

**起点问题**：「目前的插件有几个？结合普通用户，哪些是需要的？还能扩展什么？」——背后真正的焦虑是「**阿呆给其他用户提供的作用不大**」。

**五轮讨论的核心结论**：

| # | 结论 | 一句话 |
|:-:|:-----|:-------|
| C1 | 插件不缺数量，缺分发 | 正式插件 3 个，但普通用户默认 `plugins=[]` 且不能自助开 → **今天递给身边人，他一个插件都用不到** |
| C2 | 三个插件都建在「存量型需求」上 | trading/project 要有历史数据、learn 相对最轻——**新用户第一次见面永远是空态** |
| C3 | 判定标准：通用 → 基础能力 / 垂直 → 插件 | 记账、情绪、作息是通用的，**硬做成插件只会重蹈「拿不到手」** |
| C4 | 新用户依赖只能从「零数据」起步 | 唯一的解是「**托付 → 履约 → 信任**」：用户自己说的话就是第一份数据 |
| C5 | learn 是唯一「内容从外部来」的插件 | 新用户第一天就能有内容、有产物、有惊喜 → **它是冷启动 + 增长的双重入口，不是普通插件** |
| C6 | 知识传递的本质是「表征匹配」 | **老师不能为一个人重讲一遍，阿呆可以** |
| C7 | 最大的杠杆可能不在新插件 | 仓库里躺着一堆「零件齐了没插电」——见姊妹文档接线盘点 |

## 二、插件盘点：3 个正式插件 + 1 个「伪插件」

**事实源**：`services/adai-core/.../kernel/plugin/PluginRegistry.java`（硬编码 `Set.of(...)`）。

| 名称 | 注册状态 | 消费者 | 对普通用户的适配 |
|:-----|:--------:|:-------|:-----------------|
| `trading` | ✅ 正式插件 | 需要持仓/流水/纪律 + 数据导入 | ❌ 存量依赖最重 |
| `project` | ✅ 正式插件 | 一半通用（任务/待办 + 记录转任务），一半自用（`ProjectStatusAppService` 聚合 Git + RFC） | ⚠️ 需拆分 |
| `learn` | ✅ 正式插件（2026-09-16 才补上 admin 开关） | 一次分享动作即可 | ✅ 门槛最低 |
| `life` | ❌ **不是插件**——常驻基础服务（`LifeContextContributor` / `LifeKnowledgeSource`） | 快捷条已于 2026-09-16 整条下线 | ⚠️ 名存实亡 |

**两个被忽视的机制事实**（比「几个插件」更关键）：

1. 新用户默认插件全不开（`plugins=[]`，2026-09-16 `RFC 20260916` 拍板）；
2. 普通用户**不能自助开插件**，只能由 admin 在后台勾选（同批拍板「暂不做」）。

> **推论**：插件问题当前的主因是**分发断层**，不是内容不足。

## 三、判定标准：通用 → 基础能力 / 垂直 → 插件

讨论中确立的一条尺子：

> **通用需求 → 基础能力（人人常驻，无需勾选）；垂直专业需求 → 插件（受控开放）。**

`trading / project / learn` 都是垂直的，所以它们是插件——这个划分成立。但**记账、情绪、作息是通用的**，做成插件会重新撞上「拿不到手」的死结。

### 3.1 三个候选方向按此尺子过一遍

| 方向 | 通用度 | 单次输入 | 即时见效 | 越用越有用 | 判定 |
|:-----|:------:|:--------:|:--------:|:----------:|:-----|
| **记账** | 高 | 一句话（「午饭 35」） | ✅ 当日就有数 | ✅ 月度趋势 | **做基础能力**（唯一同时满足三条硬标准的） |
| 健康作息 | 中 | 一句话 | ⚠️ 单点无意义 | ✅ 趋势 | 暂缓，等真实需求 |
| 情绪日记 | 中 | 一句话 | ❌ 写本身无反馈 | ⚠️ | **不做插件**——`Memory.sentiment` 已有，属记忆出口 |

**记账的两条红线**（若做）：

1. **绝不做成 trading 那种重 domain**（trading 的复杂度来自真实交易语义，记账没有）；
2. **金额解析错了用户立刻弃用** → 必须「记完立刻回显 + 一键改」，不能静默吞掉。

**差异化前提**：如果只是张表格，不如不做（随手记/钱迹已做到极致）。它的活路是**长在记忆上**——月底给的不是数字，是「你这个月外卖比上月多 3 次，而那几周你都在熬夜」。

## 四、记忆出口：缺的不是能力，是「讲给用户听」的那一层

**现状核实**（2026-09-16 实测前端消费）：

| 记忆资产 | 后端状态 | 用户可见出口 |
|:---------|:--------:|:-------------|
| `patterns` / `preferences`（带 confidence） | ✅ 完整 | 档案页「阿呆对你的了解」（2026-09-16 刚做） |
| `topic`（同话题归并，Phase 2） | ✅ | ❌ **零出口**（前端 `topic` 全部属于 learn） |
| `superseded` / `evolvedTo`（演变链，Phase 2） | ✅ | ⚠️ 半个：旧条目划线可见，**`evolvedTo` 零消费** → 看得到「过时」，看不到「现在是什么」 |
| `sentiment` | ✅ | ⚠️ 弱：app 记忆列表有表情图标，无趋势；web 无 |
| `lastConfirmed`（时效衰减，Phase 4） | ✅ | ❌ **零消费** → 衰减在跑，用户不知道记忆在变淡 |
| `doneAt`（行动闭环，Phase 3） | ✅ | ✅ Feed「完成」按钮 |

**诊断**：Kernel 记忆 Phase 1–5 建得完整，但用户侧只有一个「**按天翻条目的日志浏览器**」（`getMemoryDates` → `getMemory(date)`）。缺的是**聚合层 + 时间维度**。

**三个出口建议**（零新增数据）：

1. **主题线**：用现成的 `topic` 聚合成「阿呆眼里的你」；
2. **演变链闭环**：补 `evolvedTo` → 「阿呆以前认为 X，后来改成 Y」（最有「AI 真的在思考」的冲击力）；
3. **确认动作日常化**：用 `lastConfirmed`，把「点✓」从档案页一个孤点变成 Feed 里的自然追问。

⚠️ **边界**：每条必须**可否认、可修正**，不得出现确定性措辞（`REVIEW S7` 已有「自称完美匹配度」的前车之鉴）。

## 五、新用户依赖：只能从「托付 → 履约 → 信任」起步

**问题**：新用户零数据，凭什么产生粘性？**答案不在功能，在承诺。**

### 5.1 那个「更小的点」

> 新用户第一句话：「明天下午 3 点提醒我给妈打电话。」
> → 阿呆：「记下了。明天 15:00 我找你。」
> → 第二天 15:00，手机真的响了。

**用户心里那句话是**：「我刚说了一句，它当真了。」

**为什么别人抢不走**：
- ChatGPT **不会主动找你**（没有「明天」的概念）；
- Siri / 提醒事项能定时，但**听不懂人话**（「下周三之前」解析不出来）；
- **阿呆两个都有**——能听懂人话 + 真的会来找你。

**能力盘点**：APNs ✅、`PushChannel` 渠道插件化 ✅、调度器 ✅、AI 理解 ✅、`actionable`/`doneAt` ✅。
**真正缺的只有一环**：用户显式指定的时间 → per-user 提醒，而不是硬编码 cron（详见接线盘点 §C）。

### 5.2 三个同源的小点

| 点 | 动作 | 心理机制 | 门槛 |
|:---|:-----|:---------|:-----|
| 托付 | 说一件事 → 明天它来找你 | 托付 → 履约 → 信任 | 零数据 |
| 空态改托付 | 开场改「说一件你总忘的事，我替你记着」 | onboarding 不是学功能，是**做第一次托付** | 零数据 |
| 比你早发现 | 第 3 条记录时给一句观察（不说教） | 被看见 + 意外 | 3 条记录 |

**三者同源**：都只依赖「**阿呆能在未来某个时刻，为用户自己的事主动开口**」——一处补齐，三个钩子同时成立。

### 5.3 空态现状与建议

2026-09-16 做的三个开场问句是「你能干什么？」「你有什么特别的能力？」「我该怎么用你？」——**都在问「产品有什么功能」，用户答不出来，也不需要答**。建议改为**让用户做一次托付**。

## 六、learn：为什么它值得重投入（修正一轮误判）

**修正**：讨论初期曾把 learn 归为「存量型」（要先喂素材）——**这个判断是错的**。量级完全不同：

- trading 要**几个月的持仓和流水**；project 要**在跑的项目**；
- **learn 只要用户刷到一条视频**——而刷视频本来就在发生。

> **learn 是唯一「内容从外部来」的插件 → 新用户第一天就能有内容、有产物、有惊喜。**

### 6.1 产品逻辑（用户 2026-09-16 亲述）

1. 每个人都在刷视频/图文，过度依赖社交 App——这是事实；
2. 看完想保留的，多通过**站内收藏**，某种程度上是在筛选碎片内容；
3. 阿呆的作用：**一键分享给阿呆**，每次分享，阿呆用**更好的方式、结合用户习惯的方式**展示；
4. 要求：**精美，类似 PPT，精致**；
5. 远期：阿呆学得多了 → **宏观知识库**，日常问答也会有意思、有意外感。

**提炼**：

> **不跟社交 App 抢「看什么」，接管「看完之后」。**

> **收藏，是一个永远不兑现的承诺**（「我留着以后看」→ 然后再也没有以后）。
> **阿呆让收藏真的发生过。**

**三环拆解**：

| 环节 | 动作 | 关键 |
|:-----|:-----|:-----|
| 接管 | 一键分享 | 不教育用户，**寄生在既有习惯上** |
| 重塑 | 更好的方式展示 | ⭐ **不是「总结」（工具行为），是「重新表达」（作品行为）** |
| 积累 | 宏观知识库 | 问答的「意外感」 |

### 6.2 「精美」的三个判断

1. **精美不是 CSS，是编辑**：精致来自**信息结构的再设计**（一页一观点、有节奏、有留白）。地基已有——`LearnPage` / `LearnCardPages` / `POST /learn/cards/repages`（一页一单元 + 历史卡回填）。**核心工作量在「把长文切成页」，不在配色。**
2. **精美 = 病毒载体**：丑的产物没人转发，精致的产物自己会传播 → **用户转发的卡片是阿呆唯一的自增长通道**。
3. **但精美与成本正面冲突**：越精美 = 页越多 = token 越多。**解法只有一个判断——精美必须是「一次性的」**（生成时把页序列存下来，之后是渲染，不烧钱）。已有 `LearnQuota` 月度硬闸说明矛盾已现实存在。

### 6.3 可迁移的存量：收藏夹

用户的**收藏夹**里躺着几百条——那是他过去几年的筛选，**唯一能一夜之间搬过来的存量**。B 站有接口（已有 `BilibiliFetcher`），浏览器书签也能导。

建议渐进式入口：**先只拉元数据**生成「待消化的收藏夹」，用户挑几条消化，不批量烧钱。

> 这是「零数据冷启动」和「宏观知识库」之间最短的一条路。

## 七、知识传递：表征适配（本轮最底层的一条）

**用户 2026-09-16 补充**：老师讲解通过文字/视频表达，那是**一种输出方式**；但不是每个学生都能以这种方式好好接收、消化。阿呆可以**基于对你的了解，用你喜欢的方式展示** → 你会更好地消化。甚至允许学习插件有一个 **prompt / AI 产物调优**。

### 7.1 问题的准确名字：编码-解码错配

老师是**编码者**，学生是**解码者**。老师只能挑一种编码——因为他面对 50 个人。**这不是内容质量问题，是表征（representation）匹配问题。**

> 所有学习产品都在优化**内容**（更全、更快、更清晰）；
> 没有人在优化**映射**（这段内容，对这个人，应该长什么样）。
> 而优化映射的前提是「知道这个人」——只有持有长期记忆的东西才知道。

**一句话**：

> **老师不能为一个人重讲一遍，阿呆可以。**

（老师面对 50 人只能讲一遍；阿呆只服务 1 个人，所以它可以为这一个人重新编码。这才是「个人 AI」在教育上的含义——不是更好的老师，是**为你翻译的老师**。）

### 7.2 现状核实：这一环是 0，不是「差一点」

`LearnDigestAppService.digest(userId, ...)` 收了 `userId`，但**只用于决定存哪个目录**。生成内容处：

```java
String userPrompt = buildDigestPrompt(content, platform, author, url, published, typeHint, existingTopics(userId));
ContextPackage ctx = ContextPackage.simple("learn", null, "学习消化", userPrompt, List.of(), userPrompt);
```

- `buildDigestPrompt(...)` 参数里**没有 userId、没有偏好、没有记忆**；
- `ContextPackage.simple(...)` 的记忆/知识位置**硬编码 `List.of()`**。

> **阿呆给你做卡片的时候，不知道你是谁。** 炒股老手和刚入门的人，拿到同一套 prompt 生成的同一张卡。

而 `MemoryService.findAllPreferences` 早已实现，唯一消费方是 `MemoryController`（insights 展示）——**没有一行回流到生成**。

### 7.3 关于「prompt / 产物调优」：不要给输入框

⚠️ **别做「让用户写 prompt」**。理由就是 learn B 形态的死因：**把最费力的一步留给用户**（当时是「自己搞到字幕再粘贴」）。写 prompt 是同一类错误——用户不会写，也不想写。

**正确形态：调优 = 反馈沉淀，不是参数设置。**

```
用户说一句「太啰嗦」 → 写进 preference（MemoryPreference 已有，带 confidence） → 下次生成自动带上
```

这样「调优」落进**记忆**——而记忆是唯一抄不走的东西。**用户调得越久，他的卡片越像他的。这是复利，不是设置项。**

### 7.4 反直觉：别问用户「你喜欢什么方式」

用户**不知道**自己喜欢什么表征（自我报告可靠性极低）。所以：

- ❌ 不给「风格下拉框」；
- ✅ 从**行为**推断（哪张卡复述得好、哪张跳过了）；
- ✅ **偶尔试探**一个不同表征——这恰好就是「意外感」的来源。

> **调优不是用户设置的，是系统观察出来的。**

### 7.5 与「精美」的优先级

- **表征 = 认知层的适配**（用什么方式讲）；**精美 = 形式层的适配**（排版、节奏、留白）。
- **「漂亮的无效」是最容易犯的错**：极精致、但用你不擅长的方式讲的页面，依然学不会。
- **顺序：先接表征的线，再上精美的皮。**（精美依然是必要的——它是病毒载体。）

## 八、外部风向观察（2026-09 实证）

讨论中做了一次联网核实，三条线正在同时起风：

| 风向 | 事实 | 阿呆的咬合度 |
|:-----|:-----|:-------------|
| **「记忆主权」** | MemVerge 的 MemoryBox 2026-08-29 上海公测，主题「AI 时代，我们该如何安放自己的私有数字记忆？」；理念「Memory Ownership」，主张**以个人 AI 记忆/数字资产为中心、让模型围绕数据** | 🎯 **最强**——`data/` 是用户磁盘上的 md 文件，File First 是架构红线 |
| **Gartner 2026 中国 AI 十大趋势**（2026-09-16 发布） | 四大主题含「可扩展的智能体劳动力」「人工智能超级入口」，十大趋势含**「个人智能体」「基于本体的语义层」** | 🎯 咬合（Kernel 记忆 Phase 1–5 已有实现） |
| **「AI 记住更多，是错的」** | 意图共鸣科技《AI 协作记忆系统·认知架构白皮书》提「AI 记忆链」；主张让用户拥有数据主权 | 🎯 `lastConfirmed` 时效衰减 + 演变链 + confidence——**观点刚提出，实现已有** |
| 超级个体 / OPC | 杭州打造 OPC 创业高地（2026-09-14）、36氪 OPC 报告、百度「让超级个体站上 C 位」 | 🎯 用户自身即活案例（17 个月真实数据） |
| AI 硬件 / 眼镜入口 | 高通「智能眼镜将成个人 AI 入口」 | ❌ 无硬件，硬蹭 |
| AI 超级入口（流量侧） | — | ❌ 无分发，硬蹭 |

**讨论中的定位建议**：

> 风口是「个人 AI 记忆主权」，但能占的位置**不是「平台」，是「唯一能拿出活体样本的人」**。
> —— 全中国讲 AI 记忆的人里，几乎没有谁能拿出「我自己 17 个月的真实记忆长什么样、怎么演变、怎么被否掉、怎么衰减」的活体样本。

**⚠️ 反提醒**：不要被「风口」骗着去做平台——没有分发、没有资本、没有团队，唯一护城河是「这东西真的在你身上跑了一年半」。**做样板、做实证、做被引用的人，而不是做平台**（平台会来找你）。
