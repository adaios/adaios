## 1. 一句话现状

一个**单人开发、两个月做成、已上线生产、每天被本人真实使用**的"个人 AI 操作系统"；产品闭环与工程基建都已成形，**但真实用户只有我一个人**，正卡在"从自己用到给别人用"的最后一公里。

---

## 2. 它是什么

**【事实】** AdaiOS（中文名"阿呆"）定位是 **Personal AI Operating System**，形态是**一个框架 + 若干插件**：

- **Kernel（内核，装"你是谁"）**：Identity（身份/偏好/规则）、Record（最小事件单元）、Timeline（记录的时间投影）、Context（上下文引擎，核心）、Memory（长期记忆）、Knowledge（结构化知识）。内核还包括内置能力：待办、搜索、时间线、简报。
- **Domain OS（插件，装"你能做什么"）**：目前 2 个可选插件——`trading`（交易）、`learn`（学习）。大模型只是内核里内置的分析引擎，能力按用户叠加（插件可按账号开关）。
- **最高设计原则**：`File First, Database Second, Context Always`——**长期知识以文件（Markdown/JSON）为准，没有数据库**，数据库只是"查询存在"（目前实际上就没有关系库，全部是文件仓储）。
- **第一原则「无第三视角」**：所有用户可见的展示必须是"我和阿呆"的自然对话，不允许出现系统视角标签（如"问：/答：/【备注】"）。

**【事实】三端**：桌面 Web（`adaiadai.com`）· **iPhone 原生 App**（TestFlight 内测，非 App Store 上架）· admin 管理后台（`adaiadai.com/admin/`）。App 与 Web 共用同一份 Flutter 代码。

**【事实】存储与数据主权**：数据落在服务器上按用户分目录的**文件**里（`data/{userId}/…`），个人数据不进 git。

## 3. 现在有什么（按用户视角）

**【事实】已上线可用的能力：**

| 场景 | 能力 |
|:--|:--|
| 记录/问答 | 唯一入口 `POST /records`，后台自动判定"这是提问还是记录"；图片记录走视觉模型（GLM-4.1V）；流式问答 |
| 记忆 | 跨会话长期记忆（沉淀/去重/时效淘汰/降级语义）；档案页"阿呆对你的了解"（长期观察 + 置信度 + 确认回流） |
| 交易 | 持仓/批次跟踪、当日盈亏（**已对齐券商口径**）、通达信历史成交导入（预检→确认两段式）、**截图入账**（OCR→候选→逐笔确认）、复盘、买点信号（B1/B2 规则）、案例库、交易规则参数、**账实一致性对账** |
| 学习 | B站/文章/图片喂入 → 服务端抓取 → 转写（无字幕视频先报价再确认）→ **"一页一单元"卡片流** → 复习提醒 → 反馈调教 |
| 待办 | 内核内置，两态 + 可选到期日 + 到期提醒 |
| 主动推送 | 自有 APNs 渠道，10 类推送（早/中/尾盘、止损、收盘小结、复习提醒、待办到期…）+ 点击深链直达对应卡片 + 锁屏脱敏 |
| 外部入口 | Siri / 快捷指令 / **iOS 分享面板**（B站等 App 里直接分享给"阿呆阿呆"）；令牌有 90 天有效期、轮换、按 hash 撤销、付费动作频控 |
| 多账号 | 账号体系 + 按 userId 数据分层 + 角色（admin/user）；插件按账号开关 |

**【事实】规模数字（2026-09-19）**：后端测试 **2033** · App **384** · Web **318** · admin **69**（全绿）｜后端端点 **154** / Controller **22**｜后端版本 **v3.72**，已在生产**第十次部署**（2026-09-17）。

## 5. 已确立、我不打算推翻的原则（请当作讨论约束）

**【事实】** 这些是写进项目红线（`boundaries.md`）的，违反它们等于项目变质：

- **B1 无第三视角**：所有用户可见展示都是"我和阿呆"的对话，没有系统标签。
- **B2 File First 不倒退**：长期知识以文件为准，不把知识锁进数据库。
- **B3 数据隐私不泄**：个人数据不进 git。
- **B4 不提前微服务化**：模块化单体是默认，除非满足"独立生命周期/数据边界/部署/多人维护"四条。
- **B5 不混合代码和知识**：prompt 模板归内核的上下文目录，不散在代码里。
- **B6 Domain 间不直接依赖**：跨域协作经应用层编排。
- **B7 审查只报告不直接修**（P0 数据丢失除外）。
- **B8 外向动作默认不做**：部署/推送/对外发请求必须人确认。
- **B9 仓库外目录只读**。

**【事实】其他已拍板的口径**：Feed 阅读方向"最新在底部"；红涨绿亏；买点徽章也用红；字号下限 11px；触达目标 ≥44pt；不出现自造术语（要用人话）。

## 6. 真实使用数据（最重要的部分）

**【事实】** 这是我认为外部 AI 最该先看的数据：

- **真实用户数：1**（就是我本人）。没有第二个真实用户，没有外部注册开放。
- **心跳**（每日对话卡片数）：2026-09-11 ~ 09-15 **连续 5 天 0 条**；09-16 有 6 张（其中 **4 张是产品缺陷反馈**）；09-17 有 1 张；**近 7 天共 53 条记录**。交易数据最近一次是 09-18。
- **迭代驱动力**：最近几周的改动主要来自**我自己的抱怨**（"卡片顺序乱了""截图识别不准""怎么又把我当新用户了"），而不是外部用户需求——因为**没有外部用户**。
- **健康度**：生产侧 ERROR 接近 0、服务全 active、4xx/5xx 过滤掉扫描器后无真实用户失败。

**【我的判断】** 这些数据说明两件事：① 它已经是我的真实工具（不是玩具）；② 使用有波动，且**"我发现问题→AI 修"这个循环是我用它的主要方式**，而非"它每天给我带来价值"。后者恰恰是从工具变成产品的门槛。

| 维度 | 现状 |

## 8. 诚实清单：已知短板 / 欠债 / 未修项

**【事实】** 按严重度排，以下都还没修（或已明确搁置）：

| 类别 | 具体问题 |
|:--|:--|
| **合规（最硬）** | 公安联网备案未办，**最迟 2026-09-30**；办完还要把备案号挂到网站底部 |
| **产品信任** | **行情取数失败时，用户那边只看到空值/旧值、没有任何提示**（2026-09-18 巡检发现：双源失败与用户操作时刻仅隔 17 秒）。这是"静默撒谎"类问题，同类思路在项目里被反复视为最高优先 |
| **数据口径** | 交易画像的统计口径建立在"清仓表（首买→末卖纸面区间）"上，不是真实逐笔回合——v2 待排；"完美图匹配度"名不副实（实为规则阈值+硬编码分数映射），已搁置 |
| **最后一公里（给别人用必踩）** | iOS 分享扩展的凭据需用户**手动签发一次**，全新安装/给别人用必然踩到（已有 RFC，未实施）；admin 才能开插件，用户不能自助开 |
| **平台缺口** | **Android 端零推送**（无 FCM/厂商通道），且此前只有调试签名问题已修；iOS 静默推送/角标/小组件未做（用户已主动搁置："锦上添花"） |
| **零入口** | 部分新端点（画像/心理提问等）在三端**完全没有 UI 入口**，只有 API 能触发 |
| **发布** | **v1.0.0 尚未正式发布**（Release Notes/数据冻结/门禁就绪，tag 待触发）；远端仓库落后本地，且**工作区有一批未提交改动** |
| **运维小债** | 部署脚本里"重建记忆"一步仍在用已退役的鉴权方式（不影响部署，日志报错） |

**【我的判断】** 这张表里，只有"合规"和"静默撒谎类缺陷"是**必须**修的；"最后一公里"是**要不要跨出去**的决策问题；其余都可以长期挂着。

## 9. 开放问题（我没想清楚的，请重点在这些上给建议）

1. **定位收敛**：它现在同时像三种东西——个人第二大脑 / 交易复盘工具 / 学习卡片工具。**只有 1 个真实用户的情况下，下一步该聚焦哪条线？** 【我的判断】：交易是我最在意、使用最密的场景；但学习插件是最近投入最多、完成度最高、也最适合对外展示的。二者是否该二选一？
2. **从 1 到 N 的最小路径**：给别人用，第一步应该是"3~5 个亲友小范围"还是"直接开放注册"？在此之前**必须**补齐什么（合规 / 新用户冷启动 / 数据隔离 / 支持成本 / 出错时的可解释性）？
3. **冷启动**：新用户第一眼看到什么才有价值？现在插件默认全关，新用户只能看到内核的记录/问答/记忆——**这够不够形成"AI 在为我工作"的感受**？项目内部讨论过"托付式引导"（让用户托付一件总忘的事），但未拍板。
4. **Android 要不要做**：目前 iOS 优先（本人用 iPhone），Android 零推送。做 Android 的收益/成本比是多少？还是应该先只服务 iOS？
5. **主动推送的边界**：已经上线 10 类推送。怎么建立"关心 vs 骚扰"的判据？是否该做"推送价值可测量"（用户是否点开、是否行动）？
6. **商业化与否**：如果要收费，个人 AI OS 的收费点应该是什么（订阅/数据服务/一次性）？如果**不**商业化，那投入的时间上限该怎么定？（我倾向先不商业化，但这会让"给别人用"缺少回报激励。）
7. **File First 的规模上限**：文件存储 + 无数据库，在多少数据量/多少用户时会撞墙？什么时候必须引入索引/检索/向量，而**不破坏** B2 原则？【我的判断】：个人量级（几万条记录）用文件 + 内存索引足够，但"给别人用"会立刻改变这个判断。
8. **记忆与画像的下一步**：现在记忆是"AI 提炼 + 文件沉淀"，已有失真审计与保真改造。下一步该往哪走——更多自动沉淀，还是更强调"用户确认"？
9. **工程体系本身的价值**：这个项目两个月里长出了一套相当完整的 AI 协作/审查/门禁方法（审查官、部署门禁、每日巡检、成本纪律）。**它是否值得作为独立产物（方法论/开源）对外，而产品反而靠它获得可信度？** 【我的判断】：这可能比产品本身更容易被外部理解和传播，但我不确定这是不是自我感动。

## 10. 已被否决 / 已搁置的方向（请不要再建议，除非你认为判断错了）

**【事实】**

- **不做 PWA/网页版当作手机方案**（明确否决；手机端只认 iOS 原生 App）。
- **不做微服务**（B4，除非满足四条）。
- **不做 `project` 项目管理插件**（2026-09-17 已整体退役，任务能力收归内核待办）。
- **不做"AI 改名"**；头像**只做预设、不做上传**；**不做**用户自助开插件（暂缓）。
- **不做"完美图匹配/样本库相似度"**（S7，已搁置）。
- **不做 B 站 Cookie 登录**（视频一律走转写；有字幕链放弃）。
- **不做静默推送 / 角标 / 桌面小组件**（用户明确"暂时搁置，锦上添花"）。
- **不建议直接砍 `adai://` 外部入口**（Siri/快捷指令依赖它；风险已用"确认 + 来源标记"缓解）。
- **不追求"全自动、零出错"的表述**：OCR 识别出错被视为**正常流程**，产品设计方向是"可编辑/可删除/丢行如实回执"，而不是承诺准确率。

## 11. 我最想要的三种回答（供你组织输出）

1. **一个明确的优先级排序**：未来 1~3 个月，做哪 3 件事、停哪 3 件事，并说明你怎么从上面的数据推出这个结论。
2. **一次对抗性检验**：指出这份简报里"我以为是优势、其实是自欺"的地方（例如"测试多"会不会只是自我安慰、"无第三视角"会不会其实是表达限制、"工程体系完备"会不会是逃避产品问题的舒适区）。
3. **一个最小可验证的下一步**：如果我要验证"这东西对第二个人有没有价值"，最便宜、最快、最不伤信任的实验设计是什么？
