## AI4SE 项目级知识库建设方案

> 面向多模块混合架构项目，覆盖需求→编码→测试→部署→运维全流程的 AI 赋能知识库。 基于项目基线梳理探索框架（5大基线），补充 AI4SE 场景所需的关键知识维度，形成完整的知识库目录结构与分阶段落地计划。

------

### 一、原框架分析与补充说明

截图中的 5 大基线维度（需求基线、仓库知识索引、项目级文档、测试与质量、部署与运维）构成了工程基线的核心骨架，覆盖了传统软件工程的主体知识。但在 AI4SE 场景下，AI Agent 要真正理解项目并辅助全流程工作，还需要以下**6个补充维度**：

| 补充维度                | 为什么需要                                                   | AI 如何使用                                        |
| ----------------------- | ------------------------------------------------------------ | -------------------------------------------------- |
| **业务域知识**          | AI 不理解保险术语、业务流程、监管规则，就无法准确生成代码或回答业务问题 | 作为 RAG 检索的上下文，约束 AI 输出符合业务语义    |
| **架构决策记录（ADR）** | 记录"为什么这样设计"，避免 AI 提出已被否决的方案             | 在代码生成/重构时作为约束条件注入 prompt           |
| **数据层知识**          | 表结构、ETL 流程、数据血缘是 AI 理解数据流的关键             | 辅助 SQL 生成、数据质量检查、影响分析              |
| **安全与合规**          | 保险行业强监管，AI 生成的代码必须满足安全基线                | 作为 Code Review 的检查规则、安全扫描的补充        |
| **AI/ML 工程知识**      | 模型配置、Prompt 模板、评估指标是 AI4SE 自身的元知识         | 管理 AI 能力的版本、评估 AI 输出质量               |
| **开发工作流规范**      | Git 分支策略、CI/CD 流程、Code Review 规范是团队协作的基石   | 辅助 AI 理解变更流程、自动生成 PR 描述、审查合规性 |

### 四、关键成功因素

**1. 高层支持与制度保障。** 知识库建设需要团队全员参与，建议将"文档入库"纳入 Definition of Done（DoD），代码合并前必须确认相关知识已更新。

**2. 渐进式建设，避免大爆炸。** 不要试图一次性填满所有文档。按阶段推进，每个阶段交付可用的最小版本，让团队尽早感受到 AI 辅助的价值。

**3. 自动化优先。** 能自动生成的文档（如 API 文档从 Swagger 生成、目录结构从代码扫描生成）绝不手动编写。人工精力集中在业务逻辑、架构决策等 AI 无法自动获取的知识上。

**4. 知识库即代码。** 所有知识文档纳入 Git 管理，通过 PR 流程审核变更，确保版本可追溯、变更可审计。

**5. 效果可量化。** 每个阶段设定明确的量化指标（检索准确率、AI 辅助覆盖率、团队满意度等），用数据驱动持续优化。
