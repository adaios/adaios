# 当前 AI Context 体系下一步建议

目前体系已经基本成型，暂时不要继续增加新的目录、Skill、Rule 或概念，进入**真实项目验证阶段**。

## 1. 暂时冻结整体架构

当前核心结构已经成立：

```text
AGENTS.md
   ↓
L1：Task / Current State
   ↓
L2：.ai
   决策 / 规则 / 模块知识 / 已知问题
   ↓
L3：.qoder
   RepoWiki / AI Rules / Skills / 技术事实
   ↓
AI 执行
   ↓
Review / Test / Release
   ↓
知识回流
   ↓
.ai L2
```

先不要继续扩张体系。

## 2. 重点验证，而不是继续设计

使用真实项目跑 20～30 个真实任务，重点观察：

- AI 是否正确加载上下文
- 是否存在漏读 / 误读
- 是否存在重复读取
- Task 状态是否漂移
- Skill / Rule 是否冲突
- `.ai` 与 `.qoder` 是否产生重复知识
- 知识回流是否真正有效
- AI 是否能稳定遵守硬卡点

目标是验证体系，而不是证明体系“看起来完整”。

## 3. 下一阶段重点：Context Router

当前体系已经解决：

> **“有哪些上下文，以及上下文如何分层。”**

下一步要解决：

> **“面对一个具体任务，AI 到底应该加载哪些上下文。”**

例如：

```text
用户：
修改交易订单接口

        ↓

Context Router

        ↓

识别：
任务类型
模块
涉及技术
相关风险
相关决策

        ↓

自动加载：

L1 Task
↓
相关 Module
↓
相关 Decision
↓
相关 Known Issues
↓
RepoWiki 对应代码事实
↓
相关 Skill

        ↓

开始执行
```

避免：

```text
把整个 .ai / .qoder 全部塞给 AI
```

## 4. 最后解决 `.ai` / `.qoder` 边界问题

继续坚持：

> `.ai` = 决策、约束、协作认知  
> `.qoder` = 代码事实、技术事实、执行能力

尤其防止同一个知识点同时存在于两个地方。

最终目标：

> **一个知识只有一个权威来源，其他地方只引用。**

## 5. 长期方向暂时保持不变

Front Matter + `_directory.md` + `dependencies / impacts` 的方向继续保留。

但：

> **先元数据规范化 → 再依赖关系 → 最后才考虑目录扁平化 / 知识图谱。**

不要为了“知识图谱”而提前重构目录。

---

### 当前阶段一句话

> **架构先冻结，真实任务验证；下一步重点不是增加知识，而是建立 Context Router，让 AI 能够根据任务自动找到正确的知识。**
